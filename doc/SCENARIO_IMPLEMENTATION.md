## 操作と保存互換性

町で追加依頼を受注し、追跡欄の指定地点を調べて開始します。「ここで中断し、同じ場面から再開する」で探索へ戻れます。物資の補給や酒場での隊の変更を挟めます。完了後の再訪では同じ結果を読み、報酬・経験値は再取得しません。

1.0.0、1.1.0、1.2.0、1.3.0のセーブを1.3.1へ移行します。1.3.0の既存職業・成長履歴・装備・負傷・乱数・待機位置を保持し、追加100本をavailableとして加えます。1.0〜1.2の旧成長から職業への移行も継続します。

旧版の命令IDと配列位置は保持しています。既に本文・選択・戦闘途中で保存した場合、その時の旧経路を完了してから、次の訪問で改稿後の経路へ接続します。旧経路内で既に払った費用は返しません。

移行時に過去の勝敗・討伐数を推測しません。historyComplete=falseで開始し、進行中の旧戦闘を1件として取り込み、既に倒れていた敵を新しい撃破に加えません。以後の撃破・勝敗を集計します。未受注からの受注で基準点を保存し、追跡変更や再受注ではリセットしません。

q100「百の帰還」は、元のq001〜q099の完了を個別に確認します。追加篇だけを100本完了しても、本編の終幕は解放しません。q200は追加篇の独立した結末で、本編のendingを上書きしません。

## 再生成

```sh
npm run build:scenarios
node tools/build-fixtures.mjs
node tools/validate.mjs
node tools/check-static.mjs
node --test tests/*.test.mjs
```

実行時の依存追加はありません。build:scenariosは基礎100本・魔物・演出・職業の生成後に、改稿と新規100本を適用し、Schemaを生成します。build-scenarios単独の反復でも開始地点は重複しません。本文修正は原稿を直してから生成し、生成済みJSONもコミットします。
