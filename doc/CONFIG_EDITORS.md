# 設定JSONの編集画面

更新日: 2026-09-23。作品版1.18.0の設定編集用ツールです。ゲームデータとセーブ形式は変更していません。

[編集HTMLのPages URL一覧](CONFIG_EDITOR_URLS.md)：全225件の直接リンクと設定一覧画面。

## 入口と使い方

[設定一覧](../config/index.html)から名前・ID・ファイル名で絞り込み、対象のHTMLを開きます。PagesではゲームURLの末尾を `/config/index.html` に置き換えます。ローカルでは `npm run serve` でHTTP配信して開きます。file://での直接起動は対象外です。

1. 各HTMLは同じ場所の対応JSONを読み込みます。通信失敗時には再読込でき、手元のJSONファイルを読み込むこともできます。
2. 文字・数値・真偽値はそのまま変更します。オブジェクトや配列は「詳細を開く」で入り、上部の経路から戻ります。60件を超える一覧はページを切り替えます。
3. 「項目を追加」「削除」「上へ」「下へ」で構造を編集できます。「型・JSON」では選んだ値・部分構造の型も変更できます。「全JSONを直接編集」は文書全体を扱います。
4. 「一つ戻す」で直前の変更を戻せます。最大30回分を保持します。「元のJSONを再読込」で編集を破棄します。未出力の下書きをサーバーへ保存する機能はありません。ページを閉じる前に出力を保管してください。
5. 「検証して全JSONを出力」を押し、問題がなければ「全JSONをコピー」を選びます。クリップボードを利用できない環境では全JSONを選択し、Ctrl+C／⌘Cでコピーします。
6. 自分でgithub.dev等を開き、画面に表示された `config/...json` へ全文を貼り付けて保存・commit・push・PR作成を行います。HTMLからGitHubへ書き込む処理はありません。

再編集すると以前の出力は直ちに無効になります。検証中の変更も古い結果を採用しません。入力途中の不正な数値や、未反映の直接JSON編集がある場合は出力できません。

## 編集元と対象範囲

現在の225原稿JSONを `authoring/` から `config/` へ移し、それぞれに対応HTMLを置きました。同じJSONを二か所で管理しません。共通フォームを使いますが、入口・読み込むJSON・貼り付け先はファイルごとに固定されています。

1. `config/quests/q001.events.json`〜`q200.events.json`：200クエストの配置・条件・現地調査スクリプト。対応HTMLは `q001.events.html` などです。
2. `config/dungeons/*.json`：13迷宮の仕掛け・接続・条件付きイベント。対応する同名HTMLがあります。
3. 直下の12件：町、職業、仲間と魔物、演出、素材、セルレイヤー、2Dマップ、q011〜q020原稿、迷宮追加内容、篝火追加内容、地形補助、退避中の3D原稿です。

素材の制作記録・ハッシュ・プロンプト、テスト用の固定JSON、互換保存、保存原文、参照文献索引、package.json、生成済みのdata・Schema・文書集計はゲーム設定の編集元に含めません。q001〜q010などJavaScriptで管理する本筋や、tools内で組み立てる基本戦闘数値を生成済みdataから編集する画面も作っていません。

`connected-maps.json` は基本マップを上書きし、最終的な通行値は `cell-layers.json` から生成します。旧maps欄や3D原稿を変更しても通常の2D形状を変えない場合があります。該当画面にも編集元を案内しています。音符・画像などの素材定義の変更は、対応する素材生成も必要です。

## 検証と出力契約

出力はJSON全体です。表示中の項目だけを再構築せず、選んだ位置だけを変更します。未編集の深い項目、追加のメタデータ、非表示ページの値も保持します。元のオブジェクトの項目順と配列順を保持し、追加項目は末尾、配列挿入・並べ替えは明示操作だけで行います。JavaScriptのJSON順序規則に従い、数値の項目名は昇順になります。インデントは半角2空白、LF改行、末尾改行一つに正規化します。

読込時に構文、重複した項目名、予約名、精度を保持できない数値、深すぎる入れ子を拒否します。5MBを上限とし、黙って項目を上書きしたり大きな整数を丸めたりしません。JSONは値として扱い、HTMLやJavaScriptとして実行しません。

ブラウザでは既存Schemaの規則を再利用し、原稿専用の構造・型・数値範囲を補います。迷宮内の所属マップ、町の親子循環、職業の初期割当、演出とSEの参照、セルの凡例・寸法、同じ一覧のID、配置物のエッジ条件など、ファイル内の整合を検査します。複数の操作盤が同じ弁を扱う場合は、別の配置点として扱います。

検証器はこのリポジトリが使用するSchemaキーワードを対象とします。未知の規則・検証定義の読込失敗・解析上限では、検証済み出力を作りません。汎用JSON Schema実装を名乗るものではありません。

別ファイルのID・画像・シナリオ本筋・生成後の到達可能性まではブラウザ検証の対象外です。反映後は通常の生成とプロジェクト検証を実行します。ブラウザには検証範囲を常時表示します。

## 生成と保守

`npm run build:config` が各HTMLと `config/shared/catalog.js` を生成します。共通フォームは `config/shared/editor.js`、編集状態とJSON入出力は `model.js`、Schema規則は `schema.js`、原稿の検証は `validation.js` です。生成HTMLを個別に手直しせず、生成器と共通コードを編集してください。

`npm run build:scenarios` の終端でも一覧・HTMLを生成します。通常の `build:catalog`、`build:jobs`、`build:dungeons` からも更新されます。新しい種類の原稿JSONを追加するときは生成器の編集形式・案内とvalidationの定義を登録します。迷宮・クエストの追加は対応するフォルダのJSONから入口を生成します。

`npm run check:config` は全原稿を検証し、JSONとHTMLの一対一対応・生成物の一致・出力の安定を確認します。通常の `npm run check` とGitHub CIにも追加しています。最終的な反映は `npm run build:scenarios`、`npm run check`、`npm run check:docs` で確認してください。

実ブラウザの再現用は `node tools/browser-config-smoke.mjs` です。PlaywrightとChromiumを利用できる環境で実行し、必要に応じて `ADV_BROWSER_EXECUTABLE` に実行ファイルを指定します。GitHub Pagesと同じ `/adv/` の下で一覧・詳細編集・検証・コピー・出力無効化と1280／390／320px幅を確認します。
