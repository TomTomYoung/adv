# ゲーム原稿の編集画面

更新日: 2026-09-24。作品版1.19.0用。編集ツールの更新で、ゲーム原稿の値とセーブ形式は変更しません。

入口は[設定一覧](../config/index.html)。公開先は[Pages URL一覧](CONFIG_EDITOR_URLS.md)に全225件を掲載しています。[編集対象JSONの一覧](CONFIG_EDITOR_SOURCES.md)で、操作ごとの出力先・生成済みデータとの区別を確認できます。

## 迷宮から始めるマップ編集

通常の入口は[マップ編集](../config/map.html)です。迷宮 → マップを選び、地形、入口・配置物、イベント、仕掛け、マップ間の接続を同じ画面で切り替えます。各操作の出力先と、変更したJSONの一覧を表示します。壁灯などの配置を選ぶと実際の正本を開き、マップの選択を保ったまま条件・配置・処理を変更できます。

1. 地形はセル種を選んで塗るか、セルを選んで「この地点だけの設定を作る」を使います。共有セル種へ進むときは、使用マップ数・セル数と確認を表示します。共有設定より地点ごとの上書きが優先されます。
2. 入口と配置物は、現在のマップの有効な原稿を編集します。篝火の既存マップは `config/kagaribi-content.json`、接続済みマップは `config/connected-maps.json` です。JavaScript原稿由来の基本情報は参照専用です。
3. イベントの追加では所属クエストを選びます。選択した `config/quests/qXXX.events.json` に配置イベントと専用処理を同時作成します。仕掛けと接続は `config/dungeons/<迷宮ID>.json` です。
4. 接続は二つの配置図でA・Bを選び、階段・扉・水密扉とそれぞれの到着方向を指定します。扉は壁に接する面に置きます。接続先マップは同じ画面で新規作成でき、名前・寸法からマップ、セル配置、所属一覧を一括追加します。新規マップは `config/connected-maps.json` に追加します。
5. 接続の編集は「接続を下書きに反映」で確定します。反映前の接続がある間はJSON出力を止めます。接続の取消は、先に作成したマップまで消しません。不要なマップ作成は接続編集を終了して「戻す」で取り消せます。
6. 出力時にはゲームと同じ接続検証を使い、接続口の足場、扉面、重複、入口からの接続を確認します。共有地形を変更した場合は他迷宮の接続も確認します。ゲーム内での全経路の到達可能性や進行条件の通し実行を代替するものではありません。

設定一覧の先頭は「マップ編集」「セル種の管理」「道具・商品の編集」です。旧開口と3D原稿は互換原稿の折りたたみへ移しています。225件の原稿別編集ページは引き続き利用でき、検索で直接開けます。

## 編集UIの仕様

ゲーム上の対象を選び、その意味に沿って編集します。JSONの階層をたどる操作を通常の入口にはしません。各画面は「対象の一覧」「設定」「配置図またはプレビュー」で構成します。編集対象の `config/...json` を上部と詳細欄に表示し、別原稿も変更した場合は「今回の出力対象」に追加します。

1. クエストは配置イベントと会話・処理を選びます。イベントは基本、配置、条件、実行内容に分けます。道具・仲間・技能・マップ・画像・処理の参照は、名前で絞り込む選択欄です。内部IDは参照維持のため通常操作では変更しません。
2. 条件は「すべて満たす」「道具を持っている」「状態の値が以上」などを組み合わせます。日本語の条件要約を併記し、入れ子・数値計算・状態参照を扱います。
3. 処理は台詞、選択肢、道具消費、報酬、移動、戦闘などのブロックを順に並べます。追加・複製・削除・上下移動、条件分岐の内部編集ができます。道具を消費する処理は道具名と個数を指定します。ゲーム側の「消費があれば明示選択する」動作は維持します。
4. マップはセルの配置図で編集します。セル種を塗る、地点ごとの通行・外観・照度・通水・イベントを上書きする、配置物・火台・イベント・接続口を置く操作を用意します。面を持つ対象はセル四辺で北・東・南・西を指定します。セル進入イベントをエッジへ置く操作は拒否し、調査・操作用であることを確認します。
5. 迷宮の接続は接続口A/Bをそれぞれのマップ上で選びます。仕掛けは篝火、水位、破壊壁、植物、転移、呪い、技能封印、空気、取引、動力、水密区画など、登録済み16種類の設定を扱います。新規マップは名前・寸法・所属迷宮から作り、マップ・セル・所属一覧の3原稿を一操作で変更します。
6. 仲間・魔物・職業・技能・商品には比較一覧を用意します。技能は対象、消費、必要武器、効果を分け、ダメージ・回復・状態異常・強化などを選びます。未知の原稿項目を削除して作り直す処理は行いません。
7. 町は背景・親子関係・接続先・施設・人物を編集し、つながりから別の場所へ移れます。q011〜q020のシナリオ原稿は本文・場面・選択肢・結末を編集し、分岐先を確認できます。
8. 画像は候補の名前とプレビュー、迷宮素材は壁・装置の候補画像から選びます。演出は下書きの効果を再生し、SEは音符と現在の音声素材を試聴できます。音符の試聴は音程・長さ・強さを確かめる簡易音で、実素材の音色再生成を代替しません。

配置図の照度表示は初期灯火とセル遮光・局所照度の確認です。ゲーム進行による出現条件、開閉、水位の変化を実行するシミュレーターではありません。旧3D原稿の層編集は互換原稿向けで、通常2D配信へは含まれません。

## 下書きと反映の手順

1. HTTPで開きます。ローカルでは `npm run serve`、Pagesでは[URL一覧](CONFIG_EDITOR_URLS.md)を使います。
2. マップ編集では迷宮・マップを選び、配置図から編集します。原稿別ページでは一覧から対象を選び、タブや配置図で編集します。上部の「編集するJSON」を切り替えても、同じ画面内の下書きは保持します。別ページを開く・再読み込みする操作では引き継ぎません。
3. 「戻す」「やり直す」でファイルをまたぐ操作を戻せます。最大60操作を保持します。「変更をすべて破棄」も戻せる操作です。原稿へのサーバー保存・自動保存はありません。
4. 「変更を確認・JSONを出力」で、名前付きの変更箇所・変更前後・出力ファイルを確認します。変更したJSONだけを、ファイルごとに全文出力します。
5. 「このJSON全文をコピー」でコピーし、表示された正確な `config/...json` に貼り付けます。自動コピーを利用できない場合は全文を選択し、Ctrl+C／⌘Cでコピーします。
6. 自分でgithub.dev等に貼り付け、commit・push・PR作成を行います。編集HTMLにGitHub認証やAPI書込みはありません。関連する複数JSONはすべて反映してください。
7. 原稿の反映後、`npm run build:scenarios`、`npm run check`、`npm run check:docs` を実行します。音符・演出素材の変更は `node tools/assets/generate-effects.mjs` と `node tools/build-presentation.mjs`、迷宮素材指定は `node tools/build-dungeon-art.mjs` も必要です。素材生成に必要な依存環境は各生成器を確認し、最後に通常の全体生成と検証を実行してください。

「高度な編集：JSONの確認・取り込み」は補助機能です。JSON全文の貼り付けや手元のJSONファイルを読み込み、形式を確認して下書きへ反映できます。取り込み途中・不正な数値の入力途中では通常操作と出力を止めます。再編集すると以前の出力を直ちに無効にし、検証中に編集した場合も古い出力は表示しません。

## 保持と検証

選択した位置だけを変更し、表示していない項目・追加メタデータ・配列順を保持します。配列の並べ替えは明示操作だけです。出力時は2空白インデント、LF、末尾改行一つに正規化します。オブジェクト順はJavaScriptのJSON規則に従い、数値の項目名は昇順です。

読込では構文、重複キー、予約された項目名、数値精度、5MB上限、深すぎる入れ子を確認します。内容をHTMLやJavaScriptとして実行しません。

出力前には既存Schemaと原稿用の規則で、型・必須項目・数値範囲・ID重複・エッジ条件・配置範囲・セル寸法・所属マップ・町の親子循環・分岐先・画像や技能などの原稿間参照を確認します。読み込んでいない原稿から、今回削除した項目への参照も調べます。条件の所持数より消費数が多い場合は注意を出します。

元原稿の探索特技にある4件の未解決演出参照（`break_rock` / `read_path` の `unlock`、`field_prayer` の `heal`、`climb_route` の `guard`）は、未変更であれば差分確認に注意を表示します。これらは `presentation.bindings.events` のキーで、実ゲームでも未定義の演出は再生されません。今回のツール改修で元データを変更しません。新たな参照切れや、定義削除によって生じた参照切れは出力を止めます。

未知のSchema規則、定義読込失敗、解析上限では検証済み出力を作りません。未知の項目は保持しますが、Schemaが禁止する項目を追加した場合は出力できません。全分岐の実行、マップ到達可能性、ゲーム内の総合バランス、素材生成の完了は、反映後の生成・プロジェクト検証と実プレイで確認してください。

## 実装と保守

`npm run build:config` が225個のHTML、`config/shared/catalog.js`、参照索引 `config/shared/reference-catalog.js` を生成します。参照索引は名前・参照先・配置・正本位置の読み取り用データです。編集原稿の正本ではありません。原稿や生成済みのゲームデータを変えた後は再生成してください。

画面は `config/shared/studio.js`、分野別設定は `studio/profiles.js`、項目・条件・処理は `studio/forms.js`、配置図は `studio/map-view.js`、原稿管理は `studio/workspace.js`、参照検証は `studio/checks.js`、素材確認は `studio/preview.js` です。旧 `editor.js` は互換テスト用として残し、各HTMLの入口は新画面へ変更しています。

照度の純粋計算を `src/core/light-geometry.js` に分離し、ゲームと配置図から共用します。計算内容は従来のままです。ゲームの状態を動かすモジュールを編集画面から読み込まないようにしています。

`npm run check:config` は全225原稿・HTML・生成索引の一致を確認します。`tests/config-studio.test.mjs` は原稿間の編集・参照・保持・出力、分野別UIを検証します。`node tools/browser-config-smoke.mjs` はPlaywrightとChromiumで `/adv/` 配下の検索、イベントのエッジ配置、セルの塗り替え、技能消費、3ファイル出力、コピー、Undo、入力エラー、1440／900／390／320px幅を確認します。実行ファイルは必要に応じて `ADV_BROWSER_EXECUTABLE` で指定します。
