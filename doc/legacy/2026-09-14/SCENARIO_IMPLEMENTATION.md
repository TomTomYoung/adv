# シナリオ進行の再実装

更新日: 2026-09-10。バージョン: 1.3.2。

2026-09-12追記: 本文はPR #3の1.3.2を対象とします。masterの1.3.1との比較と残る確認事項は [CURRENT_STATUS.md](CURRENT_STATUS.md)、文書統合後の検証は [PROGRESS.md](PROGRESS.md) を参照してください。

既存100本に残っていた「手掛かり二つ→同じ三択」を通常進行から外しました。q001〜q100を個別に定義した289場面へ置き換え、追加篇でも単一の判断メニューに寄っていた10本を組み直しました。全200本・559場面・629結末です。各行為と接続先は [シナリオ一覧](QUEST_CATALOG.md)、設計の理由と具体例は [モデルと進行](SCENARIO_DESIGN.md) を参照してください。

## 変更

- `authoring/structures-1.mjs`〜`5.mjs`：元の100本の進行。作業、救助、交渉、待機、実験、順序による損失を各依頼に記述。
- `authoring/structures-additional.mjs`：q108・q125・q126・q150・q168・q169・q175・q196・q198・q200の改稿。
- `tools/build-quest-structures.mjs`：作者が書いた接続をJSONへ変換。共通の二地点回収、番号に応じた戦闘・縄消費は挿入しない。
- `src/core/validation.js`：開示対象を最低二つ要求する制約を撤去。
- `src/core/save.js`：1.3.1の戦績を保持し、旧版で進行中の依頼は旧経路を完了できるよう移行。
- `src/application/projection.js`：使用中の経路に合わせて案内地点と手掛かり数を投影。
- `data/quests`・`data/maps`・`data/schemas`・`data/view-fixtures.json`：生成物と画面用例を更新。

元の結末IDは互換用に残します。新しい経路の行為名は本文に合わせ、途中救助、消えた記録、置いてきた荷物、虚偽報告の訂正など11結末を加えました。戦闘がある旧依頼は29本になりました。修理や返却を選ぶだけで機械的に戦闘が起きる規則はありません。

## 遊び方

町で受注し、追跡欄の地点を調べます。選択した行為で次の場面へ進みます。必要な作業を済ませていなければその選択は成立せず、資材や金が不足しても状態は変わりません。戦闘付きの作業は勝利した時にだけ費用を支払います。

「ここで中断し、同じ場面から再開する」で探索へ戻れます。町での補給や仲間の変更を挟んでも続きから再開します。完了後の再訪では結果を読み、金・経験値は再取得しません。

q100は元の99本の完了を確認します。今回の終幕はq001・q098・q099の実際の結果も参照します。過去に居住区を全て描いた場合、公開用の写しから住居を除く作業を挟みます。昔の選択を別の結果へ書き換えません。q200の結末は本編のendingを上書きしません。

## 保存互換性

保存の形式はsaveVersion 1、内容版は1.3.2です。1.0.0〜1.3.1を移行します。

1.3.1からは、戦績・受注時基準点・戦闘中に計上した撃破・隊員・職業・成長・装備・資材・乱数・VMの継続位置を保持します。旧版から進行中の依頼だけを `flags.legacyQuestRoutes` に記し、完了までその旧経路へ案内します。移行後に新しく受注した依頼は新しい進行です。完了済みの結果や報酬を取り消すことはありません。

1.0〜1.3.0は従来の職業移行・追加依頼の補完を継続します。その版に存在しなかった過去の戦績は推測せず、移行以後を記録します。

新命令には `<id>.flow.*` の別IDを使います。1.3.1の1,376スクリプトの命令配列は変更せず、ハッシュの比較でも確認します。途中の会話・選択肢・戦闘を配列の添字で保存する仕様を維持するためです。

## 再生成

```sh
npm run build:scenarios
node tools/build-fixtures.mjs
npm run check
```

基礎データ、互換用の1.3.1進行、新しい個別進行、Schemaの順に生成します。通常は上のコマンド全体を使ってください。`build-content` や `build-scenarios` 単体では内容版が途中段階へ戻ります。生成済みJSONもコミットします。実行時の追加依存はありません。

## 検証の範囲

`tests/scenarios.test.mjs` は全200本を対象に、実際のマップを歩いて入口へ入り、VMの選択を探索して629結末への到達を調べます。各場面の保存復元と中断再開、戦闘の勝利・逃走可能時の逃走・敗北、再訪時の報酬の一回性を検査します。経路検査は高レベルと十分な物資を使い、戦闘バランスとは分けています。

別の通し検査は、初期能力と獲得した資金・物資で、元の100本の新しい進行を全て完了します。旧経路の300結末到達も互換性検査として残します。旧二地点を回る経路を、新進行の検証の代用にはしません。

個別検査では、救助後の再捜索、救助人数、止水の順、梯子の重り、水門の操作順、置いてきた荷、返事にない交流の捏造防止、嘘の後の応答、過去の結果と公開範囲、費用の原子性を確認します。旧戦績の集計・不正セーブ拒否・手紙と返信の区別・避難と討伐の区別も継続して検証します。

1.3.0と1.3.1それぞれの本文・選択・戦闘中の実セーブをfixtureとして使います。1.3.1のfixtureはマージ済みの旧実装で生成し、狼の撃破記録とq200の片方だけ訪問した進行も含めました。新しい定義を旧版と称したデータではありません。

作品参照・構文・素材・全自動テストを `npm run check` で確認します。実行結果は [PROGRESS](PROGRESS.md) に記載します。全件を人が通して遊ぶ文芸的評価と、ブラウザでの視覚・操作確認は含みません。この環境ではローカルURLへのブラウザ接続が制限されています。
