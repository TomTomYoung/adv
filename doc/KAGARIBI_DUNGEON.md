# 篝火の迷宮：仕様と実装

更新日: 2026-09-24。現行作品1.19.0の実装仕様です。導入版は1.5.0。

出典：[Notion「篝火の迷宮」](https://app.notion.com/p/3dac3c1966b38057b740df426b57da09)。2026-09-16に本文を読み、ユーザーの実装指示に従いました。Notionページの編集は行っていません。

## 2026-09-24：点灯・消灯・イベント戦闘の確定仕様

作品版1.19.0で実装済みです。通常の点灯はくらがり除けを兼ねます。普通の火と入口で受け取るくらがり除けの火は、通常の魔物の出現を妨げません。通常遭遇を完全に抑える効果は特別な火だけが持ち、現在は深火が該当します。

携帯火が消えていても、有効な壁灯・篝火の範囲内なら通常点灯と同じ扱いです。保護する火が一つも届かない場合は、消灯時の遭遇候補に切り替えます。局所照度の数値だけでこの火の守りを代用しません。

### 消灯中の二段階の抽選

まず戦闘が発生するかを抽選し、当選した場合だけ敵の種類を抽選します。成功歩数7歩ごとに基本22％で戦闘が発生します。これは既存の通常遭遇周期と迷宮の通常遭遇率に合わせた初期調整値です。既存の隊の遭遇率補正を乗算します。安全オブジェクトのあるセルでは歩行遭遇しません。消火・点火・向き変更・壁への衝突・会話・メニュー開閉・セーブ／ロードだけでは抽選しません。判定周期は全体の成功歩数を使い、点火や消火ではリセットしません。

消灯中の敵候補は現在kuragari_huntだけ、重み1です。したがって、戦闘発生率は100％ではなく、発生した戦闘がくらがりである確率が100％です。通常の魔物との混合抽選や、くらがりを外した後の追加抽選は行いません。

正本config/dungeons/kagaribi.jsonのsystems.fires.threat.encounterRateが基本遭遇確率、encounterPoolが敵候補と重みです。将来はくらがりの種類ごとの遭遇定義を追加し、この配列へ重み付きで登録します。候補比率は各重みを重み合計で割った値です。撃退技能の対象照合と報酬0の検査もこの配列を参照します。候補の追加だけで判定処理を書き換える必要はありません。

通常点灯中はマップの通常遭遇候補・確率を使います。消灯中は上記の専用候補・確率を使い、くらがりへ通常魔物用の能力倍率を適用しません。篝火の迷宮では旧灯油ゲージの残量による暗闇加算を使いません。移動による燃料消費を先に処理するため、その歩行で火が消えれば消灯後の状態で抽選します。

### 老人同行中の消灯はイベント戦闘

q001の帰路の指定地点では、携行火と最後の壁灯を消し、q001-F-kuragariのbattle.startで戦闘を開始します。歩行遭遇の確率・周期・敵候補とは独立したイベント戦闘です。乱数が外れる値でも開始し、同じ歩行で追加のランダム戦闘は行いません。新人の発言・火による救助・強制終了・現地会話への継続を保持します。

q001固有の演出として、入口で携行火を残り25歩、老人の場面で8歩、帰路の消灯地点で0へ設定します。途中で燃料を補充していても、このイベントによる指定が優先します。救助後は25歩へ戻します。一般の消灯にこの強制戦闘を適用してはいけません。

以前のunprotected_kuragari条件イベントは削除しました。消灯や移動通知から無条件に即戦闘を起動しません。通常遭遇はGameEngine.finishMoveの共通抽選で、物語戦闘はq001原稿で管理します。

1. 世界設定と遊べる範囲

篝火の迷宮は灯帰りができるきっかけとなった迷宮です。各所の篝火には魔力を持つものがあり、極めて危険な「くらがり」は通路の松明の火を嫌います。火を絶やさず篝火を整備するため、灯番（ともしびばん）の制度が始まりました。

最奥の種火を持ち帰ると死者を生き返らせられる、という伝承があります。原文は伝承としているため、蘇生の効能を確定したり、無条件の蘇生機能を追加したりはしていません。深火の祭壇では種火を採って持ち帰れます。効能の真偽は碑文で未確定と明示します。

既存の灯守の地下水道など10探索先を維持し、「迷宮へ」に篝火の迷宮を追加しました。導入時は11ダンジョン・23マップ、現在は13ダンジョン・33マップ、10地域・200クエストです。地域1に二つの迷宮が所属するため、地域とダンジョンの分離を実際に使っています。

第一層は灯番の巡回路、第二層は消えた灯の回廊、第三層は深火の祭壇です。第一層の入口側は踏査済みの地図を初期公開し、奥は探索に応じて明らかになります。巡回記録と碑文で町の起源、灯番、くらがり、種火の伝承を読めます。

2. 火と台座

火台は本来のeffect、影響radius、燃料capacity、初期点火状態を定義します。普通に点火すると台座本来の効果が発現します。点火・燃料補充には通常の松明を1個使います。

灯っている火から「種火を採る」で火入れに一つ保持します。火元の現在の有効な効果を採取します。火元は消えません。別の種火を採ると保持中の種火を持ち替えます。

消灯中の台座に「種火を移す」と採取した効果が台座本来の効果に優先し、種火を一つ消費します。移植効果は消火または燃料切れまで持続します。燃料補充は移植効果を保持します。消火では移植効果を解除し、次に普通の火で点火すると本来の効果へ戻ります。

範囲は同一マップの通路を辿った距離です。壁、閉じた扉、別階層へは届きません。判定は可視・既知状態とは独立し、まだ地図にない火でも実際に届いていれば働きます。

守護の可否は、届いている火の一つでもrepelsがtrueなら有効です。通常遭遇率と敵強さは、届く火のうちpriority最大の効果を採用します。同順位は火元IDの昇順で決定します。手持ちの火も同じ候補に入ります。倍率を重複加算して際限なく強化しません。

3. 初期の火の効果

普通の火はくらがりを防ぎ、通常遭遇・強さは標準です。携帯松明への通常点火でこの効果を得ます。

くらがり除けの火もくらがりを防ぎ、通常遭遇率は標準の1倍です。入口の篝火と通常の守護用台座の効果です。

鎮めの火はくらがりを防ぎ、通常遭遇率を0.5倍、敵のHP・攻撃・防御・知力を0.6倍にします。

呼び寄せの火はくらがりを防ぎ、通常遭遇率を2倍、敵のHP・攻撃・防御・知力を1.6倍にします。

深火の種火はくらがりを防ぎ、通常遭遇を抑えます。蘇生能力は未確認です。

鎮め・呼び寄せ・深火は通常の守護火より優先度が高く、台座による通常遭遇の変化を体験できます。深火が最優先なので、その有効範囲では呼び寄せと重なっても通常遭遇を抑えます。くらがりの強さは通常遭遇用の倍率で弱体化させません。経験値・金の倍率も変えません。

4. 携帯松明と持ち帰る種火

篝火の迷宮へ新たに入るたび、入口の灯番が入口の火を整備し、くらがり除けの携帯松明を一つ渡します。消灯して帰った入口も、次回の出発時に整備します。これは「入るときに必ず持つ」という原文を満たすための運用です。

携帯松明は90成功歩で消耗します。25歩と8歩で二段階の警告を一度ずつ表示します。回転、壁への衝突、会話、メニュー、セーブ、ロードでは減りません。火の管理と戦闘にも追加の歩数消費はありません。通常の灯油ゲージはこの迷宮では携帯松明の残り歩数表示に切り替えます。

携帯松明には種火と灯番のスキルによる効果を持たせられます。移植には消灯が必要です。灯番の点火スキルは手持ちの火を直接更新でき、点火と燃料を満たします。

火部品の壁面松明は同じ迷宮での成功歩数により燃料が減ります。q001の壁灯3本は別途イベントobjectとして段階状態を管理し、数値燃料を持ちません。無限燃料の篝火はcapacityがnullです。燃料切れの台座には魔力効果もありません。

階層移動で携帯松明の残り時間は戻りません。通常帰還・緊急帰還・敗北時は携帯松明を返却し、次の入場時に一つ渡します。個数は累積しません。採取した種火は火入れに保持したまま帰れ、次の篝火の迷宮探索へ持ち込めます。持っているだけでは保護されず、点火・移植が必要です。

5. くらがりと灯番

携帯火・壁灯・篝火の守護範囲外では、上記の消灯時の歩行抽選を行います。遭遇確率と敵種の比率を分離し、一般の消灯だけで確定戦闘を開始しません。q001の帰路は独立したイベント戦闘です。[イベント仕様](scenarios/EVENT_SYSTEM.md)。

くらがりはHP1800、攻撃130、防御70、速さ15、知力90を初期値とします。通常の魔物より極めて強力です。撃退による金・経験値・討伐数の獲得はありません。現行の姿絵は既存wraith素材を使用しています。専用原画の制作は今回の変更に含めていません。

既存職業ID lantern_keeperを維持し、表示名を灯番へ統一しました。現在版の職業・成長履歴を保存できます。職業総数は30のままです。

Lv1で「くらがり除けの火」を習得し、MP3で携帯松明・近くの消灯台座を点火できます。くらがりとの戦闘では同名の技で敵を逃走させ、携帯松明にも守護火を灯します。敵を撃破したことにも、味方が逃走したことにもせず、戦績repelsへ加算します。固定戦の勝利継続は実行しません。

Lv5で鎮めの火、Lv10で呼び寄せの火をMP4で点火できます。スキルは現在の職業、レベル、生存、出撃、MP、対象の距離を検査してから消費します。別ダンジョンではこれらの特殊点火を使用できません。通常の魔物にくらがり撃退技を使うこともできません。

通常逃走が成立した入力の中で同じくらがりを即再生成しません。次の歩行遭遇判定まで猶予があり、安全な範囲へ戻るか点火できます。無防護で歩く場合も、次の遭遇は周期と確率に従います。

6. 保存・構造・再生成

編集元は config/dungeons/ の11定義、追加マップ・文章・魔物・道具は config/kagaribi-content.json、職業の技能は config/jobs.json です。範囲、燃料、警告、火の倍率、台座の効果と配置はJSONで変更できます。

生成は npm run build:dungeons。ゲーム用はdata/dungeons.json、新規マップ、kagaribiスクリプト、追加道具・魔物・遭遇、マニフェストです。build:scenarios、build:jobs、build:charactersの末尾にも組み込みました。既存シナリオの再生成ツールの他の性質はこの変更では改変していません。追加職業の変更を反映する場合はbuild:jobsを使用します。

部品レジストリはsrc/core/dungeons.js、火部品はsrc/core/systems/fire-network.js、表示部品はsrc/view/dungeon-systems.jsです。コアが操作可否と効果を判定し、applicationが表示情報を投影します。ビューは内部状態を変更しません。

保存はstate.dungeonsに分離します。activeはダンジョンID・探索番号・成功歩数・携帯火・探索中の種火、persistentはダンジョンと部品ごとの台座状態・持ち帰った種火です。地図発見は既存discoveredに保持します。別迷宮では火部品が作動せず、元の灯油・遭遇処理になります。

旧内容版の移行は行いません。現在版で保存領域が欠けた記録もエラーとし、新規開始へ切り替えます。

実行中の敵の環境倍率は戦闘へ保存し、定義から再計算した能力と照合します。旧戦闘は倍率1です。火の状態・所持数・効果ID・燃料・所属ダンジョンが不正な保存は、Coreで拒否した後、Applicationが新規開始へ切り替えます。

7. 検証

現行の全体検証は[PROGRESS.md](PROGRESS.md)を参照してください。篝火の操作・保護・保存・撃退・旧セーブをテストしています。

クラウドブラウザはローカルHTTPへの接続をERR_BLOCKED_BY_CLIENTで拒否しました。ブラウザでの視覚・クリック確認は未完了です。データ検証、モジュール境界検査、コアの実操作による確認と区別して記録します。

8. 本書で補った具体値と将来範囲

階層数3、90歩、警告25/8、火台10基、各範囲、特殊火の倍率、MP費用、くらがりの能力、帰還時の入口整備、種火一枠は原文に数値がないため今回の設定値として定義しました。変更は編集元JSONで行えます。

一般的なダンジョン編集フォーム、YAML取込、任意イベント・条件ルールの編集、自動生成、蘇生の真相・物語は今回実装していません。火台はGUIから操作でき、作者がJSONで配置・効果を変える方式です。将来設計はDUNGEON_SYSTEM_DESIGN.mdに格納しています。

現在は専用の壁面・装置素材と、q001に付随する携帯灯の現地調査もあります。[素材・現地調査](DUNGEON_ART_AND_SCENARIOS.md)を参照してください。

## q001との接続

1.9.0では巡灯路の油切れ壁灯2本と、老人の最後の弱い壁灯を配置しました。光の現在状態と範囲を共通の火判定で扱い、帰路の消灯時には壁灯と携行火が実際に消えます。新人の火による救助後、町へ帰還します。[改訂概要](DUNGEON_REVISION_1_9.md)と[改稿全文](scenarios/QUEST_CATALOG.md#q001-帰らない灯番)を参照してください。

壁面松明には設置セルとedge方向を指定します。そのセルで面を向いた場合だけ調査・操作できます。照明と魔除けは向きに関係なく設置セルを中心に保ちます。足元の篝火と正面の壁灯がともに操作対象なら両方を選べます。同じ種火の再採取は無効です。[調査操作](ui/INSPECTION.md)を参照してください。
