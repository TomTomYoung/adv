## 生成と検証

```sh
npm run build:scenarios
npm run check:docs
npm run check
```

全生成はbuild:catalogとbuild:docsまで含みます。表示例を変更したら `node tools/build-fixtures.mjs` で11個の現行スナップショットも更新します。配布JSONからカタログだけを更新する場合は `npm run build:catalog`、ダンジョンのみは `npm run build:dungeons`、職業は `npm run build:jobs`、人物は `npm run build:characters` を使います。エディター用スキーマは `node tools/build-schemas.mjs` です。文書の説明だけを修正した場合は全生成せず、`npm run check:docs` と差分確認を行います。集計文書の更新が必要な場合は `npm run build:docs` を使います。

PR #15では全生成を再実行し、data・doc計309ファイルのハッシュが一致しました。今後も生成前後の差分を確認し、配布JSONだけの手修正や、利用者が加えた原稿の上書きを避けてください。

`node tools/build-fixtures.mjs` は data/view-fixtures.json の画面プレビュー用スナップショットを再生成します。文書だけの修正では実行不要です。旧セーブのテストfixtureはこれとは別に保持し、旧版を読み込んだ際に新規開始へ切り替える検証資料として扱います。

## 実装時に維持すること

Coreはゲーム状態を所有し、ApplicationはコピーしたViewModelを作り、Viewは表示とdispatchだけを行います。固有の依頼IDを共通コアへ追加せず、条件・本文・分岐を原稿へ置きます。

技能は `engine.skills` と許可計画器で判定します。人物定義の旧 `skills` 配列だけで使用可否を決めません。派生能力は `actorStats`、環境による制限はダンジョンのフックを通します。テストのレベル変更も `award` を使い、成長履歴との整合を保ちます。

失敗した操作でMP・材料だけを先に失わせないでください。戦闘後の作業は勝利時だけ確定し、逃走・敗北・中断で未成立の救助や合意を追加しません。乱数は保存されたPRNGを使います。

利用者の指定により現行1.10.0も旧内容版のセーブ移行を行いません。読込エラーは最初から開始します。同版の正常な保存は継続できるよう、命令配列を構造変更する際は内容版を更新します。現地調査の改稿は原稿の revision を上げます。

## 立体地形の保守

[CELL_CATALOG.md](CELL_CATALOG.md)に現行セル種・状態・境界・移動手段・配置物の仕様を整理しています。配置索引は `tools/cell-catalog.mjs` からbuild:docsで更新します。新しい部品を加えたら、カタログ本文の仕様と集計の両方を更新してください。

セル・壁・境界の定義は[MAP_CELLS_AND_BOUNDARIES.md](MAP_CELLS_AND_BOUNDARIES.md)です。2Dの25マップとその四方移動・保存形式を保守対象として残します。方向別境界と入口依存の出口制限は拡張仕様であり、現行JSONへそのまま追加しないでください。導入時には移動・経路・退避・保存・到達性・Viewの許可判定を揃えます。

仕様と確認ルートは[VOXEL_TERRAIN_AND_WATER.md](VOXEL_TERRAIN_AND_WATER.md)です。立体区画はvoxel_spaceの一部品が担当します。水門閉鎖時は区域の水没度を保持します。水は体積ではなく、水平連結区域へ適用する操作です。下向きの穴があれば上部を水没させず下へ再帰します。経路途中の完全水没、閉じた面、密の立方体、終点の足場を費用支払い前に検査します。

従来マップの踏査キーはx,y、立体マップはx,y,zです。2D地下水道はフロア単位の0〜10水没度、3Dは水平連結区域単位の操作です。旧版の部分水域・水量保存へ戻さないでください。

### q001「帰らない灯番」の火と恐怖

1.9.0の改稿は実装済みです。現行は7場面、物語状態の改訂2、救助後の2結末です。全文と分岐は[カタログのq001](QUEST_CATALOG.md#q001-帰らない灯番)、仕様と保存時の挙動は[改訂概要](DUNGEON_REVISION_1_9.md)にあります。

入口で新人から火のルールを聞き、油切れの壁灯を確認し、最後の弱い火の下の老人を介助します。帰路で火が消え、火の外にいたくらがりが迫り、新人が老人から受け取った油の火で二人を救います。新人は救助前まで入口に留まり、恐怖が消えたことを救助の条件にしません。恐怖と救助行動を別状態として維持してください。

壁灯3本は `state.objects` と `object.state.set` で個別管理します。油切れは `empty`、老人地点は `low`、帰路の消灯後は `extinguished` です。壁灯の状態をクエストフラグへ複製せず、携行火、人物・油の所在、実マップの座標と整合させます。壁灯の歩数ごとの数値燃料管理は未実装です。

結末は `informed`（巡灯路の修繕）と `compromise`（二人の付き添い）です。旧3結末や新人同行の経路を復活させず、どちらも新人の救助を経て選びます。

### 灯帰り・水没・装備個体・保存

灯帰りの起源と初回依頼の案内は篝火の迷宮に統一済みです。地下水道は2Dのフロア全体の水没度0〜10と潜水・濡れ・魔法補正、3Dは水平区域への操作と下穴への再帰を実装しています。廃坑の塩・洗浄・ソルトイーターによる消失は装備個体単位です。詳細は[改訂概要](DUNGEON_REVISION_1_9.md)を参照してください。

旧内容版セーブの移行は廃止済みです。自動セーブ・手動スロット・記録ファイルの解析または検証に失敗したら、最初から開始して自動セーブを更新します。同版の正常な保存は継続します。担当は `src/application/restore.js` とCoreのloadです。

## 今回実装したワールド接続

町は篝火広場、旅道具店、帰り火亭、灯番組合、医学校、標本室、保険審査所を共通IDで定義します。Coreが現在地・所在・会話・移動記録を管理し、Applicationが背景・人物・行き先を投影し、Viewが一枚絵とスプライト、本文・選択肢、取引・編成パネルを描画します。

q002は灯守の地下水道 `region_1` / `region_1_f1` (11, 9) の `q002_decision`、医学校・標本室 `hikarigaeri_medical_specimens`、保険審査所 `hikarigaeri_insurance` を接続します。箱を持参した経路と、運搬人と地下水道へ戻って回収する経路を分けました。審査には同意した運搬人と持参した台帳・荷札が必要で、標本は医学校に残ります。

移動行為の `depart` は出発準備、`effects` は実際の目的地で確定します。`state.journey` を保存し、移動中の人物は `transit`、正確な位置はワールド状態で管理します。中断して場所を離れる場合も探索隊の所在を現在地に同期し、NPCは元の場所に残します。旧版の自動移行は行いません。

ダンジョン所属は既存 `dungeons[].maps` を正本にし、マップとイベント配置点へIDを生成します。QUEST_CATALOGは全200件の実配置とq002の各場面の現在地・出発先を出力し、LOCATION_CATALOGは施設と参照場面を出力します。未定義ID、所属不一致、通行不能・範囲外座標、親子循環、実イベント不一致、カタログの指紋と配置参照のずれを検査します。
