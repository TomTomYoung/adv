### 2026-10-14：Classic/Grid 共存と「隊の状態」での戦闘陣形（仕様・未実装）

**状態：設計仕様。Core・画面・JSON・セーブ形式はまだ変更していない。** 既存のターン制戦闘を廃止せず、同じ戦闘エンジン上の `classic`（従来式）と `grid`（位置・射程式）を切り替える。敵味方にそれぞれ3行5列の仮想グリッドを設ける。味方は町の「隊の状態」から戦闘開始陣形を設定できる。数値や初期配置は以下を実装時の初期仕様とし、全技能・敵のバランス調整は別工程とする。

#### 1. 共通エンジンと戦闘モードの境界

- 共通：AGIによる敵味方混合の行動キュー、同値時の隊列順・遭遇順、先制の追加行動、HP/MP・材料消費、技能Lv・職業権限、命中・クリティカル・ダメージ／回復式、状態異常・バフ・防御・かばう、逃走・勝敗・報酬・戦績、戦闘イベント・中断・保存再開。`src/core/battle.js`・`battle-turns.js` 等の効果処理を二重実装しない。
- `classic`：現在の `enemy`／`ally`／`self`／`all_enemies`／`all_allies` と `maxTargets`、敵AIの対象決定、既存UI・画像配置を維持する。座標・射程・遮蔽・移動の判定を一切要求しない。未指定モードは `classic` とし、既存の遭遇・物語戦を変更しない。
- `grid`：対象選択の前段に座標、射程、着弾地点、効果範囲、経路・遮蔽、占有、移動合法性を追加する。既存の効果計算へは合法な対象集合を渡す。戦闘中のコマンド・対象候補・敵AI・混乱／狂暴化／暴発・かばうの対象変更も同一のGrid計画器を通す。Viewから座標の合法性を独自判定しない。
- Grid内部の移動許可は別設定 `movement: "fixed" | "step"` とする。`fixed` は陣形固定・射程／範囲あり、`step` は手番を使った位置移動あり。第三の戦闘エンジンは作らない。強制位置変更の扱いは技能別に明示する。

**戦闘開始時のモード決定順（上位優先）：** `battle.start` の明示 `battleMode` → `data/encounters.json` の `battleMode` → 保存対象のプレイヤー希望値 `state.battleModePreference`（`auto`／`classic`／`grid`。`auto` は指定なし）→ `data/game.json` の `battle.defaultMode`（省略時 `classic`）。値は `classic`／`grid` に限る。指定済みのイベント／遭遇をプレイヤー希望で上書きしない。プレイヤー希望の切替操作は将来の「記録／設定」に置き、変更は**次の戦闘開始から**反映する。`state.battle.mode` を開始時に確定・保存し、戦闘中およびロード再開時に再判定・変更しない。`movement` はGrid遭遇の定義を優先し、未指定のGrid戦闘は `step`。

想定定義例（仕様例であり、現行データにはまだない）：

```json
{
  "id": "boss_1",
  "battleMode": "grid",
  "movement": "step",
  "enemies": ["guard_1_elite", "guard_1"],
  "enemyPositions": [{"x": 2, "y": 2}, {"x": 1, "y": 2}]
}
```

#### 2. グリッド座標と距離

- 各陣営のローカル座標は `x=0..4`、`y=0..2`。表示上は敵陣の3行を上、味方陣の3行を下に置く。双方を縦につないだ戦闘座標は `x=0..4`、`y=0..5`。
- 敵の戦闘座標は `y=0` が後衛、`1` が中衛、`2` が前衛。味方は `y=3` が前衛、`4` が中衛、`5` が後衛。味方の保存用ローカル `y=0/1/2` を戦闘開始時に `3/4/5` へ変換する。両陣の前衛同士（敵 `y=2` と味方 `y=3`）は隣接している。
- 距離は初期仕様としてチェビシェフ距離 `d=max(abs(dx),abs(dy))` を採用し、斜め隣も距離1とする。射程は整数の `minRange..maxRange`（両端含む）。射程だけで遮蔽無視や命中確定にはしない。
- 初期実装は1ユニット1セル。生存ユニット同士の重複配置は禁止し、空セルは地点指定可能。大型敵の複数セル占有、障害物地形、高低差、陣営越えの通常移動は後続拡張とし、今回のデータ構造をそれらと混同しない。

#### 3. 味方陣形の正本と「隊の状態」画面

- 通常のセーブ状態に `state.partyFormation` を追加する。形式は `{ "ada": {"x": 2, "y": 0}, "nio": {"x": 1, "y": 0}, ... }` のような **現在の `members` のactor ID → 味方ローカル座標** の写像とし、酒場の待機者は含めない。職業や人物定義・戦闘中ユニットのデータには置かない。全員の座標は範囲内かつ一意でなければならない。
- 「隊の状態」の**パーティー欄に「戦闘陣形」入口**を追加する。従来のパーティー／酒場と人物プロフィールの4領域・△▽の操作は消さない。入口から専用の3行5列編集画面へ切り替え、前衛／中衛／後衛、人物名・位置を確認できるようにする。画面だけの選択・ハイライト状態は保存しない。
- 編集は「人物または占有セルを選択 → 移動先セルを選択 → Coreへ確定」。空セルなら移動、別の在隊者がいれば両者を入れ替える。取消は未確定選択を戻し、MP・アイテム・行動順・歩数・乱数・ターンを消費しない。選択とフォーカスは確定後も維持する。配置不能セル・異常な座標は無効化し、Coreは拒否理由を返す。背景内表示／従来表示とキーボード操作の挙動を共通化し、狭い画面ではグリッドを判読可能なサイズに保つ。
- 変更可能なのは **町の通常滞在中**（`state.mode==="town"` かつ `dungeonInterior` ではなく、`waiting`／`battle` なし）のみ。迷宮での「隊の状態」は保存済み陣形を**閲覧のみ**。戦闘中の実際の位置は戦闘画面で表示し、陣形編集画面から変更しない。Classicでも陣形の編集・保存は可能だが、Classicの対象判定・表示には影響させない。
- **隊列（`members` の表示・同AGI時の順番）と空間陣形（`partyFormation`）は別物**。既存 `party.order`／酒場側 `rosterOrder` の△▽は並び順だけを変更し、座標を動かさない。逆に陣形編集は `members` の順序を変更しない。専用のCoreコマンド案は `{type:"party.formation.set",actor:"ada",x:2,y:1}`。Viewは直接 `state` を書き換えない。
- **加入**はその人物へ空き座標を1つ割り当て、**待機**はその人物の座標を削除して残留隊員を動かさない。既存の `party` の `swap`（交代）が実行された場合は、退出者の座標を新加入者へ引き継ぎ、他の位置を保持する。再加入時の過去位置は自動復元しない。配置変更と編成変更は同時に原子的に確定し、失敗した場合は両方を無変更とする。
- 初期の決定的な味方配置優先順（`[x,y]`、ローカル）は `[2,0]`、`[1,0]`、`[2,2]`、`[3,2]`、`[2,1]`、`[3,0]`、`[1,1]`、`[3,1]`、`[1,2]`、`[0,0]`、`[4,0]`、`[0,1]`、`[4,1]`、`[0,2]`、`[4,2]`。新規開始・従来セーブへの初期補完では `members` 順に使用し、加入時は空いている最初の候補を使う。乱数や未定義の「職業からの推測」は用いない。

#### 4. 敵出現配置と戦闘中の位置

- `encounters[*].enemyPositions` は省略可能な配列で、`enemies` 配列の**出現順・個体数**に一対一対応する敵ローカル `{x,y}`（敵 `y=0/1/2` = 後／中／前）とする。同種敵が複数いても種族IDで紐づけず、生成後の `enemy:enemy_0` 等の個体キーで管理する。省略時は敵側の決定的な優先順（先頭は前衛中央 `[2,2]`、続いて `[1,2]`・`[3,2]`）から自動配置し、15セル超・重複・範囲外は検証エラーにする。既存の座標なし遭遇はClassicのまま変更しない。
- 戦闘開始時に `state.partyFormation` と敵初期配置をコピーして `state.battle.grid.positions` に **戦闘全体座標**として格納する。キーは既存 `unitKey` 形式（`actor:ada`／`enemy:enemy_0`）。戦闘中の移動・ノックバックはここだけを更新し、平時の `partyFormation` へ逆流させない。勝利・逃走・全滅・中断後も設定陣形は維持する。`classic` 戦闘は `battle.grid` を持たなくてよい。
- 戦闘不能者の最終座標は履歴として保持するが、占有・遮蔽からは除外する。戦闘中に復帰した場合、元位置が空いていれば復帰し、塞がれていれば同陣営の空きセルへ決定的な順で配置する。空きがなければ復帰可能なスキルを実行不可とし、消費も発生させない。Grid全ユニットの位置は途中保存・再開で保持し、ロード時に再配置しない。

#### 5. 射程、着弾地点、範囲、命中対象

- 既存の技能 `target` は対象陣営・自分の指定として残し、Grid専用の任意 `targeting` に `aim: "unit"|"cell"`、`range:{min,max}`、`area:{shape,...}`、`trajectory`、`friendlyFire`、`maxAffected` を追加する。`unit` は実在する合法対象を狙う。`cell` は空セルも選択できるが、通常の攻撃・回復は範囲に有効対象が1体以上ないと確定できない（空地点への設置型スキルは技能定義で明示した場合のみ例外）。
- 範囲の初期形は `single`、`cross`、`radius`（初期距離規則はチェビシェフ）、`rectangle`、`line`、`cone`、`row`、`column`、`side_all`。中心・方向・長さ・幅は範囲定義の値で決める。射程は「指定点まで」、範囲は「指定点から及ぶセル集合」と分ける。`line`／`cone` の方向は使用者から指定点への向きで確定し、セルの列挙・同距離の処理順は決定的にする。同一ユニットには原則1回だけ効果を適用する。
- 経路種別は `direct`（途中の生存ユニット／障害による遮蔽を受ける）、`piercing`（途中のユニットを貫通）、`lob`（ユニット越しの投擲）、`indirect`（地点発生型で途中のユニットを遮蔽としない）を基本とする。遮蔽のセル通過アルゴリズムはCoreで一意に定義し、範囲攻撃が味方を巻き込むかは `friendlyFire` で明示する。`false` が通常値で、混乱・暴発時の陣営例外を別途扱う。
- 計画順は「行動者・習得・職業権限・コスト・状態・環境 → 射程と経路の合法性 → 範囲内の生存対象列挙 → 敵味方フィルタ・対象数／特殊条件（解析済・かばう等） → 実行確定」。プレビュー・無効選択・取消ではMP/HP/材料/乱数/行動機会を消費しない。確定後のみ現行の `performSkill`／`applySkill` を使う。
- **選択点数と実際の被効果者数は別**。現行 `maxTargets`、職業 `grant.maxTargets`（多対象上限8）および `scatter` のHP割合順3人などは、Classicでは完全維持。Grid移行直後も既存技能の上限を勝手に15へ拡大せず、`maxAffected` 等で明示調整した技能だけ範囲上限を変える。初期Gridでは `attack` の武器射程を `equipmentType` から取得（剣・斧・短剣・手甲・杖は1、槍は1–2、弓は2–5を仮値）、技能固有の `targeting` はこれに優先する。
- 既存技能に `targeting` がない場合は動作不能にせず、移行中の互換プロファイル（`self` は自身、`ally` は味方陣内0–4、未指定の `enemy` は暫定1–5、`all_allies`／`all_enemies` は既存の全域・既存上限）をCore側で決定的に適用する。これは**暫定の移行規則**であり、公開用Grid対応完了条件は `data/skills.json` の76技能・使用武器・敵AIの各射程／範囲を個別監査して明示すること。スキルLv派生 `effectiveSkill` も同じ解決規則を通し、UIの「魔法／スキル」分類名で暗黙に効果を推測しない。
- `cover`（かばう）は従来の単体攻撃リダイレクトを維持し、Gridでは発動時・適用時にかばう相手と隣接（距離1以内）していることを要する。複数対象の範囲攻撃は既定では一括肩代わりしない。混乱・狂暴化・暴発・反動・自己効果・道具も共通計画器を通して、範囲外の対象へ無制限に飛ばさない。

#### 6. Gridの移動・敵AI・戦闘表示

- `movement:"step"` では1手番の「移動」で上下左右・斜めの隣接空セルへ1マス移る。原則、自陣3×5内のみ、同セル占有と盤外移動は禁止。移動のみでその手番を終了する。移動先不正なら手番・資源・乱数は未消費。突進・攻撃後退・位置交換・ノックバック等の複合行動は別スキルとして将来追加できる。`fixed` では通常移動を出さない。
- 敵AIは行動可能な各技能についてGrid計画器から「射程内の合法な対象／地点」を得て、既存の `priority`・条件・`weakest`／`random` をその候補集合内で評価する。命中人数や距離を考慮するAIは追加の明示パラメータとする。攻撃可能な技能がない場合、`step` なら接近／距離維持の合法移動を検討し、移動不能なら防御または待機する。AI行動も通常の混合行動キューを1枠消費する。先制・スタン・敵味方交互順へ作り直さない。
- Classicの既存UIは維持。Gridは敵味方のセル配置・選択中の使用者・射程内セル・範囲に含まれる対象・無効理由を表示し、対象確定までは効果を実行しない。既存の敵画像・背景・戦闘メッセージ・演出は継続使用し、描画位置やヒット先はCoreが投影した座標を利用する。狭い画面とキーボード／取消にも対応し、色のみで使用可否を伝えない。

##### 敵スプライトの疑似奥行き描画（Grid専用、2026-10-14追記）

- **論理座標と描画を分離する。** 3行5列の敵陣では引き続き1セル1体、戦闘の占有・射程・遮蔽・効果範囲は論理位置 `battle.grid.positions` でのみ判定する。**スプライト画像の矩形はセルからはみ出してよく、隣の敵画像と重なってよい。** 画像の重なりは同セル占有・複数対象命中・射程増減を意味しない。Classicの従来の敵横並び描画は変更しない。
- **横方向の重なり：** 同じ奥行き行の敵同士は、描画後のスプライト可視幅 `W` のおおむね1/3まで水平に重ねてよい。幅が等しければ中心間隔 `Δx≧2W/3`（重なり幅 `≦W/3`）を基準とする。異なる幅 `W_i,W_j` では重なり量 `O=max(0,(W_i+W_j)/2−abs(cx_i−cx_j))` を測り、原則 `O≦maxOverlapRatio×min(W_i,W_j)` とする。初期 `maxOverlapRatio=0.33`。**これは描画レイアウト上の目安**で、画像素材の余白・大型敵・画面幅に応じ個別調整できる。固定5分割のセル枠へ無理に収めず、基準セル座標から最終表示座標を計算する。
- **前後による縮小：** 敵ローカル `y=0`（後衛・奥）を70%、`y=1`（中衛）を85%、`y=2`（前衛・手前）を100%として初期表示する。すなわち `rowScale=[0.70,0.85,1.00]`（`y=0,1,2` の順）。奥へ下がれば縮小、前へ出れば拡大する。**横縦は必ず同じ倍率**で拡縮し、素材のアスペクト比を保つ。敵固有のサイズ補正を許すが、行スケールとの合成順序を固定して明示する。
- **足元基準と奥行き：** 描画のアンカーは `bottom-center`（足元中央）。セルが決める位置に足元を置き、縮小で接地点が飛ばないようにする。画像内の透明余白によって実際の足元がずれる素材は、素材固有の描画オフセットまたは可視領域情報で補正する（戦闘座標は補正しない）。後衛→中衛→前衛の順で重ね描きし、手前が奥を隠す。同行同士の表示順は `x` と個体ID等により決定的にする。前後移動中の平行移動・拡縮はアニメーションさせてもよいが、判定位置はCoreが確定した座標で即時に更新する。
- **対象選択の保証：** 画像が1/3程度重なったり、手前の敵が奥の敵を隠しても、各敵を必ず独立して選択できること。Coreの個体キーに対応した対象リスト／キー操作／フォーカス順を保持し、画面上でクリックしにくい敵も名前・位置・HP・選択輪郭等から識別できるようにする。画像上のクリック領域と論理セルの判定は別とし、前面画像が他個体のクリック操作を完全に奪わないよう補助の選択経路を用意する。選択中・範囲内・攻撃不能を色だけに依存せず区別する。
- **画面幅の適応：** まず論理5列から横の基準位置を求め、画像固有の表示幅・行倍率を使って重なりと画面端を調整する。収まらない場合は敵群全体と余白を見直し、それでも必要なら**縦横等倍率**で縮小する。横方向だけ引き伸ばしたり圧縮したりしない。スマートフォン表示でも前後3行・各敵の識別・選択を維持する。
