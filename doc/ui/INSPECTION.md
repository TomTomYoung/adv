# 便利調べると任意調べる

更新日: 2026-10-10。作品版1.25.0。ユーザー確認済みの仕様として、消費を伴う操作は一つだけでも選択して確定する。

## 操作と候補

便利調べるはEnter・Space・E、任意調べるはRとプレイヤーコマンドのボタンから開く。キーは記録のキー設定で変更できる。既存設定にRの割り当てがある場合はそれを保ち、新しい任意調べるだけ未割り当てにする。ゲームの操作IDは便利が `interact`、任意が `inspect`。キー設定内の既存 `inspect` はEの便利調べるを維持し、新設 `inspectManual` がRを担当する。

便利調べるは、配置物・イベントの interactionRange に合う位置の対象、近傍の装置、および今向いている正面エッジ上の対象を集める。interactionRange は here（省略時：同じセル）・front（正面の一マス先）・here-or-front（両方）。シナリオ地点は配置セルに入り、手掛かりは各配置の interactionRange に従って調べる。セル上の篝火とエッジのたいまつは同等の候補で、片方を優先して隠さない。条件を満たさず出現していない対象や遠方の対象は出さない。

未読の説明、説明・状態・有効条件の変化、現在有効な状態変更操作が候補になる。変わらない説明、確認済みの実行不能理由、処理済みの一回限りの対象は便利調べるから省く。候補がなければウィンドウを開かず、歩数・燃料・危険判定も進めない。

対象が一つなら対象選択を省き、複数なら「何を調べる？」で選ぶ。対象内の有効な操作が一つで、消費しないと確認できれば直接実行する。複数の有効操作、道具・金・MP・HP・種火・使用回数などの消費がある操作は選択肢を表示する。スクリプト自体に選択肢がある場合は、その選択で確定する。候補表示と取消だけで支払わない。無効な選択肢には理由を残す。

任意調べるは足元セル、正面セル、正面エッジ、操作位置に合う配置物・近傍の装置から必ず対象を選ぶ。便利調べるが省いた説明、完了済みの対象、実行不能理由も再確認できる。対象選択後の操作も明示確定し、取消は対象一覧、さらに取消で探索へ戻る。完了済み対象の報酬・処理を再実行しない。

## 未読情報とマーカー

「？」は、現在の条件で読める未読情報がある手掛かりを示す。ミニマップ・拡大地図と、通常表示・背景内表示の探索画面に同じ判定を使う。灯番の巡回記録などのセル上の手掛かりも、壁面の手掛かりも、本文を読み切って調査を終えると消える。説明や提示選択肢が新しくなれば再び表示し、既読として記録した説明へ戻っただけでは再表示しない。表示する本文・選択肢がない対象や、まだ実行条件を満たさず本文を読めない対象には表示しない。

既読の対象に操作が残っていることと、未読情報があることは別に扱う。たとえば油蔵の記録を読み、「探索へ戻る」を選んだ場合は、搬送路を確かめる操作を残したまま地図・探索画面の「？」を消す。選ばなかった操作の結果の文章を、今読める手掛かり本文として数えない。便利調べるは有効な操作が残れば引き続き候補にし、任意調べるでは既読の説明も再読できる。

対象名の一覧や操作前の確認を開いただけでは本文を既読にしない。複数段の説明は最後まで読み終えてから確定し、途中で保存・再開しても未読を維持する。調査の結果として別の説明が解禁された場合、その新しい説明は読むまで未読のまま残す。

既読の「？」は地図・探索画面の両方から消し、地図のセル説明からもその対象名を省く。配置物のデータ、当たり判定、地形・壁の描画、壁灯の光、任意調べるの入口は残す。同じセルに複数の手掛かりがある場合は、既読の対象を候補から除いてから描画対象を選ぶため、残る未読の印を隠さない。表示側の扱いは[表示契約](VIEW_CONTRACT.md#未読の手掛かりの目印2026-10-10)と[ミニマップ仕様](MINIMAP.md#未読情報の表示)を参照。

## エッジ配置

マップ物体、クエストイベントのpoints、fire_networkのfixturesに任意の `edge` を指定する。値は `north`・`east`・`south`・`west`。例は `{ "map": "kagaribi_f2", "x": 1, "y": 1, "edge": "north" }`。座標は壁セルではなく、操作する側の通行可能セルを指す。

指定セルに立ち、その方向を向いたときだけ操作できる。隣接セルや壁の反対側から同じ対象を扱わない。エッジ物体にはinteract、クエストの操作調査にはactionを使い、enter・auto・セル全体を塞ぐblockingとの併用は拒否する。エッジの通行・遮光規則を追加する機能とは別である。

q001の西・東の油切れ壁灯と老人の壁灯、および篝火の地下二・三層入口の壁面松明をエッジ配置にした。既存の物体ID、点灯状態、物語上の油消費は維持する。光源と魔除けの範囲は設置セルから計算し、プレイヤーの向きで消えない。歩行画面とミニマップではセル上の物体と分けて表示する。

## 判定・保存・拡張

`src/core/player-commands.js` が候補収集と実行時の再検査、`inspection.js` がスクリプトの読取専用解析と既読の指紋を担当する。便利調べる向けの `signature` は本文・条件分岐・物体状態を比較し、マーカー向けの `information` は現在の本文と提示選択肢を比較する。選択肢の実行先は消費・効果の解析対象に残すが、未選択の処理本文を現在の情報へ混ぜない。乱数を進めたり仮のゲーム実行で副作用を起こしたりしない。

解析は完全なスクリプト実行器ではない。ランダム処理、再帰、解析上限、未知の副作用は操作候補を残して選択を要求する。状態への書込みが後続分岐を変える場合も、その分岐での消費を見落とさないよう保守的に選択を残す。新しい命令・装置を追加したら、意味のある変化と消費の判定を更新する。

同じ種火の重複採取は無効にした。既存装置は操作計画の可否を使うため、有効な切替・待機などは再利用できる。新しい無効果操作は計画器で無効にし、便利調べるの候補へ戻さない。

`state.inspections` に既読の指紋、`inspectionActive` に調査スクリプト完了時の更新情報を保存する。説明ごとの履歴は `<record>/read/<information>` のキーに残し、最後に読んだ説明だけへ上書きしない。本文・選択・戦闘途中から同版保存を再開でき、終了時に既読を確定する。新しい本文が解禁されている場合、便利調べる向けの指紋をその新しい本文の値で先に更新しない。

調査中の状態変更で開始時と終了時の説明が異なる場合は、実際に表示された分岐を推測せず、開始時の説明も含めて既読の更新を保留する。この場合は、条件が元へ戻ると再確認の「？」が出ることがある。壁灯のように調査の外で説明が切り替わる対象は、各説明を読み終えた履歴を保持する。

履歴キー追加前の同版保存も、既存の指紋が現在の情報に一致し、有効な本文を読んだ記録と確認できれば引き継ぐ。実行途中の先行記録や、条件未成立の理由だけを確認した記録から本文を既読扱いにしない。コマンドの対象選択は現在地と向きも保持し、変更後に古い選択IDを送っても実行しない。旧内容版の保存は移行せず、新規開始する。

地下関所などの入室は、対象が一つでも「詰所に入る」を選択します。操作の `explicit` 指定は資源消費と独立しており、入室で金・歩数・灯油を消費しません。

操作位置の記法と既存配置の分類は[クエストイベント仕様](../scenarios/QUEST_EVENTS.md#操作できる位置)を参照。地図の印や歩行画面の表示は操作位置と独立し、表示されるだけではイベントを実行できない。
