# UIの根本方針と現在の実装

更新日: 2026-09-23。基準masterは `79f43e3`、PR #39まで反映済みです。作品版1.18.0。下部領域の通常28%・最低200pxを維持し、戦闘を左コマンド・右メッセージへ整理しました。

## 根本の目的

プレイヤーが意識する対象は、探索している場所、会話の相手、敵、行いたい行為です。UIは、その場で何ができるかを示し、選んだ行為を確実に実行するために置きます。内部のイベント状態やデータ構造をプレイヤーに操作させる画面にはしません。

通常の冒険は少数の共通操作で進めます。台詞を読む、選択肢を選ぶ、移動する、調べる、敵と戦う流れは決定と方向入力で完結させます。装備・編成・記録などの管理へ入るときに別の操作を使っても、開いた後は決定・キャンセル・方向入力へ戻します。画面ごとに操作を覚え直す負担を増やしません。

## 一つの場面の中で遊ぶ

町やダンジョンの背景を主画面とし、本文・選択肢・プレイヤーコマンド・隊の状態をその内側へ収めます。管理の一覧は必要なときに画面内で開きます。状況を読むために操作欄と別のページを往復させず、人物・敵・現在地と行動の関係を保ちます。

シナリオの本文と選択肢は一つのメッセージウィンドウに統合します。「調べる」「帰還する」などの通常行為はコマンドウィンドウから始め、対象や確認が必要ならメッセージへ続けます。装置ごとの常設パネルを増やして背景を覆いません。

物語上の到着は、プレイヤーが目的地へ到着したことで成立します。条件を満たすフィールドイベントは自動で始めます。「目的地で続きを進める」のような管理ボタンで到着を代行しません。これらの発火・成否・費用はゲーム側が判定します。

## 探索が基準、選択が必要な間だけ項目を選ぶ

ダンジョンで会話・戦闘・管理画面がない状態では、方向入力をそのまま移動へ渡します。上で前進、下で後退、左・右で方向転換し、決定で足元・正面を調べます。移動ボタンを選んでから決定する手順を通常の探索に挟みません。探索へ戻ったら「調べる」を初期フォーカスにし、移動ボタンに以前のフォーカスが残っていても決定は調査を始めます。

シナリオの本文が出たら決定で読み進め、選択肢が出たら先頭の有効な項目へフォーカスします。その間は方向入力で選択肢を選び、ダンジョン内の移動は起こしません。町、戦闘、装備・記録などの管理画面でも、方向入力は現在の操作範囲にある有効なボタンを選びます。本文や背景画像、無効な項目へ迷い込まず、長い一覧では選択項目を見える位置へスクロールします。同じ選択画面の再描画では操作位置を保ちます。

選択画面の決定は現在選択している行為に使います。戦闘では行動を選び、必要なら敵や仲間を選び、最後の決定で実行します。候補を見たり対象を選んでいるだけでは、手番・道具・MPを消費しません。

戦闘の操作は左下、結果のメッセージはその右に配置します。左側は行動者・現在の階層・候補に絞り、スキルとアイテムはそれぞれの項目から一覧を開きます。情報や候補の増加で枠を縦に伸ばさず、固定高の内部スクロールを使います。探索装置の説明や常設キー説明を戦闘の行動一覧に混在させません。[戦闘配置と検証方法](IN_SCENE_VIEW.md)。

キャンセルは最前面から一段ずつ戻ります。候補一覧、詳細、管理画面を閉じ、町では親地点をたどって最初の広場、ダンジョンでは探索へ戻れることを基準にします。最上位でキャンセルしても、別の管理画面を開きません。作者が用意した安全な中断は使えますが、必須判断の選択、無料の逃走、帰還費の支払いをキャンセルが代行してはいけません。

## 設定とビューの責務

決定・キャンセル・方向は共通入力です。現在の場面が、その入力を移動・調査に使うか、項目の選択・実行に使うかを決めます。Enter・Esc・矢印などの物理キーは、その意味に割り当てる入力です。キー設定を変えても画面の戻り順序、行為の費用、判定は変えません。

本文のページ位置、候補の選択、フォーカス、未適用のキー設定はUIの状態です。人物の立ち位置・左右反転・前後関係は作者の演出指定として保存し、Viewはその指定を描画します。進行・所持品・乱数・条件判定はCoreに置きます。Viewは投影された情報から既存のintentを返し、隠された状態や選択肢の日本語から成否を推測しません。背景内表示と従来表示は同じゲーム状態・同じ操作の意味を使います。

## 現在できること

PR #27で背景内表示と従来表示の切り替え、画面内の管理ウィンドウ、表示専用の長文ページ送りを実装しました。初期表示は背景内表示です。「記録 → 画面配置」で変更でき、設定はブラウザへ保存します。

PR #28で両ビューの決定・選択・キャンセルを共通化しました。今回、探索中まで矢印がボタン選択になる挙動を修正し、十字キーの直接移動と決定の調査を基準にしました。台詞の続き、先頭の有効な選択肢、次の戦闘手番へフォーカスを移します。戦闘対象、装備する仲間、転職先・交代相手、掲示板の絞り込み、記録の設定をボタンで選べます。記録後は同じ枠、転職後は開いた詳細を保持します。

管理画面を閉じた後は、町ならコマンド選択、ダンジョンなら直接探索へ戻ります。記録・ヘルプを閉じたときも探索の初期フォーカスへ戻します。町の二階層から広場への復帰、戦闘の対象選択を取り消した際の無消費、記録の新規開始確認からの復帰を自動試験で確認しています。WASD移動とEの調査は探索の補助キーです。選択肢の数字指定、マウス、Tabで明示的にボタンへ移る補助経路も使えます。Tabの後でも方向入力・キャンセル・再描画で探索の基準へ戻ります。

キー設定はPR #29で追加しました。「記録 → キー設定」に主キー・副キーの変更、競合の検出、適用・取消・初期値復帰を実装しました。適用前は現在の操作を維持し、適用後は通常画面と記録画面の両方へ反映します。割り当てはブラウザへ保存し、Escで戻る経路を固定で残します。[キー設定仕様](KEY_CONFIG.md)。

## 残っていることと確認の基準

固定領域では、文章量でウィンドウや人物を押し上げません。左本文は実寸によるページ送り、右選択肢は内部スクロールとし、方向入力で選んだ項目を見える位置に保ちます。人物は大きな立ち絵を標準に、場面の関係に沿って配置します。q001の帰還報告は二人を左、組合のリネを右とし、発話者だけを手前へ出します。カード表示も選べます。[人物演出仕様](CHARACTER_STAGING.md)。

自動試験に加え、今回の固定領域・ページ送り・人物表示・選択肢スクロールは実ブラウザで確認します。最新の件数と確認範囲は[PROGRESS.md](../PROGRESS.md)を参照してください。キー設定の全経路、全管理画面、全戦闘と音声の実画面検証は引き続き残ります。

キー設定の最初の対象はキーボードです。ゲームパッド、タッチ操作の専用配置、修飾キーとの組み合わせ、端末間の設定共有は未対応です。文字入力・ファイル選択・音量調整ではブラウザ標準の操作も使用します。これらを少数の共通操作へ近づける場合も、入力や取消の意味を画面ごとに変えないことを基準にします。

UI変更時は、通常の冒険でマウスを要求していないか、探索の方向入力が直接移動になるか、選択中に背面が移動しないか、次の行為へフォーカスが続くか、キャンセルが最上位まで戻れるか、選んだだけでゲームが進んでいないかを確認します。具体的な検証結果は[PROGRESS.md](../PROGRESS.md)に記録します。
