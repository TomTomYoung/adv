# UIの根本方針と現在の実装

更新日: 2026-09-19。確認したmasterは `570eae6`、PR #28まで反映済みです。今回の文書整理とキー設定は、その続きの変更です。

## 根本の目的

プレイヤーが意識する対象は、探索している場所、会話の相手、敵、行いたい行為です。UIは、その場で何ができるかを示し、選んだ行為を確実に実行するために置きます。内部のイベント状態やデータ構造をプレイヤーに操作させる画面にはしません。

通常の冒険は少数の共通操作で進めます。台詞を読む、選択肢を選ぶ、移動する、調べる、敵と戦う流れは決定と方向選択で完結させます。装備・編成・記録などの管理へ入るときに別の操作を使っても、開いた後は決定・キャンセル・方向選択へ戻します。画面ごとに操作を覚え直す負担を増やしません。

## 一つの場面の中で遊ぶ

町やダンジョンの背景を主画面とし、本文・選択肢・プレイヤーコマンド・隊の状態をその内側へ収めます。管理の一覧は必要なときに画面内で開きます。状況を読むために操作欄と別のページを往復させず、人物・敵・現在地と行動の関係を保ちます。

シナリオの本文と選択肢は一つのメッセージウィンドウに統合します。「調べる」「帰還する」などの通常行為はコマンドウィンドウから始め、対象や確認が必要ならメッセージへ続けます。装置ごとの常設パネルを増やして背景を覆いません。

物語上の到着は、プレイヤーが目的地へ到着したことで成立します。条件を満たすフィールドイベントは自動で始めます。「目的地で続きを進める」のような管理ボタンで到着を代行しません。これらの発火・成否・費用はゲーム側が判定します。

## 決定は行為、方向は選択、キャンセルは戻る

方向入力は現在の操作範囲にある有効なボタンを選びます。本文や背景画像、無効な項目へ迷い込みません。長い一覧では選択された項目が見える位置へスクロールします。次の選択肢や手番になったら自然な初期項目にフォーカスし、同じ画面の再描画では操作位置を保ちます。

決定は現在選択している行為に使います。戦闘では行動を選び、必要なら敵や仲間を選び、最後の決定で実行します。候補を見たり対象を選んでいるだけでは、手番・道具・MPを消費しません。

キャンセルは最前面から一段ずつ戻ります。候補一覧、詳細、管理画面を閉じ、町では親地点をたどって最初の広場、ダンジョンでは探索へ戻れることを基準にします。最上位でキャンセルしても、別の管理画面を開きません。作者が用意した安全な中断は使えますが、必須判断の選択、無料の逃走、帰還費の支払いをキャンセルが代行してはいけません。

## 設定とビューの責務

決定・キャンセル・方向選択は操作の意味です。Enter・Esc・矢印などの物理キーは、その意味に割り当てる入力です。キー設定を変えても画面の戻り順序、行為の費用、判定は変えません。

表示配置、ページ送り、候補の選択、フォーカス、未適用のキー設定はUIの状態です。進行・所持品・乱数・条件判定はCoreに置きます。Viewは投影された情報から既存のintentを返し、隠された状態や選択肢の日本語から成否を推測しません。背景内表示と従来表示は同じゲーム状態・同じ操作の意味を使います。

## 現在できること

PR #27で背景内表示と従来表示の切り替え、画面内の管理ウィンドウ、表示専用の長文ページ送りを実装しました。初期表示は背景内表示です。「記録 → 画面配置」で変更でき、設定はブラウザへ保存します。

PR #28で両ビューのEnter決定・矢印選択・Escキャンセルを共通化しました。台詞の続き、先頭の有効な選択肢、次の戦闘手番へフォーカスを移します。戦闘対象、装備する仲間、転職先・交代相手、掲示板の絞り込み、記録の設定をボタンで選べます。記録後は同じ枠、転職後は開いた詳細を保持します。

管理画面を閉じた後は町・探索のコマンドへ戻ります。町の二階層から広場への復帰、戦闘の対象選択を取り消した際の無消費、記録の新規開始確認からの復帰を自動試験で確認しています。探索のWASD移動とEの調査、選択肢の数字指定、Tabとマウスも併用できます。

キーの割り当てはPR #28時点では固定でした。今回、「記録 → キー設定」に主キー・副キーの変更、競合の検出、適用・取消・初期値復帰を実装しました。適用前は現在の操作を維持し、適用後は通常画面と記録画面の両方へ反映します。割り当てはブラウザへ保存し、Escで戻る経路を固定で残します。[キー設定仕様](KEY_CONFIG.md)。

## 残っていることと確認の基準

PR #28までの自動試験は555件、今回の追加後は576件成功しています。UI試験はNodeのDOMアダプターであり、実ブラウザの寸法・フォーカス描画・ネイティブ入力を保証するものではありません。公開画面で確認できたのはPR #27の「画面配置」の表示と切り替えです。ローカルプレビューのブラウザ接続は拒否されており、PR #28以降の実キーによる通し操作、狭い画面、大きな文字、一覧の収まりの確認が残っています。

キー設定の最初の対象はキーボードです。ゲームパッド、タッチ操作の専用配置、修飾キーとの組み合わせ、端末間の設定共有は未対応です。文字入力・ファイル選択・音量調整ではブラウザ標準の操作も使用します。これらを少数の共通操作へ近づける場合も、入力や取消の意味を画面ごとに変えないことを基準にします。

UI変更時は、通常の冒険でマウスを要求していないか、次の行為へフォーカスが続くか、キャンセルが最上位まで戻れるか、選んだだけでゲームが進んでいないかを確認します。具体的な検証結果は[PROGRESS.md](../PROGRESS.md)に記録します。
