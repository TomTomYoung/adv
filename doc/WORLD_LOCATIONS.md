# 町とシナリオのワールド接続

更新日: 2026-09-18。作品版1.14.0。町の共通ロケーションとq001〜q003の実移動を接続しています。[1.11.0改訂](scenarios/EXPLORATION_AND_PROSE_1_11.md)も参照してください。

## 正本と参照

町の正本は [authoring/locations.json](../authoring/locations.json)、配布先は [data/locations.json](../data/locations.json) です。`game.world.townRoot` を起点とし、各施設は安定ID、名称、親、追加の移動先、背景、人物配置、施設機能を持ちます。共通施設を増やすときはここへ追加し、依頼内に同名の独立した町を作りません。

[ロケーション一覧](LOCATION_CATALOG.md) は10か所の親子・機能・背景・参照場面を配布JSONから生成します。篝火広場の下に旅道具店、帰り火亭、灯番組合、医学校、保険審査所があり、医学校の下に標本室、組合の下に灯番詰所、広場の下に上層の待避場、帰り火亭の下に汚水槽があります。`location.move` は親・子・明示した接続先へ移動します。会話・戦闘中は移動できません。

宿泊・編成は帰り火亭、取引は旅道具店、依頼掲示板は灯番組合、無料の手当は医学校に表示します。`service` と購入操作は対応施設が現在地の場合のみ成功します。遠隔操作で施設へ自動移動しません。通常の迷宮一覧は入口を持つ町ロケーションから出発します。受注中のクエストの入口ボタンは町のどの施設からでも使え、現在の次イベントに対応する迷宮入口へ進みます。現在地を変えない編成・職業等の既存の町内APIは維持しています。

マップの所属は `dungeons[id].maps` を正本にし、生成時に `maps[id].dungeon` とクエストの `events[].points[].dungeon` を付けます。全配置が同じダンジョンに属するときは `events[].dungeon` も付けます。q193・q194など複数ダンジョンに同一イベントを置く場合は、配置点ごとの所属を使います。既存のダンジョン名とIDを地域番号から推測し直しません。

## q002の実際の場所

依頼の正本は [authoring/story-q002.mjs](../authoring/story-q002.mjs)、イベントの正本は [authoring/quests/q002.events.json](../authoring/quests/q002.events.json) です。8場面・3結末、物語状態の改訂2です。全文・座標図・3マップの経路・イベントIDは[q002専用ページ](scenarios/QUEST_Q002.md)へまとめています。

引き揚げ場は灯守の地下水道 `region_1` / `region_1_landing` の (5, 1)、イベント `q002_decision` です。岸と浅瀬の作業は同じ現地イベントの範囲で扱います。標本室は `hikarigaeri_medical_specimens`、審査所は `hikarigaeri_insurance` を参照します。対応は `story.worldPlaces` に置き、各場面の `place` から引きます。

1. 地下水道の現場で、荷札のみの回収、骨箱ごとの引き揚げ、管理番号の照会を選びます。
2. 医学校へ照会する選択では出発準備だけを確定します。帰還し、広場から医学校、標本室へ入ると自動で会話が始まり、貸出台帳との照合が成立します。
3. 箱を持参していればその場で返却できます。浅瀬に残っていれば運搬人と出発し、地下水道の実座標へ戻ってから引き揚げます。持ち帰った箱は標本室への到着後に返却します。
4. 運搬人の同意を得ると、台帳と荷札を受け取り審査所へ出発します。到着後に実書類と証言を照合して、不正請求を立証します。標本の箱は医学校に残ります。

旧版で医学校に置いた荷札を会話内だけで取り戻す処理は廃止しました。現在の審査には持参した荷札が必要です。旧q002の場面・二つの廃止手掛かりイベントも通常データから除去しました。旧内容版のセーブは移行しません。

## 出発・到着・中断

移動行為は `journey: {to, companions}`、出発時の効果 `depart`、到着時の効果 `effects` を持ちます。DSLの `story.journey` が出発処理を一括確定し、会話を閉じます。現在の定義では移動行為へ費用や結末を直接付けません。現場作業や到着後の選択へ分けます。

`state.journey` は依頼・行為・出発場面を保存します。出発した探索隊と同行者の論理上の所在は `transit`、会話場面はnullになります。正確な実位置は `mode` と `townLocation` または `location` が持ちます。町の目的地は場所ID一致、ダンジョンの目的地はmap/x/y/zが足元のセルと一致することを要求します。

Coreのフィールドイベントは、目的地への実到着で到着効果を自動確定します。移動中に元の受付へ戻って再開しても、その移動を巻き戻しません。途中保存・再読込や寄り道では、台帳照合・返却・証拠取得を先に成立させません。到着は一度だけです。上部の目的地・継続ボタンのUIは削除しました。目的地案内は手帳・メインクエスト欄を使います。

通常の中断では現在の場面を保持します。その後に実際の場所を離れた探索隊の `partyAt` は現在地に同期し、依頼の定義外なら `transit` になります。同行指定のないNPCは元の場所で待ちます。戻ると施設の「続きを話す」または現地イベントから再開します。完了済み依頼の物語状態は結末の記録として保持します。

不正な場所ID、移動行為、同行者の所在、現在地と会話の不一致はセーブ検証で拒否します。Applicationの共通復元処理は読込失敗時に最初から開始します。同じ1.14.0の正常な町・会話・移動途中の保存は継続します。

## 表示と素材

Coreが現在地・会話・人物・物品・移動記録を所有し、Applicationの `world-projection.js` が表示用の町・移動案内を返します。Viewは背景、透過立ち絵、場所名、本文、選択肢を描画します。取引と隊編成は施設から開く追加パネルです。背景へ表示した人物の肖像を会話欄へ重複表示しません。

背景7枚は `assets/images/locations/`、標本係・運搬人・審査官の立ち絵3枚は `assets/images/characters/sprites/` です。既存の生成肖像を参照して透過立ち絵を生成しました。背景1536×1024、立ち絵1173×1341。元の生成PNGは保持し、配布画像はサイズ変更・描き直しをせずWebPへ符号化しました。

英語・日本語プロンプト、参照画像、生成元・配布画像のSHA-256は [素材manifest](../assets/source/world-locations/manifest.json)、概要は [PROVENANCE](../assets/PROVENANCE.md) にあります。背景と立ち絵の単体を目視確認し、透過・寸法・ファイル参照を検査しました。

`node tools/build-fixtures.mjs` は現在の処理から11個の独立した表示例を作ります。1.10.0ではブラウザのローカル接続が拒否されました。1.11.0でも実ブラウザ確認は実施しておらず、背景と人物の重なりを含む実画面、スマートフォン幅、音声は未確認です。

## 生成と検証

`npm run build:scenarios` のダンジョン生成末尾で `tools/build-world.mjs` を実行します。手書きのダンジョン所属が間違っていれば生成を止めます。配布JSONの不正なダンジョンID・町ID、所属マップ、通行不能・範囲外座標、現地イベントの不一致、ロケーションの親子循環を `validateContent` が検出します。

`npm run build:catalog` でシナリオと町の索引を更新します。全200件のイベント配置にダンジョンID・名称・マップ・階層・座標・イベントIDを掲載し、q001〜q003では各場面の現在地と施設ID、出発先も掲載します。実装指紋はクエスト・人物に加え、ロケーション・ダンジョン・マップを含みます。`npm run check:docs` は指紋と配置行、町カタログの実データ一致を照合します。
