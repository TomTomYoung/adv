# ダンジョン固有システム 1.7.0

更新日: 2026-09-14。全13ダンジョン・25マップ・200クエスト。13件の固有システムはmasterのcf2920f6（1.7.0）に反映済みです。PR #8の素材・現地調査も本ブランチへ含みます。反映状況は[CURRENT_STATUS.md](CURRENT_STATUS.md)を参照してください。

先に [ダンジョン一覧](DUNGEON_CATALOG.md) を作成・コミットし、そこへ記した10件の追加設定を実装しました。Notionの世界設定・文章は変更していません。以下の植物の表示名、配置、係数、消費量はゲーム用の初期設定です。Notionで未確定とされた固有名や歴史を確定するものではありません。

## 編集と再生成

1. 各迷宮の仕組み、対象セル、移動先、消費量は `authoring/dungeons/<ID>.json` で編集します。
2. 追加マップ・道具・敵・素材価格・初期地図は `authoring/dungeon-content.json`、技能・調合レシピ・職業の許可は `authoring/jobs.json` で編集します。
3. 迷宮だけを変更した場合は `npm run build:dungeons`、技能も変更した場合は `npm run build:jobs` を実行します。Schemaの変更後は `node tools/build-schemas.mjs` も実行します。
4. `npm run check` で参照、通路、保存、操作と既存クエストを検証します。生成物の `data/` を直接編集すると再生成で上書きされます。

JSONを正本とします。YAML入出力、専用フォーム、任意のスクリプトを埋め込むルールエディタは未実装です。既存の仕組みの組み込み・数値・配置変更にJavaScriptの編集は必要ありません。未対応の能力を増やす場合は新しい部品を実装します。

## 部品と実装済みの動作

1. 根喰みの地下庭園：`plant_garden`

   `species` に植物名、`growth`、`radius`、`heal`、`encounterRate`、`materials`、`harvest`、`immatureHarvest`、`terrain` を定義します。`plots` が植床と地形の対応です。両階層に計6植床を配置しました。

   解熱胞子は3行動で生長し、範囲内の生存隊員を行動ごとにHP3回復します。赤蜜花は4行動で生長して遭遇率を2倍、静謐苔は3行動で生長して遭遇率を0.5倍にします。根橋草は5行動で橋を作り、塞道茨は4行動で横道を塞ぎ、階渡りツタは6行動で別階層への移動を可能にします。

   範囲は同一マップ内の縦横距離の合計で判定し、初期値は3です。複数の植物の遭遇倍率は乗算します。壁越しでも距離内なら効果が届きます。

   各植物は対応する種・胞子1個と培養土1個を消費します。入口の育苗箱から、6種類の種・胞子を各2個と培養土12個を一度だけ受け取れます。追加の資材は町で購入できます。成株の採取では種に加え、薬効葉・赤い蜜・植物繊維・硬い茨を得ます。未成熟で取り除くと種だけが戻ります。薬効葉と赤い蜜は錬金術師が傷薬へ、繊維は縄へ加工できます。赤い蜜は市場の交渉にも使います。

   植物と成長度は退出後も保存します。成長はその庭園での成功した移動と「生長を待つ」で進みます。採取すると周囲への効果と地形変化が消えます。隊の足元へ茨が生える場合は成長を待ち、橋の上から橋を取り除く操作は拒否します。素材不足・袋の上限超過では操作も消費も行いません。

2. 鏡沈みの礼拝堂：`warp_network`

   `portals` に8枚の鏡を配置しました。各鏡の `destination` は別の鏡のIDです。現在地と正面の鏡を操作でき、移動先の名前を確認できます。階層をまたぐ4組の接続を組み合わせて探索します。接続は個々の鏡に指定するため一方通行にもできます。実体・鏡像の別世界を増やす仕様にはしていません。

3. 灰時計の書庫：`skill_library`

   `books` に本、技能ID、API、座標を設定します。`gates` は開門技能と開通するセルです。両階層に計6冊と4封印を配置しました。

   一人につき一冊を借り、自分の習得済み技能一つを「忘却の栞」で封じます。交換先は「余白の開門」「祓いの光」「調息」に対応する技能です。自分がすでに持つ技能は借りられません。別の本へ交換すると元の封印を解き、新しく選んだ技能を封じます。

   「余白の開門」はMP3で封印通路を開きます。戦闘技能は戦闘コマンドから実際に使用でき、封じた技能は使えません。本の前で返却するか、書庫を出ると元の技能へ戻ります。開通した通路は保存します。職業・成長履歴そのものは変更しません。

4. 眠れる地下市場：`market_pacts`

   `offers` で通行料、物々交換、購入、護衛を定義します。両階層に計8取引を置きました。通行料15Gで横道を開き、赤い蜜1個で別の魔物を追い払わせます。傷薬は8G、護衛は20Gです。

   護衛は30歩の間、通常遭遇率を0.35倍、通常遭遇の敵の強さを0.75倍にします。シナリオが固定指定する戦闘編成の強さはこの護衛補正の対象外です。

   戦闘開始ごとに警戒が1増え、上限は5です。警戒2で店と交渉窓口が閉じ、警戒2・3で各階の横道へ用心棒が増えます。用心棒は正面から戦え、勝利するとその探索中の障害がなくなります。逃走では排除されません。

   支払った通行料と物々交換による開通は永続です。警戒、護衛の残り歩数、用心棒の排除は退出時に解除します。

5. 黒潮の沈没城：`air_supply`

   `water` が水中セル、`pockets` が最初から空気の残る場所、`devices` が浮上装置と追加の補給地点・通路です。24の残存空気地点と4つの浮上装置を配置しました。

   空気は最大36。水中移動で1、戦闘開始で2、敵の行動を含む戦闘ラウンドで2消費します。残量10以下で告知します。空気のあるセルへ移動すると満量になり、補給ボタンでも補充できます。浮上装置は新たな補給地点と出入口を開きます。

   空気0では、消費の機会ごとに生存隊員へ最大HPの12%を切り上げた窒息ダメージを与えます。全員が倒れると通常の敗北・救助処理へ進みます。戦闘開始時に全滅した場合も操作不能の戦闘を残しません。浮上状態は永続、空気は探索ごとに初期化します。

6. 鉄胎の機関廟：`power_grid`

   `controls` が配電盤、`devices` が装置と所属系統、`power` が必要動力です。初期容量は3で、両階層に計4系統・8装置があります。動力は迷宮全体で共有します。

   門扉系統は扉1・門番1、移送系統は昇降機2・修復装置1を使います。配電盤で系統を選ぶと、同じ系統の門番も起動します。装置の前で機関部品を外すと、その装置を電力計算から外せます。部品を戻せば再接続できます。門番を事前に切り離すことで、起動を避けて扉だけに給電できます。

   昇降機は別階層へ移動します。修復装置は隊を回復し、一回の探索につき計3回使えます。扉の中にいる隊を閉じ込める切断操作は拒否します。配電状態と取り外した部品は永続、門番との決着と修復回数は探索中だけ保持します。

7. 星欠けの地下観測所：`terrain_shift`、`mode: "manual"`

   `states` に地形パターン、`controls` に天球儀を配置します。同じ対象セルへ、各パターンで床 `.` または壁 `#` を指定します。東星／西星の2配置により計8か所の横道を切り替えます。プレイヤーが天球儀を操作するまで変化しません。選んだ地形は退出後も保持します。重力の物理シミュレーションは行いません。

8. 帰還者の深淵：`vector_curse`

   各床セルに流れを定義します。編集元の `vectorRows` は、マップと同じ寸法の文字列配列です。`↑ → ↓ ←` が流れ、`・` が無方向、`#` が壁です。生成時に検証し、配信用の座標・ベクトル配列へ変換します。直接 `vectors` 配列で書くこともできますが、両方は指定できません。

   実際の移動変位と出発セルのベクトルの内積が負なら、デバフを1重加算します。向き変更、壁にぶつかった操作、階段・ワープそのものには加算しません。現在の配置は入口から離れる方向を基本にし、入口へ逆戻りすると累積します。

   初期値は攻撃・防御・素早さ・知力を `0.6 ^ 累積数` 倍にし、切り捨てます。2重で36%、5重で約7.8%、上限100重です。HP・MPの上限は変えません。階層移動やセーブでは解除せず、深淵を出ると解除します。通常の帰還印は使用でき、救援費を払って脱出できます。長い逆行を含む探索は帰還を挟んで行う必要があります。

9. 祈りの届かない谷：`suppression_zone`

   `cells` が遮断区域です。`blockedSkills` と `blockedAbilities` で使用禁止を、`suppressedSkills`・`statuses`・`buffs`・`items` で効果停止を個別に指定します。専用マップの入口側は境界外、東側は境界内です。

   回復祈祷、祓いの光、聖なる守りなどの指定技能と「旅の回復祈祷」を禁止し、呪詠みの呪い、対象の戦闘補正、青石の護符の能力補正を停止します。物理攻撃や通常の傷薬は使えます。すでに受けていた呪いは保存状態に残し、区域内ではダメージを止め、外では再開します。禁止は味方のフィールド操作・戦闘・道具の術と敵AIにも適用します。

   町の行先一覧と探索パネルに禁止・停止対象を表示します。境界の誘導地点で呪詠みを引きつけると、次に歩いた先で戦闘になります。境界の内外を選んで迎え撃てます。追跡中の状態も保存します。境界外へ出ると制限は即座に解除されます。

10. 巨獣上の移動集落：`terrain_shift`、`mode: "random"`

   天球儀と同じ地形パターンを使い、3つの姿勢で足場を変化させます。成功した移動または「様子を見る」で時間が進み、3〜7行動のランダムな間隔で現在とは異なる姿勢へ変わります。プレイヤーが姿勢や発生時刻を直接指定する操作はありません。

   乱数と残り時間はセーブに保持し、ロードしても変化を引き直しません。会話や戦闘中は地形変化を進めません。足元が失われた場合は設定済みの固定乗降台へ退避し、通過していないイベントは発火させません。姿勢は永続、次の変化までの時計は探索単位です。

## マップと物語の関係

既存のクエスト地点と階段を維持し、植物・封印・交渉・浮上・配電・天球儀で追加の通路や移動手段を開きます。鏡とツタ・昇降機を使った階層間移動も可能です。町の「迷宮へ」には谷と移動集落を追加し、既存の地域10へ分類しました。地域数は10のままです。

q193・q194の既存受付地点を残し、専用マップにも同じ依頼の訪問地点を設けました。クエストの状態は共通なので二重完了はできません。谷の治療小屋や集落の契約結果は元の分岐に従います。地形や配電の操作だけでクエストの真相・結末を確定しません。

## コアと画面の境界

各部品は `src/core/systems/` にあり、`src/core/dungeons.js` に登録します。状態初期化、入退場、移動、戦闘開始・ラウンド・終了、地形、能力、技能許可、効果の有効性、操作計画、投影、定義・保存検証を共通窓口で扱います。自由なコード文字列の評価は行いません。

画面は `dungeon.systems[]` の `title/summary/cards/actions/markers` を表示します。ボタンの許可はコアの `plan` と共有し、実行時も再検査します。戦闘中にも空気や区域の制限などの要約を表示します。水没と、植物・用心棒などによる通行不能は描画上でも区別します。

## 保存と検証

作品版を1.7.0へ更新しました。1.6.0・1.5.0のセーブは、その版で存在した部品構成を検証してから、訪問済みダンジョンへ不足する部品だけを補います。既存の篝火、水位、装備腐食、破壊壁、会話、選択、戦闘、所持品、成長、クエスト、乱数は保持します。1.4.0以前の移行も既存試験で検証しています。

現行の全体検証は[PROGRESS.md](PROGRESS.md)を参照してください。各部品の操作、支払い、動的地形、貸出、術制限、窒息、保存、旧版からの移行を検証します。固有状態を読む13件の現地調査も[素材・現地調査仕様](DUNGEON_ART_AND_SCENARIOS.md)へ追加しています。

技能・Schemaを再生成した前後で、全data JSONのハッシュが一致しました。

ブラウザの実画面での目視・クリック確認は未完了です。地下水道・庭園・観測所の描画関数をCanvasへ出力した確認は実施済みです。操作許可・画面投影とコアの一致は自動試験で確認しています。
