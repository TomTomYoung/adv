# 立方体地形・六面の境界・水と移動

更新日: 2026-09-16。対象: 作品版1.9.0。立方体の形状・六面に加え、区域への水没操作を実装しました。従来の二次元マップは高さ0の通路として互換読込し、灯守の地下水道の貯水立坑から立体地形を導入します。

## 空間の単位

2Dも含めたセル・壁・境界の定義、四方／六方の進入・退出と互換性は[MAP_CELLS_AND_BOUNDARIES.md](MAP_CELLS_AND_BOUNDARIES.md)を参照してください。現行の共有面は両方向に同じ通行可否を使います。境界の一方通行と入口依存のセル内接続は、同書の未実装の拡張仕様です。

座標はmapと整数のx・y・z。zが1増えると立方体一個分上がります。一個は人物一人が立って収まる空間です。地形は密（#）と空（.）。密は岩・土・建材などが占め、人物も水も入りません。水は空の立方体の区域に対する水没度であり、地形を密へ変更しません。

空間は東西南北と上下の六方向で接続します。二つの立方体は一つの境界面を共有します。境界面には通行、通水、足場の支持を独立して指定し、壁・水門・格子・床板・排水蓋を表します。密の上は床、側面は壁、下は天井になります。下も空で支持面がなければ穴です。

map.voxels.layersは低いzから並ぶ同寸の平面図、minZは最下層の高さです。従来のtilesはz=0の断面を保持します。立体定義のないマップはz=0のtilesを読み、下と上を密として扱います。従来の地形変化部品は従来マップの高さ0で動作します。立体マップはvoxel_spaceを一つだけ所属させ、その六面・掘削状態で地形を管理します。既存の地形パッチ部品を立体マップへ重ねる変換は行いません。

## 区域への水没操作

同じzで、通水できる水平面を通ってつながる空の立方体を一つの区域とします。水没度は0〜10で、区域内の全セルへ同じ値を保存します。1〜3は足元、4〜6は腰、7〜10は完全水没として描画します。6以上の通行には潜水の備えが必要です。

区域に下向きの通水穴が一つもなければ、操作で水没度を上げます。上面が開いていても保持できます。下向きの穴がある場合、その区域は水没させず、つながる下部区域へ同じ操作を再帰的に渡します。複数の穴が同じ下部区域に着く場合、一操作を重複適用しません。下部が複数の閉区域に分かれていれば各区域へ適用します。

下方向の区域外開口は排水先です。waterは体積・水の個数ではなく水没度で、面積で割ったり水量保存を計算したりしません。10で打ち止めとなり、上の区域へ越流しません。drainedは区域からの排水処理回数です。

水門を閉じると、分かれた区域それぞれの水没度を保持します。水平接続を開くと接続先の最大水没度に揃えます。下穴を開くと下部へ水没度を渡し、既にある水没度との大きい方を採用します。この境界変更時の扱いは操作規則の具体化です。流速・波・空気圧などの物理計算は行いません。

通常の地下水道2D階層はフロア全体の周期水没です。立坑は給水・開閉・掘削で水没操作を行い、潮の時刻は進めません。潜水の備え、濡れ、魔法、死亡判定は地下水道の部品と共有します。

## 移動と手段

通常歩行は同じzの隣接空間への移動です。移動先が空、境界が通行可能、水没度6未満または潜水準備済みである、足場があることを検査します。上下への素の移動、穴への落下、密の中への侵入はできません。

梯子・階段・ツタ・縄などは空の立方体を六方向にたどる具体的な経路です。各区間の通行と水没、到着先の足場を確認します。登りと下りの両方に手段が必要です。密の立方体や常時閉じた面を経路が貫く定義は拒否します。開閉できる面を経路へ含める場合、閉じている間は利用できません。壁を越えるには上の空間を経由します。

移動手段は常設、材料による設置、隊を誘導する探索技能による一回の利用を定義できます。設置した縄は退場後も残ります。設置済みの再購入・再消費はしません。今回の隊用技能は技能者一人が仲間を誘導するものです。個人だけの飛行・泳法・別行動は今回の実装に含めません。

橋は上の立方体の下側に足場を作り、橋の下の空間を保持します。橋上の空間が乾いていれば通れ、下の立方体の完全水没を通過した扱いにはなりません。橋上まで水が達した場合はその立方体に水没判定がかかります。

## 操作・保存・退避

操作は表示と実行で同じplanを用い、距離・高さ・習得・出撃・生存・MP・材料・経路・到着を支払い前に検査します。不成立では水没度・地形・所持品・位置・時刻を変更しません。設置、給水、面の開閉、許可された掘削を明示した対象へ行います。

水没度、開閉した面、掘削した立方体、設置経路はダンジョンの永続状態へ保存します。現在地と踏査記録はzを区別します。立体マップのinitiallyKnownも「x,y,z」の形式で指定します。z省略は旧マップの高さ0とします。旧内容版の保存は移行せず、読込エラーで新規開始します。

備えのない足元が水没度10になった場合は溺死として全滅処理を行います。6〜9になった場合、または足場を失った場合は、変更前に通行できた経路から安全足場への退避を検査します。2Dフロアの増水にはこの立体地形の退避を適用しません。現在地から退避できる足場がなければ既存の帰還印で救助します。密・壁・梯子のない上下経路を無視して自動移動しません。会話・戦闘の途中で給排水操作は受け付けません。

## 表示と編集

探索画面と地図は現在のzの断面を表示し、高さと水深を明記します。上下を見回す自由カメラや、橋の下を透かす立体描画は未実装です。境界の壁、水門、床の穴、上下の接続、三段階の水を表示します。Viewは投影済みの空間・面・水深と操作可否だけを読み、ゲーム状態を変更しません。

編集元はauthoring/voxel-content.jsonとauthoring/dungeons/*.json。配布先のmap.voxelsとvoxel_space部品へ生成します。npm run build:dungeons、技能の変更を含む場合はnpm run build:jobsを実行し、Schema・参照・保存・通行・水の検証を行います。

## 貯水立坑での確認手順

町から灯守の地下水道へ入り、入口の「貯水立坑へ向かう」を選びます。座標は0始まりです。立坑内の(1,1,0)の出口を調べると従来の地下水道へ戻れます。

1. (3,2,0)で手押し給水ポンプを使います。初期状態の水門と底蓋を閉じたまま2段階ずつ4回操作すると、貯水室Aの(4,2,0)と(4,3,0)は水没度2・4・6・8となり、表示は足元・腰・腰・完全水没へ変わります。
2. 同じ操作位置で移送水門を開くと、隣の貯水室Bも同じ水没度へ揃います。水門を閉じても残水は残り、底の排水蓋を開くと下の縦坑を通って区域外へ排水します。
3. (2,2,0)の梯子を選び、(3,2,1)の踊り場へ登ります。高さ1の橋を東へ歩けます。下の貯水室と橋上は別の立方体です。
4. (3,4,0)で縄1個を使って渡り縄を設置できます。設置後は追加消費なしで往復できます。同じ場所から発破薬1個、または「岩砕き」で(4,4,0)を掘削できます。
5. 町の酒場で斥候か狩人に転職した隊員がいれば、(3,3,0)から「登攀誘導」で上の足場へ隊を運べます。Lv1から使え、技能者のMPを3消費します。経路が水没度6以上で潜水の備えがなければ消費せず拒否します。

装置は同じ高さの足元または正面から操作します。正面の操作位置との間に閉じた面があれば操作できません。移動経路は端点に立って選びます。上下キーによる自由移動はありません。常設または設置済み経路の利用は通常歩行一回と同じ探索処理を行い、素材による設置と給排水は部品の操作時刻だけを一回進めます。

## JSONの記法

`authoring/voxel-content.json` の `maps.<mapId>` は通常のマップ定義です。その `voxels` にversion、minZ、layers、faces、links、devices、initialWaterを記述します。マップ全体の実例は [編集元JSON](../authoring/voxel-content.json) にあります。

minZ=-1、layersが3枚なら、添字0・1・2がそれぞれz=-1・0・1です。各層は同じ幅と行数を持ち、tilesはz=0の層と一致させます。入口とイベントにはzを指定でき、省略時は0です。全体4096立方体以内、最大16層、空間と掘削予定地の合計512個以内を検証器の上限とします。

共有面は片側から一度だけ宣言します。例えば以下は貯水室の下側の排水蓋です。面の向きはnorth/east/south/west/up/downの六つです。面の操作位置は別の空間に設けられ、離れた蓋をハンドルで操作できます。

```json
{
  "id": "drain_hatch",
  "name": "底の排水蓋",
  "at": {"x": 4, "y": 3, "z": 0},
  "side": "down",
  "operable": true,
  "handle": {"x": 3, "y": 2, "z": 0},
  "initiallyOpen": false,
  "closed": {"passage": false, "water": false, "support": true},
  "open": {"passage": false, "water": true, "support": false}
}
```

passageは面を人物が通過できるか、waterは水が通るか、supportは上側の立方体の床を支えるかです。未定義の面は通行・通水可、支持なしです。密の立方体はこの設定にかかわらず人物と水を遮ります。下向きの範囲外への通水可の面は排水口です。範囲外は歩ける場所にはなりません。

経路のkindはladder/stairs/vine/rope/bridge、pathは六方向に隣接する座標列、bidirectionalは往復可能かです。accessの三種類は次のように記述します。

```json
{"kind": "fixed"}
```

```json
{"kind": "install", "item": "rope", "count": 1}
```

```json
{"kind": "skill", "ability": "climb_route"}
```

devicesではkind=pumpにat、target、amountを、kind=digにat、target、item、countと任意のabilityを定義します。給水先は空、掘削先は操作位置に隣接した密の立方体です。initialWaterは `[{"at":{"x":4,"y":2,"z":0},"amount":2}]` のように初期水没操作を与えます。amountは1〜10の水没度増分です。読込時にも下向きの穴を再帰するため、上部に指定しても下部区域が水没します。密のセルへの操作は拒否し、10を超える増分は10に収めます。

ダンジョン側はsystemsへ `{"use":"voxel_space","maps":["waterworks_shaft"],"portals":[...]}` を追加します。portalsはid、name、map/x/y/zを含むatとdestinationを持ちます。ダンジョン自身のmapsにも対象マップを登録します。正本を変更したらbuild:dungeons、技能も変更したらbuild:jobs、Schemaを変更したらtools/build-schemas.mjsを実行します。

## 保存とスクリプト

`state.location.z` と `discovered.<map>` の `x,y,z` で高さを区別します。従来マップは引き続き `x,y` の踏査記録を使用します。map.teleportにzを指定でき、map_discoveredで立体マップを調べる場合もzを明示します。

`state.dungeons.persistent.<dungeon>.systems.<system>.maps.<map>` はfaces、removed、installed、water、drainedを保持します。水没度は座標キーごとに1〜10を保存し、0は省略します。区域の値が揃わない記録や、下穴のある区域に残る水も不正です。未登録の面、固定面の改変、許可されていない掘削・設置、密や範囲外の水、不正な現在地はロード時に拒否します。旧内容版は移行しません。Applicationが読込失敗を受けて新規開始します。

貯水立坑は新しい二本の `.v1` スクリプトを使い、既存の命令列や継続位置は変更しません。橋上の点検札は会話途中で保存・再開できます。水と地形の進行を既存依頼の救助や結末へ自動的に加算する処理は含めません。
