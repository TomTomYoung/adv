# シナリオ設計とNotionモデルの対応

参照: [シナリオモデル20260908（統合版）](https://app.notion.com/p/20260908-3d5c3c1966b3814c8e26ef30c00862e4)。2026-09-09の実装時に全本文を参照しました。参照先を変更せず、本リポジトリにゲーム用のデータを作成しています。

## 方針

百の依頼を、冒険者が地下へ潜って誰かの説明を現場で確かめる行為に統一しました。魔物を倒す目的だけでなく、救助、修繕、回収、調停、証言の保存、避難路の整備を扱います。

古い装置、労働慣行、記録の誤読、知識の偏りを中心に、世界の事実と人物の解釈の差を作りました。魔物は迷宮の危険・守護者として実在します。事件の原因が別にあっても、通路を開く戦闘は生じます。

## 五層の対応

| 元モデルの層 | JSON | 実行上の対応 |
| --- | --- | --- |
| World | model.world.truth/history/causes | 観察される現場の由来と、選択後の結果を記述 |
| Agent | model.agents | 依頼人の観測・信念・目的と、隊の初期知識を分ける |
| Narrative | model.narrative.units | 依頼文、現場の痕跡、記録・証言、決着を別スクリプトへ配置 |
| Audience | model.audience | 途中の仮説と未解決の問いを作者用に保持 |
| Transformation / Reveal | model.reveal | 既出の二つの手掛かりを参照し、事情を踏まえた選択を解放 |

真相のメタデータを付けただけではなく、quest.evidenceと条件式で実際の選択肢の有効性を変えます。調査を省略すると、依頼を優先した決着か別案の決着を選べます。知ったことと世界に起こしたことを、別々に保存します。

履歴と人物モデルは作者向けの設計記録です。一般的な世界シミュレーターや、自動推論する読者モデルを実装したと主張するものではありません。プレイヤーの推論は人間が行い、エンジンは観察の取得と条件だけを判定します。

## 一件の構成

依頼を受ける → 迷宮の該当階へ潜る → 痕跡と証言を調べる → 決着地点で判断する → 必要なら戦闘を通る → 結末と報酬を保存する → 帰還・継続探索。

100件のタイトル・依頼文・真相・二つの手掛かり・三つの行動・三つの結末は原稿に個別記述しました。番号や固有名詞だけを差し替えて本文を水増しする生成ではありません。プログラムは原稿を共通エンジンのcommands・参照・座標へ変換します。

機械上のジャンルは共通の調査形式が中心です。救助・護送に相当する一部の枠で縄の消費と戦闘、地域の最終依頼で逃走できない守護者戦を加えています。分類typeは作者用であり、すべての分類に別の操作系を実装してはいません。

## 結末と長期変化

選択ごとに依頼人と周辺者の帰結を文章で変え、報酬・経験値・選択数・地域完了数を状態へ反映します。地域ごとの最後の一件は、先行する仕事をある程度経験した後で開きます。全99件を経て最後の一件を開き、共同管理・独占・封鎖という終幕の扱いを決めます。

一件の選択は取り消せません。別の結果を見る場合は選択前の手動記録を読み込みます。報酬比較だけで正解が決まらないよう、事情を踏まえた道は調査と費用、契約優先の道は戦闘、別案は低めの報酬という違いを付けています。すべての結末の価値判断をエンジンの善悪値へ還元してはいません。

## 検証と限界

100件・300結末の到達性、証拠取得前の選択制限、手掛かり保存、完了報酬の一回性、最終解放をテストしています。因果や人物の納得感、公平な伏線、感情的な余韻は人の読解・プレイテストで確かめる必要があります。機械検査の合格を物語品質の保証にはしません。
