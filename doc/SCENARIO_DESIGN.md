## 既存100本の見直し

旧版の「二つの手掛かり→真相を示す無効選択肢→三つの結末」という共通構成には、知識が選択より遅れて提示される問題がありました。真相を含む行動は根拠取得前に非表示とし、判断地点へ来た時点で事情を説明してから、行動を選べるようにしました。事情を知っても依頼優先や別案を選ぶ自由を残しています。

q011の矢印、q013の芽と繊維、q017の空棺、q018の最終割賦印は、追加説明を求める根拠として扱います。これらは一方の観察だけで判断地点の説明を聞けます。他の96本は従来の二つの根拠を照合します。調査前でも説明の不足を申し出られ、その発言は完了後の再会で参照します。

元の依頼文・固定された過去・個別の結末を基礎に、提示順・実行条件・作業費用・再会を改稿しました。既存100本すべてを別の多段場面へ置き換えた版ではありません。旧継続位置との互換性のため、配信済みの命令列も保持します。

## モデルと状態の対応

| モデルの関心 | 実装 | 境界 |
| --- | --- | --- |
| 固定された過去・現在の事情 | model.world、原稿の「依頼と人物」「展開と開示」 | 選択に合わせて過去を書き換えない |
| 人物の目的・信念 | 作者用model.agentsと、本人へ尋ねる場面 | 自律的なNPC推論器ではない |
| プレイヤーが知ったこと | evidence、表示済みの場面、発言・調査フラグ | 作者の真相を未解決ViewModelへ流さない |
| プレイヤーがしたこと | flags.quest.<id>、道具・金消費、戦闘結果 | 質問、同意、配送、返信、避難などを区別 |
| 戦闘の客観的履歴 | recordsと受注時のbaselines | NPCの過去の功績や申告と混ぜない |
| 異なる順序・知識不足 | 各場面の条件式、戻る・保留・別案 | 同じ手順の履修を全件に要求しない |
| 選択の負担と余韻 | 費用、行動条件、個別outcome、再訪 | 表示した報酬で道徳的な正解を決めない |

## 追加100本の構成

Notionモデル配下のGQ001〜GQ100を、既存IDと衝突しないq101〜q200へ対応させました。原稿の控えはauthoring/reference、実行する分岐原稿はauthoring/scenarios-01.mjs〜10.mjsです。100本合計239場面、318結末を持ち、既存篇と合わせて200本・618結末です。

各依頼の開始地点は既存の20マップへ一つずつ追加しました。地下居住区や周辺集落での出張として設定し、依頼内の地理移動は本文と選択で進めます。全ての村・館・道を別の歩行マップとして追加したわけではありません。相談・調査地点は既存イベントや閉鎖扉と重ならず、実際の歩行で到達できます。

途中の状態は場面ごとに保存します。中断・町への帰還・仲間の入替えを経ても、現在場面から続きます。現実時間を待つ処理はなく、葬列の準備、宿泊、配達、封鎖などの選択で有限の時間や回数を進めます。

## ゲーム化した範囲

戦闘を選んだ経路は既存のターン制戦闘で実行します。追加13体の固定遭遇は既存の画像と地域相当の能力を使います。NPCの一時同行は本文内の役割であり、戦闘パーティーへ自動加入させません。原稿のペルとカイルは、該当する依頼だけ既存のレンとイルへ置換しました。

原稿の修理券・紹介状などの報酬は、現行ギルドの金・経験値に換算しました。新規篇は基本的に地域ごとの定額報酬で、q154の盗みへの協力辞退だけ金報酬0です。特殊な利用権や新施設のUIは追加していません。

谷での魔法遮断、勝利の忘却、帰還印の約束などは当該依頼の場面内で成立する設定です。通常探索の魔法使用・帰還処理・本編終了条件へ影響する全世界ルールにはしていません。個別の調整点は各JSONのmodel.adaptation.limitsへも記載しました。

作者用モデルやテストの合格は、物語の面白さや人物の納得感を自動判定するものではありません。今回の実装範囲と検証結果は [SCENARIO_IMPLEMENTATION](SCENARIO_IMPLEMENTATION.md) を参照してください。
