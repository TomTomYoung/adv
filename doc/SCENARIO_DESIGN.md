# ゲームシナリオの設計と実装

更新日: 2026-09-14。作品版1.8.0の実装を対象とします。全200本を一つの手順へ揃えず、人物の目的、固定された過去、得た情報、行為の成立、応答と代償を各原稿で定義します。

## 適用モデルと経路

q001〜q010はモデルv1.1、実装アダプターは `adv-story-state/1` です。人物・物品・場所・保持者・同席・介助・同意・情報の取得条件を検査し、新規進行は `.v11.*` を使います。[モデルの実装範囲](SCENARIO_MODEL_V11.md)と[本文](SCENARIOS_Q001_Q010_V11.md)を参照してください。

q011〜q020はモデルv1.0に基づくカタログ改稿を `.catalog1.*` へ反映しています。個別フラグ、費用、作業、同意、結末条件を宣言します。v1.1の所在検査を持つものとしては扱いません。[現在の本文](SCENARIOS_Q011_Q020.md)を参照してください。

q021〜q200は各依頼の場面グラフと固有条件を使います。内部移動が会話選択として扱われる場面もあり、全ての場所を別の歩行マップにはしていません。

## 状態と情報

`quests.<id>` は受注・証拠・結末、`flags.flow.<id>`／`flags.quest.<id>` は原稿ごとの内部進行、`stories.<id>` はv1.1の検査対象状態、`records` はエンジンが自動記録する戦績です。

`model.world.history` と `truth` は固定された過去を表します。`knowledge` や取得済みの観察は、人物やプレイヤーが何を知ったかを表します。過去の事実と知った時点を同じフラグにしません。作者向けの注釈は制約として保持し、本文へ機械的に流し込みません。

q001では老人・新人・油の所在、q010では住民の到着・帳簿・証言を区別します。q011〜q020の原稿では貸借、避難の標示、筆写、機材の使用目的などを場面の行為と条件へ落とし込みます。場面数や結末数を揃えることを生成器の目的にしません。

## ダンジョンとの接続

歩行マップの固有部品は `dungeons` の状態を管理します。PR #8で追加済みの現地調査はその状態を読み、関連依頼の手帳へ観察を残します。確認対象、調査地点、本文は `authoring/quests/qXXX.events.json` です。

物理的な装置の操作と、救助・合意・証言など別の事実を区別します。本筋の分岐へ接続を深めるときは、行為が何を成立させたかを明示した条件へ反映し、異なる事実を一つの完了フラグへまとめません。

## 正本と生成順序

```sh
npm run build:scenarios
```

基礎データと互換用スクリプト、追加篇、個別構造、v1.1とカタログ改稿、ダンジョン、スキーマの順に生成します。最後に現行データから文書を更新します。

q001〜q010は `stories-v11-*.mjs`、q011〜q020は `catalog-q011-q020.json/.mjs`、その他は `structures-*.mjs` と `scenarios-*.mjs` が主な編集先です。詳細は[HANDOFF.md](HANDOFF.md)へ記載します。

[QUEST_CATALOG.md](QUEST_CATALOG.md)をユーザーが改稿した場合は、内容を確認して正本へ反映してから再生成します。文書更新だけの依頼でカタログ本文を配布JSONへ強制的に戻してはいけません。

## 互換性と検証

旧経路と旧script配列を保持し、進行中・完了済みの旧依頼は元の意味で継続します。1.3.1以前の旧地点、1.3.2の個別進行、v1.1の物語状態、カタログ改稿後の進行を区別します。

結末到達、再開、費用、勝敗時の作業成立、旧セーブの継続を自動検証します。文章が人物の目的や情報取得と整合しているかは、具体的な選択列を読んで確認します。一般化したObjective／Reward、自動期限、世界共通のNPC配置は未実装です。
