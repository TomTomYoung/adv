# ゲームシナリオモデル v1.0 と個別の進行

更新日: 2026-09-10。対象: 灯帰りの迷宮 1.3.2。

基準は [ゲームシナリオモデル v1.0](https://app.notion.com/p/v1-0-3d7c3c1966b381818a0fcb62493abcc3) です。固定された過去、人物の目的、提示した情報、行為に対する応答を分けるモデルを引き続き使います。Notionの原本は変更していません。

## 今回直した問題

1.3.1の既存篇は、事情を判断前に説明するようにはなりましたが、「二地点を調べる→同じ三択」の生成構造が残っていました。依頼番号に応じた戦闘や縄の消費も、人物の目的や必要な作業と無関係に挿入されていました。

1.3.2では q001〜q100 の通常進行を全て個別の原稿へ置き換えました。場面の順序、戻れる場所、作業、選択の条件、戦闘の有無を作者が各依頼に書きます。真相を見せる場面や、集める手掛かりの数をコンパイラが決める処理はありません。検証器の「開示の対象が最低二つ」という制約も外しました。モデルそのものを別の理論へ置き換える必要はありませんでした。

依頼人の希望に従う経路を必ず戦闘にする規則もありません。修理・書類の返却・設備停止はその作業として実行します。既存100本のうち、戦闘を含む個別進行は29本です。通常探索のランダム遭遇は別に残ります。

## 原稿と実行の境界

`authoring/structures-1.mjs`〜`5.mjs` は既存100本の進行、`structures-additional.mjs` は追加篇10本の改稿です。`structure-kit.mjs` は場面・選択・条件式を短く書く記法だけを提供します。`tools/build-quest-structures.mjs` は書かれた行為を通常のJSON命令へコンパイルします。実行時の専用推論器やクエスト固有コードはありません。

固定過去や元の文章は `authoring/quests.txt` と `authoring/reference`、維持した追加篇は `authoring/scenarios-*.mjs` にあります。1.3.1の命令配列は継続互換用として生成し、その後に新しいIDの進行を追加します。

マップは20のままです。各依頼の内部移動は本文と選択で表し、全ての場所を別の歩行マップにはしていません。NPCの同行は場面内の役割で、自動で戦闘パーティーへ加入しません。時間は待機・検温・観測など選択によって進み、実時間や世界共通の時計には依存しません。

通常探索全体への天候変更、NPCの自律行動、汎用の目的生成は追加していません。モデルを実装の都合で固定の調査手順へ縮めることをやめ、既存の状態・条件・分岐で個別の仕事を表現しています。
