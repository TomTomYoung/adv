# 0. 中心命題とv1.2bの改訂方針

人物が、知り得たことと大切にしているものから行為を選び、その行為が世界と関係を変え、後から与えられる情報によって意味が読み直される。その過程へプレイヤーが介入できるものとしてシナリオを設計します。

v1.2bでは、作者用の設定に理由が書いてあることと、読者が実際にその理由を感じ取り、判断し、帰結を経験できることを分けて検査します。整合した台帳は制作の土台です。人物の切実さ、発見、可笑しさ、恐れ、安堵、関係の変化は、本文・選択・出来事の組合せで成立させます。

v1.2に既にある動機、反事実、情報開示、演出、本文だけのレビューを廃止したり、新設だったと数え直したりはしません。今回の改訂は、それらを実際の原稿に適用する判定と差戻しを具体化するものです。

主な改訂は次の九点です。

1. 作者の整合性確認を、そのまま語り手や登場人物の説明にしない。
2. 判断に必要な情報を示しながら、読者が結び付けるべき答えを先に言い切らない。
3. 選ぶ理由を、作者用のwhy欄と、本文で得られる動機の両方から確かめる。
4. 宣言した危険・喪失・両立不能が、実際の経路に存在するか確かめる。
5. 自然な別解を採用した後、ドラマの核と残った選択を再設計する。
6. NPCの判断や負担を、その後の行為・提案・関係へ接続する。
7. 分岐が約束した違いを、経路上の体験と合流後の描写へ対応させる。
8. 失敗を終わりにするか、次の判断へ進めるかを作品の狙いから決める。
9. 作品群では構造だけでなく、欲望、語り口、人物の応答、感情の着地点も比較する。

「必須」は、その作品の行為・判断・断定・中心的な体験を支える範囲に適用します。全人物の生涯、全施設の工学計算、全世界の法体系、全場面の強い対立は要求しません。不要な項目は理由付きで適用外にできます。成立に必要な未定義条件を、適用外と呼んではいけません。

契約は作者が矛盾と不足を見つけるために使います。読者にすべての承認・照合・記録を順番に体験させる義務はありません。成立条件が既にそろった日常の手続は圧縮し、人物が判断し、相手が応じ、見え方が変わる箇所へ本文の長さを使います。

すべての選択の有利さをそろえること、成功に罰を付けること、全NPCに拒絶や裏切りをさせること、全作品を悲劇・謎解き・どんでん返しにすることは要求しません。全面的な成功、容易な工夫、静かな会話、素直な協力も、その作品が実現する体験として設計できます。

# 1. 継承する五層と物語の軸

## 1.1 五層

Worldは、固定された過去、現在の実体、場所、資源、法則、制度、出来事を扱います。人物の証言や作者の説明文そのものを世界の正本にはしません。

Agentは、人物ごとの知識、誤認、信念、目的、価値、感情、企み、資源、判断を扱います。本人が知り得ない真相から、その人物の行動を選ばせません。

Narrativeは、何をどの順番・視点・粒度・呼称で提示するかを扱います。見せ方を変えるために、確定した過去を後から変えません。

Audienceは、読者に生じ得る疑問、期待、仮説、誤読、早期理解を扱う作者用の層です。現実のプレイヤーの内心を正確に取得できるとは仮定しません。

Transformation / Revealは、世界、人物、関係、提示、受け手の前提、開示の仕方を変える操作を扱います。誰が何をしたかの再構成と、その行為を何として読むかの再解釈を区別します。

## 1.2 抽象度・粒度・Arc

StoryWorld → Plot → Scenario → Narrative → Textは具体化の系列です。実行JSONは、その全体の代わりにはなりません。

Beat → Scene → Sequence → Episode → Workは構造の粒度です。表示ノードやゲームブックの節は、Sceneと一対一である必要はありません。

Arcは、人物、関係、謎、政治、主題などにまたがる変化です。分岐図の階層とは分けて追跡します。全作品へ同じ謎解きやどんでん返しを課しません。

## 1.3 ドラマの核

Dramatic Kernelには、表面課題、誰の何が懸かっているか、認識の差、プレイヤーが動かせる部分、結末へ持ち越す問いを記します。要求の両立不能を中心にする作品では、何と何が、どの条件で両立しないかを加えます。発見、熟達、喜劇、交流を中心にする作品へ、無理に犠牲を付けません。

Conflictは敵の存在ではなく、複数の要求がそのままでは両立しない関係です。事情を説明しただけで利害が消えるなら、その説明がなぜ従来の判断を変えるかを示します。第三の解決も、協力・技術・資源・制度上の手段などの成立根拠を必要とします。

教訓や悲哀は、必ず誰かを死なせることや、成功に罰を付けることではありません。守ったもの、引き受けたもの、分からないまま残ったものが、人物の振る舞いへ現れることを重視します。

## 1.4 体験の焦点と、実際の経路

Dramatic Kernelと合わせて、読者が主に何をする作品か、どの場面でその体験が生じるか、最後に何を見届けるかを短く記します。観察をつなぐ、誰かを信じる、順番を工夫する、約束を引き受ける、相手に任せる、掛合いを楽しむなど、作品に即した動詞で書きます。「感動させる」「深いテーマを描く」だけでは場面を設計できません。

これは読者の感情を測定する仕様でも、一作品を一種類の感情へ閉じ込める規則でもありません。意図した体験を支える本文の証拠を探すための焦点です。関係の変化を狙うなら、誰のどの言葉・動き・選び直しでそれが現れるかを示します。

「確かな成果を捨てる賭け」「取り返せない犠牲」「どちらかしか守れない」と提示する場合は、その危険・喪失・両立不能を生む条件を、到達可能な経路で確かめます。直後の既知の手順で同じ成果を無条件に回復できるなら、取り返せない犠牲とは呼びません。

人物が結果を恐れること、読者に先が見えないこと、世界内に失敗条件があることは別です。主観的な不安は、その人物の取得情報と経験に基づいて描けます。作者の客観説明まで、存在しない危険を断定しません。

一つの方法が明らかに有利でも、それを発見し、実行し、誰かと共有する体験は成立します。核が現実の経路と合わなくなった場合は、核や描き方を改める方法も選べます。葛藤を保つためだけの事故、隠れた費用、不自然な禁止を追加しません。

# 2. 設定・命題・根拠の正本

## 2.1 過去、現在、未来を分ける

開始以前の履歴と、開始時点の状態を分けます。固定過去の最終結果と初期状態が一致し、過去の出来事がプレイ開始時に二重実行されないことを検査します。

開始後の履歴は、実際の行為、人物の判断、法則、保存可能な判定結果から生じます。開始時に真相候補を抽選する作品では、抽選時点と以後固定する事実を宣言します。推理が当たったから真相を変更することは認めません。

「あの時は支道にいた」は、救出後も真であり得ます。「いま支道にいる」は現在地を参照します。未実行の救助は予定であり、帰還済みの事実ではありません。

## 2.2 設定の出典・採用・時間範囲

重要な設定はFact Recordとして、ID、命題、出典、採用状態、適用する作品・地域・人物・時期、固定過去か現在値か法則か、依存する設定、影響する行動・提示・結末を持ちます。

出典の種類は、既存の採用済み設定、観測記録、人物の証言、推論、今回の創作上の補足を区別します。作者が採用した世界の真実と、人物が真実だと主張しているだけの内容も区別します。

採用状態は採用済み、提案中、未解決、廃止です。今回新しく決めた前提は創作上の補足として出典を残します。ユーザーから認められた制作範囲内の通常の補足は作者が決められますが、既存の固定条件に反する改変を補足と呼んではいけません。

q001の新しい二瓶規則は、該当結末で成立する制度変更です。全経路の開始時から存在する規則へ昇格させません。地域限定の慣習を、他地域にも自動適用しません。

## 2.3 根拠を結ぶ関係

重要な行為・推論・合意・結果・描写は、根拠となるIDを参照します。関係の種類として、原因、必要条件、人物にとっての動機、制度上の許可、証拠による支持、結果の確認、提示による再解釈を分けます。

「許されている」は実行した証拠ではありません。「実行したい」は実行できる条件ではありません。「そう信じた」は世界で真である証拠ではありません。これらを一種類の因果の矢印へ潰しません。

各重要断定には、根拠の集合、そこから断定へ進める理由、適用条件、残る反証・別解、確認状態を持たせます。必要条件と十分条件、ANDとORを明示します。「結果が起こると設定したから、その結果が起こる」は作用機構の説明になりません。

根拠の連鎖は、出典付きの採用設定、適用範囲を定めた創作法則、該当する観測・試験などで止められます。世界の全法則を無限に証明する必要はありません。ただし、根拠を止めた前提と、そこから推論した結論を混ぜません。

相互依存する運用や循環は、時間と維持条件を持つ仕組みとして許容します。結論Aを結論Bで、BをAだけで証明する循環は根拠不足です。

# 3. 通常運用と依頼成立：Situation Contract

## 3.1 必須項目

Situation Contractには、通常の目的、担当者と役割、人数・交代・連絡の運用、使う資源、正常に終わったと判断する条件、今回崩れた箇所、崩れたきっかけ、発見時点、依頼時点まで放置された理由を記します。

続けて、依頼人が知っていること、表向きに頼むこと、私的に望むこと、自力・通常の担当者・上位組織で処理できない理由、プレイヤーへ依頼できる立場、依頼の終了条件を結び付けます。

役職名には、実際にする仕事を一文で添えます。正式な担当、見習い、同行者、所有者、管理者、代理人を区別します。名称が魅力的でも、その人物の権限や業務内容を名称だけから推測させません。

## 3.2 検査と適用例

通常なら何が起きるかを再生し、そのどの条件が今回は成立しなかったかを確認します。「いつもこうしている」だけでは、事故が今回起きた理由になりません。蓄積、規模の変化、偶発的な故障、誤判断など、該当する差を置きます。

q001では、一経路を一人で巡灯する通常業務と、新人教育のための同行を区別します。リネが同行を知ることと、正式な当直人数に新人を数えることは別です。新人を帰還確認の対象から消す根拠にはなりません。

q020では、王という通称の説明に加えて、本来の交代運用、途絶えた理由、その後も持ち場を離れない理由が必要です。強い責任感は説明になり得ますが、その偏りが行動や過去から読み取れるようにします。

# 4. 原因と結果の作用機構：Mechanism Contract

## 4.1 必須項目

Mechanism Contractには、対象と範囲、入力・出力、作用の順序または接続、成立条件、処理能力・閾値、所要時間、増減する資源、止まる条件、介入によって変わる箇所、変わらず残る箇所を記します。

物理現象、魔法、生態、経済的な連鎖など、その作品で結末の根拠になる仕組みに適用します。普通の扉を開けるたびに詳細計算は不要です。逆流、増殖、呪いの移動など、常識だけでは結果を一意に補えない仕組みを優先します。

創作法則には適用対象、発動条件、費用、限界、例外を定めます。魔法だから成立する、当地の慣習だから従う、とだけ書いて任意の結果を許しません。現実の法則に依存し、その正しさが結末を左右する場合は、必要な範囲を資料で確認するか、創作法則としての変更を明示します。

## 4.2 数量・時間・介入の検査

保存量は、開始量に発生・流入を加え、消費・破壊・流出を引いた量として説明します。移動しただけで増えないこと、時間を要する変化が瞬時に完成しないこと、試験と本運用の条件が対応することを確認します。

q003では、宿屋の排水がどの経路へ流れ、どの処理能力を超え、どこへ逆流し、浮子が何を検知するかを分けます。鐘を止める介入は警報へ作用し、逆流そのものを除去しません。

放水の時間分散は、放水総量や購入水量の削減を必ずしも意味しません。水売りの減収を結末に含めるなら、実際の使用量・購入量を減らす運用まで根拠に含めます。ここで示すのは因果検査の要求であり、本書への記入で個別クエストを変更したことにはなりません。

一度の試験で確認できる範囲と、長期運用で確認すべき範囲を区別します。「一晩は危険線を越えなかった」から、あらゆる豪雨でも安全と断定しません。

# 5. 人物の判断と目的の変化

## 5.1 Agent CardとPlan Card

Agent Cardには、社会的な立場、表向きと私的な目的、価値、恐れ、守りたい自己像、知識・信念と情報源、使える資源、越えない一線、判断の偏り、代案を持たせます。本人の資源欄は現在の所持・能力の正本を参照します。

主要な振る舞いには、観察される行為、本人にとっての理由、他者からの見え方、後に読み直される意味を記します。すべての仕草を伏線にせず、生活感や余白も残します。

Plan Cardには、所有者、望む状態、信じている前提、他者やプレイヤーへの予測、表向きの提案、隠した利害、資源、見える兆候、妨害されたときの反応、代案、失敗の代価を置きます。企みを見抜かれた人物にも撤回・拒否・逆提案・責任転嫁などの次の判断を与えます。

## 5.2 Goal Transition Contract

目的が新しく生じる、優先順位が変わる、放棄される場面には、人物、変更前の目的と優先順、きっかけとなる出来事、本人が取得した情報、本人の解釈、変化を支える価値や感情、変更後の目的、維持する条件、対応する行動を定義します。

目的を変えるのは新情報だけではありません。疲労、喪失、関係の変化、約束、羞恥、時間切れも理由になり得ます。ただし、どの出来事で何が変わったかを示します。作者が結末に必要だと気付いたことは、人物が目的を変える理由になりません。

当初の主目的、副目的、条件付きの希望、他人から課された目的を分けます。目的が競合したときの優先順や越えない条件を保持します。人物が合理的な最適化をしない場合も、その人物にとっての理由を置きます。

## 5.3 q005への適用

トトの当初の主目的は、排水の詰まりを除いて工房を再開することです。冷水で菌床の増殖を抑えられると知り、保存の可能性を見いだした後に、「食用にできるなら残したい」という副目的が生じます。

保存できる可能性を知ったことは、食用として安全だと知ったことではありません。排水の回復、菌床の保存、糖液の食用確認は別の達成です。

副目的を聞いていない経路でも、焼却で詰まりを解消する選択は成立し得ます。その経路の主人公が、聞いていない保存希望を裏切ったと断定してはいけません。人物の希望がプレイ中に成立した時点と、作者が用意した潜在的な可能性を分けます。

## 5.4 NPCの判断が、次の展開へ返ってくること

主要人物の目的や価値を設定欄へ書いただけでは、その人物の能動性が本文に現れたとは判定しません。本人が受け取った出来事、解釈、選んだ返事や行為、それによって変わる相手の判断・選択可能性・関係・負担を、必要な場面でつなぎます。

返ってくる反応は拒絶に限りません。条件を示す、別の方法を提案する、自分から役割を取る、引き受けた仕事を進める、相手を待つ、以前の言葉を言い直すことも含みます。主要な判断を主人公の選択の復唱だけで済ませた場合は、本人がそう決めた意味を見直します。

同意は、負担や以後の希望が消えることを意味しません。予定を変えた、資源を使った、約束を信じたなど、後の判断に関わる差は方針転換と合流の後にも保持します。本人が納得して負担を引き受け続けることは可能です。その理由や次の行為が必要な場面では、実際の本文に現れるようにします。

全NPCの独立した副筋、拒否分岐、数値化した好感度は不要です。一言や仕草で十分な差はその規模で表し、単なる背景人物へ主要人物と同じ設計量を課しません。

# 6. 制度の効力と例外：Institution Contract

## 6.1 必須項目

Institution Contractには、地域と適用時期、制度の目的、権利・義務・資格の対象、通常の手続、効力を発生させる行為、判断権者、必要な証明、記録と原本の役割、執行者、異議申立て、欠席・紛失・代理・不正の場合の扱いを記します。物語で使わない例外を網羅する必要はありません。

正式な制度、地域の慣習、当事者間の契約、事実上の力関係、本人がそう思い込んでいる規則を区別します。慣習違反が、直ちに法的な無効や処罰になるとは限りません。

制度が公正である必要はありません。不公正な制度も設計できます。その場合は、何を根拠に誰が不利益を課せるのか、対抗する手段があるのか、それを利用できない事情は何かを一貫させます。

## 6.2 行為・証明・効力・執行を分ける

q004では、通行証の紙、資格、登録名義、留置、仮証発行を別の対象として扱います。紙を二枚に複製しても資格は二つになりません。留置を解く権限と、正式資格を認める権限が同じとは限りません。

q018では、金を用意する、支払う、役人が確認する、原本を失効させる、債務が終了する、終了が争われる、という違いを扱います。債権者の欠席で何が妨げられ、何は有効なままかを決めずに、都合に応じて効力を切り替えません。

不正者が再請求を主張できることと、その請求が有効と裁定され、実際に取り立てられることは別です。虚偽の主張だけで赤札や差押えまで描くなら、それを実行する者が何を信じ、どの権限で動いたかをつなぎます。

新しい役所や例外規則を足す場合は、その手段が以前から使えなかった理由と、他の経路へ与える影響を確認します。必須欄を埋めるためだけに行政機構を増やしません。

# 7. 証拠と結論：Inference Contract

## 7.1 必須項目

Inference Contractには、判断する人物、観測または取得した証拠、その出所と取得時点、証拠の信頼性と保管経緯、結論、証拠から結論へ進む論拠、補助前提、競合する説明、反証条件、断定の範囲、未解決事項を記します。

結論の扱いは、可能性、仮説、裏付けあり、当該制度の判断基準を充足、宣言した前提内で確定、といった区別を持ちます。これらは常に一列の強弱になるとは限りません。公的な裁定が出ても、世界の真実と一致する保証はありません。

情報源に接触したという記録は、その情報源が正しく、十分であることの保証ではありません。複数の証拠が同じ伝聞に由来するなら、独立した裏付けとして重複計上しません。

## 7.2 不在と否定の区別

記録にないことから出来事がなかったと断定するには、その記録が対象期間・対象行為を漏れなく含む理由と、欠落・改竄の扱いが必要です。

q006の石入りの箱と入金記録の欠落は、未払いの偽装を疑う材料になります。しかし、それだけで投棄者や全履歴まで一意に確定するとは限りません。断定を保つなら、記録の完全性、証言、本人の説明、金銭の履歴など、残る別解を区別する根拠を整えます。整わなければ結論の表現を狭めます。

q019で重量差を観測したことは、契約上の給金不足を計算したことではありません。当時の単価、計量・換算条件、記録が残る期間を照合し、確認できた範囲だけを不足額とします。

## 7.3 推理の自由と検証

証拠が足りなくても疑いを述べたり、仮説を試したりできます。その入力を、公的に立証した状態と同一視しません。

必要な証拠の代替経路をOR、その経路内で同時に必要な証拠をANDとして定義します。別々のプレイでしか取得できない証拠を合算しません。

検査では、同じ証拠と両立する別の説明を少なくとも関連範囲で探します。残る別解が結末の断定を覆すなら、追加調査、制度上の限定した裁定、断定の弱化のいずれかへ改稿します。証拠名に「決定的」と付けるだけでは合格しません。

# 8. 合意から実行まで：Resolution Contract

## 8.1 必須項目

Resolution Contractには、解決したい問題、変更する仕組み、提案者、影響を受ける当事者、判断権者、同意が必要な人物、その受諾・拒否条件、交渉で変わる条件、費用、資材、人手、技術、所要時間、実行者、確認方法、維持担当、残余の問題を記します。

解決段階は、提案、実現可能性の確認、必要な同意または適法な決定、資源の確保、実行、結果確認、必要なら維持運用を区別します。段階の順は行為に応じた依存関係で決め、一律の儀式にしません。

物理的に強行する行為は、相手の同意なしでも実行可能な場合があります。その場合は強行として権限・抵抗・危険・後の解釈を扱います。「必要な同意が成立した」と偽って記録しません。

## 8.2 なぜ相手が応じたか

不正を指摘された人物が応じる理由は、事実の理解だけとは限りません。証拠を公表される不利益、執行力、代替案による損失軽減、守りたい関係、以前の約束などを具体化します。相手が応じない経路や、提案条件が満たされない場合の扱いも置きます。

承諾を得る選択肢は、必要条件がそろえば承諾される行為として圧縮できます。ただし、プレイヤーの希望とNPCの判断を無条件に同一化しません。相手の判断根拠が不足するなら、承諾を試みる段階として扱います。

q020で費用と補修担当の争いが交代停止の原因なら、補修図の完成だけで工事完了へ進めません。誰が費用と作業を引き受けたかを示すか、その争いを解く交渉を入れるか、結末を計画・一時交代の段階に限定します。採用する方法は個別原稿で決めます。

## 8.3 圧縮と完了の条件

短いシナリオでは、成立条件のそろった一連の作業を一場面・一段落へ圧縮して構いません。画面外の行為にも実行者、資源、時間、出来事と結果が必要です。必須条件が不明なまま「その後すべて解決した」とは書きません。

試験完了、制度の承認、実際の救助、名簿への記載は別の出来事です。名簿が誤っている物語も作れますが、記載だけで世界内の帰還を成立させません。

継続的な清掃や当番で維持する解決には、担当者の承諾、必要資源、頻度、途絶えた場合の影響を定めます。「再発しなかった」と将来を断定する場合は、その期間の運用と結果を後日談として確定します。

# 9. 代案と非介入：Counterfactual Review

## 9.1 比較する基準

事件発生前に通常の手続が働いた場合、依頼時点でプレイヤーが介入しない場合、重要な情報を早く知らせた場合、目につく簡単な代案を試した場合を比較します。

代案ごとに、誰がいつ思い付けるか、何を知っていれば考えられるか、物理的・制度的な可否、資源・時間・危険、本人が選ぶまたは選ばない理由、予想される帰結を記します。

想像できる全行動を実装する必要はありません。作品がプレイヤーへ約束した介入範囲に照らし、明白な代案を採用する、選べない理由を示す、物語の範囲外として明示する、いずれかを選びます。単に作者の用意したボタンがないことを、世界内で不可能な理由にしません。

## 9.2 修正を要する場合

「上司へ連絡する」「別の出口へ回る」「依頼人本人が回収する」「何もしない」が低負担で問題を解くなら、その代案を採用するか、人物や状況に根差す制約を補います。元の筋を守るために、代案の数だけ場当たり的な禁止規則を追加しません。

出口の一つが閉じたことだけでは、別の有効な出口も失われたとはいえません。例えばq010を点検するなら、閉門後の通常経路と縦坑の状態を別に確認します。未帰還と、以後の救助が不可能であることも分けます。

時間制限を代案の不採用理由に使うなら、その時計と時間消費を定義します。実行上は待ち続けられる設計で、選択を正当化するときだけ迫る死を持ち出しません。演出上の緊迫感と、判定に使う期限を区別します。

人物の誤認や恐怖によって合理的な代案が選ばれないことは許容します。偏りに先行する根拠があり、別の情報や介入で判断が変わり得るかを確認します。

## 9.3 有効な別解を採用した後の戻り先

成立する代案を追加したら、行動と終了条件に加えて、ドラマの核、従来の手段を選ぶ理由、以後の情報提示へ戻って点検します。代案の論理的な妥当性だけで、この改稿を完了しません。

代案で中心課題が解けた場合は、その成功を認めて適切に終える、解けた後に残る具体的な問いへ進む、発見や実行を中心とする作品に組み直す、といった方法を選べます。新しい問題を必ず発生させる義務はありません。解決済みの危機を危機として語り続けないことが要件です。

待機や委任に比べて、自力で動く理由が技能の習得、仕事上の関心、関係、本人のこだわりにあるなら、その根拠を当該経路で示します。自力の筋へ戻すために、専門家を理由なく無能にしたり、安全な待機を突然危険にしたりしません。

代案、機構、期限、人物の目的、結末を変更したときは、それらを参照する「難しい選択」「大きな代償」等の説明も再検査します。構造検査に通った変更であっても、物語の中心を弱める場合があります。

# 10. 選択時点の理由：Choice Contractの拡張

## 10.1 読者への約束と世界への行為

Choice Contractには、行為としての選択ラベル、主人公が発想できる根拠、プレイヤーへ提示済みの情報、見えている目的、期待できる利益、時間・費用・危険、不可逆な負担、不確実性、実際の作用、他者の解釈、後へ残る差を記します。

表示してよい条件、主人公の知識条件、実行可能性、結果の成立条件を分けます。同じ意味の条件は共通の述語を参照します。「慰める」と選んだのに重大な告発を実行するなど、入力に含まれない行為を追加しません。

プレイヤーだけが幕間で秘密を見た場合、主人公がその秘密を事実として引用できるとは限りません。疑いを試す、別の根拠から質問する、証拠を求める、といった介入を区別します。

## 10.2 選びうる理由を、本文からも確かめる

各重要選択について、なぜ今それを選びうるかを記します。期待できる利益、避けたい損失、特定人物への義理、約束、見栄、恐れ、確実性、好奇心などを、その人物と局面に結び付けます。「早いから」「慎重だから」という名前だけでは、本文で成立している動機の証拠になりません。

主人公の理由には、当該経路で提示済みの出来事・言葉・振る舞いへの参照を付けます。作者用のwhy欄を隠して読み、何を望んでその選択をするのか、負担がある場合は何と比べているのかが読み取れるか確認します。理由を全部説明する必要はありませんが、中心的な決断を作者しか知らない前提に依存させません。

小さな便益のために永久的な大損失を選ばせるなら、損失を小さく偽るのでなく、その便益が本人にとって特別な理由、本人の判断の偏り、または意図的な自暴自棄などを具体化します。外から見て合理的であることや、全選択肢の期待値が等しいことは要求しません。

自由に演じる主人公では、特定の感情を本人の確定事実として押し付けず、プレイヤーが選べる態度や目的を本文とラベルで成立させます。固定された主人公の既知の経験、プレイヤーの推測、作者の真相は混同しません。

誤った選択、無謀な選択、悪意ある選択も扱えます。その意図や当時の見通しを、作者だけが知る結末から逆算して責めません。q019で原因を調べず秤を交換する選択を残すなら、故障と考える根拠や交換の利点を確かめます。正常と確認済みなら、それでも交換する理由が別に必要です。

## 10.3 分岐の意味と作品群の多様性

世界、知識、関係、責任、解釈のどこが変わり、以後どこへ残るかを定めます。態度を表す小さな選択も残せますが、実質のない差を重大な結末分岐とは呼びません。

informed、contract、compromiseは特定作品の結末IDであり、本モデルの必須三分類ではありません。「調査するほど善い」「依頼どおりなら愚か」「妥協は必ず先送り」という対応を固定しません。契約の履行が妥当な解決になる作品、真相を知っても解決できない作品、関係の変化で終わる作品も扱います。

複数作品を生成するときは、事件の仕組み、人物の要求、介入方法、情報の配置、分岐と合流、結末に残る差を比較します。名詞や舞台を変えただけで同じ構造が反復していないかを検査します。

## 10.4 分岐が担う違いと、実際の回収

分岐の役割は、世界の帰結、次にできる行為、判断に使える知識、関係や責任、出来事の解釈、局所的な態度や情景のどこが変わるかで記述できます。分類を選ぶことが目的ではなく、どの本文・行為でその違いを経験できるかを結びます。既存のChoice、Scene、意味の参照で足りる場合は、新しい台帳を増やしません。

大きな決断として提示した枝には、その重みに対応する違いを置きます。調査が次の判断に役立つと期待させるなら、何をどう使えるかを確認します。情景を味わう枝や、口調を選ぶ枝は、その場の体験として成立して構いません。すべてを恒久フラグや別エンディングにしません。

合流では、結果が同じでも、誰と何を交わし、何を目撃したかを点検します。その違いが後の感情や行為の根拠になるなら、本文変種、会話、動作、結末の像へ引き継ぎます。未経験の会話を共通の感動の前提にしません。後で使わない局所的な違いは、無理に保存しません。

## 10.5 選択ラベルの仕事

選択ラベルは、選ぶ行為、必要なら意図と既知の重大な負担を示します。「愚かにも」「正しく」「安全に成功する」等の作者の採点を、未確定の結果の代わりに付けません。相手に頼むことと、相手が承諾して実行を終えることも区別します。

危険や不可逆な代償を隠す必要はありません。既知の危険は具体的に伝えます。一方、失敗へ誘導するために不自然に愚かなラベルを置いたり、謎を解く選択肢だけが正解の理由を全部説明したりしていないかを確認します。

結果が確定している行為、合意済みの日常作業、結果を選ぶこと自体が主題である選択では、結果の見通しを明記できます。全選択を不確実にする規則にはしません。

# 11. 作者向け制約と、読者へ伝える情報

## 11.1 AI向け注釈

個別の事実項には、次の注釈を付けられます。

「以下の事実は世界設定上の整合性を保つための制約です。これらを台詞、説明、選択肢としてシナリオへ直接反映する必要はありません。ただし、生成・改稿時に矛盾させてはいけません。」

この注釈は、制約を実行上も無視してよいという意味ではありません。また、事実項を機械的に台詞へ挿入する指示でもありません。

## 11.2 Presentation Necessity Contract

重要な設定には、作者だけが保持する背景、選択を理解するための前提、推理に用いる手掛かり、後で意味を変える情報という提示上の用途を付けます。複数の用途を持たせても構いません。

選択の理解に必要な情報には、誰へ、どの判断までに、どの意味が伝わればよいか、説明・物・行為・会話など何で伝えるか、未提示の経路でどう扱うかを定義します。事実を全文説明することを要求せず、必要な意味が伝わることを求めます。

例えば当直の人数規則を説明しなくても、新人が教育のために同行したと分かれば人物関係を理解できる場合があります。作者向け注釈を読まないと何を頼まれているか分からない状態は、本文の提示不足です。

## 11.3 追加設定の影響

設定の追加・変更時には、依存する行動、推論、制度、結末、他クエストをたどって再検査します。廃止した設定を前提とする本文や、改稿前の検査結果を残しません。

「矛盾しない」と「原因や判断の説明として十分である」は別です。両方を検査します。追加設定で元の問題を説明できても、より簡単な別解が生じた場合は再評価します。

条件と関係の把握に使わず、世界の雰囲気を作る背景も保持できます。すべてをフラグ化したり、使わない設定を一律に削ったりしません。一方、未採用の補足案を世界観wikiの確定事項へ自動登録しません。

## 11.4 作者の検査説明が本文へ漏れていないか

「見ていないことを書き加えない」「合意しただけで実行済みにはしない」「箱が二倍にはならない」といった、作者の誤記を防ぐ注意は、まず作者用の根拠へ置きます。それを本文に出す場合は、作中の誰の誤解や判断に応じているか、どの感情・声・情景を生むかを確かめます。

本文を読んで、誰もしていない勘違いを語り手が訂正し続けている、現物の受渡しですでに分かる数量をさらに弁明している、結末が未実施事項の監査報告で終わっている場合は、該当文を作者資料へ戻すか、人物の行為・必要な描写へ書き換えます。

判定は、その説明を除いたときに、選択の理解、公平さ、事実関係、人物の声、文章の調子の何が失われるかで行います。必要なものが失われるなら残し、もっと自然に伝わる方法があれば改めます。説明文・否定文・直接的な感情表現そのものを禁止しません。作中の否認、皮肉、ためらい、誤解を解く会話は有効な表現です。

証明書類が物語の中心にある作品は書類を描けます。ただし、各作品を一律に「確認、承諾、署名、限定報告」の順へ並べる必要はありません。すべての文に実用上の役割を要求せず、生活感、間、可笑しさ、音や手触りも残します。

# 12. 実体・所在・身体・物品・状態

## 12.1 実体の同一性

会話、移動、救助、受け渡し、判断、証言に関わる対象へ固定IDを与えます。Entityには、種別、呼称、役割、関係、出典、確定度を持たせます。本名がなくてもIDを定義できます。

同じ老人への「灯番」「あの人」という呼称は同じ実体を参照します。偽名・変装では世界の実体と観測者の同定を分けます。故人、回想中の人物、現在生存している人物を混ぜません。

集団は一つの実体にまとめられますが、一部だけ別行動するなら、個体または分遣隊と構成員数を定義します。背景人物が行為や証拠の担い手になった時点で、検査できる対象として登録します。

## 12.2 所在・接続・身体能力

場所はID、包含関係、接続、移動手段、通行条件、必要な時間を持ちます。同じ入口という呼称でも、地下入口と地上の詰所は必要に応じて分けます。広い同一空間では、接触や会話の範囲も必要な粒度で定義します。

実体の直接の所在は、場所・容器・保持者などの一つを正本として参照します。包含の循環を禁止し、保持関係をたどって実効位置を求めます。物品の運搬中は保持者に従い、降ろすと所在を更新します。

身体は、生存、意識、歩行、介助があれば移動可能か、発話可能かなど、行為で使う軸を定義します。既存のHPや状態異常が正本ならそれを参照します。会話場面へ入っただけで回復したことにしません。

遠隔会話、瞬間移動、分身、夢を扱う場合も、参加形態と法則を定義します。整合検査を一括無効にする例外を設けません。

## 12.3 所持・所有・数量

物理的な保持と所有権、容器と内容物、複製できる情報と固有の原本を分けます。貸与で保持者だけが変わる場合と、贈与で所有も変わる場合を区別します。

数量には単位、値域、容量、分割可能性を定めます。分配は出し手の減少と受け手の増加を対応させ、消費・生成・破壊には出来事を持たせます。破壊された物の履歴を、最初から存在しなかったことへ書き換えません。

## 12.4 状態台帳

State Recordには、IDまたはpath、意味、型、定義域、単位、初期値、正本か派生値か、許可された更新者、参照する行動と提示、寿命、可視範囲、不変条件を定義します。初期値は実際の初期化処理まで対応させます。

型はboolean、有限enum、範囲付き数値、実体参照、集合などから選びます。参照先の存在と種別も検査します。正本は宣言した行動、初期化、明示した移行からだけ更新し、派生値は読み取り専用にします。

世界の事実、人物の認識、提示履歴、関係・約束、客観的な戦績、進行位置は別の意味です。既存の所持品や能力から計算できる現在値を別フラグへ重複保存しません。現在の同行と、以前に同行へ同意した履歴も区別します。

不明は、作者未決定、世界では確定しているが人物には未知、旧セーブ等から復元不能、の三種類を分けます。行為の成否に必要な作者未決定値を、都合のよい値で埋めて完成扱いにしません。候補を許す場合は、許した候補ごとの条件を検査します。

# 13. 行動・遷移・失敗・確定

## 13.1 Action Contract

行動には、ID、主体、対象、行為種別、動機または目的遷移への参照、物理・資源・知識・制度上の前提、所要時間、成功効果、失敗の種類ごとの効果、観測者、出来事、再試行方針、作用機構または制度への参照を与えます。

意思決定の理由と物理的な成功条件は別に検査します。閉じた扉を開いていると信じて進もうとすることはあり得ますが、信念だけで閉じた扉を通過させません。

移動は対象と通る接続を持ち、待機している無関係な人物を動かしません。手渡しは現在の保持者、接触可能性、受け手の能力と必要な同意を検査します。観測は情報源との接触と、観測から得られる命題の範囲を確認します。

## 13.2 原子性と中断

不可分な行為は、前提検査、変更案、変更後の不変条件、状態と出来事の一括確定、結果提示の順に処理します。表示時だけでなく選択確定時にも前提を再検査します。

戦闘や移動の途中で失敗・中断・介入があるなら、保存可能な中間段階を定義します。実際に消費した薬や戦闘結果を、救助が未完了だからと一律に巻き戻しません。救助の成功効果は成立後にだけ確定します。

行動定義IDと行動インスタンスIDを分けます。再送・再読・セーブ再開で同じ取引や報酬を二重確定せず、繰り返し可能な取引まで一生に一回へ制限しません。

原子的な処理をアダプターが保証できない場合は、明示した処理段階と再開・補償を実装するか、未対応とします。成功文を表示することを状態更新の代わりにしません。

## 13.3 Transition Contract

遷移には、出発ノード、到着ノード、発火主体、条件、参照行動、成功先と失敗先、反復方針を持たせます。状態効果を行動と遷移の双方へ手で重複記述しません。

意図した失敗終端は、その帰結と再開方針を定義します。実行可能な選択が意図せずなくなる状態を、物語上の悲劇とは呼びません。

## 13.4 失敗の後を、次の判断にするか、結末にするか

主要な失敗では、何ができなくなり、何が分かり、誰が負担を負い、当初の目的をどう変えるかを確認します。次の判断を中心にする作品では、救援を呼ぶ、目的を絞る、助けを受ける、責任を引き受ける、別の人物へ任せるなど、変わった状況に対応する選択を設計できます。失敗した事実は消しません。

短い失敗終端も有効です。警告済みの限界を越えた結果、短編の一つの帰結、再挑戦を含む形式など、役割を明らかにします。全失敗を救済すること、必ず長い挽回経路を付けること、成功と同じ報酬へ戻すことは要求しません。

差戻しが必要なのは、作品が失敗後の判断を中心に約束したのに即時終了だけで済ませる場合、失敗の影響を合流で消す場合、または意図しない行き止まりを結末として扱う場合です。単に失敗後が短いという理由だけでは不合格にしません。

# 14. Scene・Beat・情報開示・描写

## 14.1 Sceneと合流

Sceneには、ドラマ上の問い、参加者それぞれの要求、言われないこと、プレイヤーが動かせる部分、失われ得るもの、時間、場所、視点、参加形態、入口条件、行動、本文変種、出口条件、後へ残る差を持たせます。

現地同席、遠隔通信、回想、引用、話題としての言及を区別します。入口条件は検査であり、それに合わせて人物を自動移動・回復させる命令ではありません。

Beatでは、世界、認識、目的、関係、選択可能性、読者の期待の何が変わるかを捉えます。すべての文へ複数の役割を強制しません。

合流では、到達する各状態で本文と選択が成立するかを確認します。排他的な本文条件の重複と欠落を検査し、既に救出した人物、消費した物、交わした約束を初期状態へ戻しません。再読、再訪、時間経過を伴う再訪を区別します。

## 14.2 四つの情報所在とReveal Contract

作者の真実、人物が取得した内容、プレイヤーに提示済みの内容、プレイヤーが実際に理解した内容は別です。取得した証言の内容と、それを真実だと信じることも分けます。

Revealには、明かす事実、前後で変わる解釈、伏線、競合する説明、必要な証拠、開示条件、効果的な局面、遅くとも必要な局面、早期発見時の応答、取り逃した経路での扱い、読み直される行為、開示後にも残る対立を持たせます。

手掛かりと断定の間はInference Contractで支えます。開示のために固定過去を変更せず、早期正解者へ理由なく指定の手掛かり巡回を強制しません。真相が分かってから交渉や決断が始まる構造も、最後の一文で意味が変わる構造も許容します。

## 14.3 演出とPresentation Assertion

何を見せるか、順序、視点、細かさ、呼称、信頼性を作者が設計します。仕草、触れない品物、台詞と行動のずれ、沈黙、反復、対照、場面の切れ目を、フラグとは別に保持します。

重要な提示単位には、本文、参照実体、命題、時点、話者または視点、断定の種類、成立条件、根拠ID、提示による情報更新を記します。

現在の客観描写は現在状態、過去の説明は該当履歴、証言は発話と伝達、信念は本人の認識、予測は主体と根拠、確定した後日談はそこまで進めた出来事を参照します。嘘の証言を世界の真実との不一致だけでエラーにせず、嘘をつく知識と理由を検査します。

地図に書いた位置は、観測時刻付きの情報です。音の方向しか知らない経路では捜索範囲として記します。人物が後で動いても、地図の記載を自動的な現在位置へ読み替えません。

本文に契約未登録の行為や断定が混入していないかを逆方向にも読み直します。登録した命題だけを検査して本文全体の整合を保証したことにはしません。

## 14.4 公平な情報と、読者が結び付ける部分

推理・工夫・発見を中心にする場面では、観察できる規則と手掛かり、そこから考えられる仮説、選ぶ行為、実行後に分かる結果を区別します。作者は「この場面で読者に残す結び付きは何か」を一文で説明できるようにします。それがなければ、解答を読む場面なのか、結果を選ぶ場面なのか、狙いを改めます。

公平さのために先に必要なのは、行為の意味、主人公が当然知る規則、判断に重大な既知の負担、取り返しのつかない操作を見分ける情報です。謎解きの答え、最適な手順、まだ観測していない結果をすべて事前説明することとは分けます。

冒頭の規則、本文、選択肢だけでなく、節題、挿絵、ヒント、表示中の記録欄、結末名の一覧が答えを先に明かしていないかも点検します。学習用の実演や、知ったうえでの実行を意図するなら、解答を示す形式を選べます。全場面で一部の情報を隠す必要はありません。

不可逆な損失を黙って追加して驚かせること、主人公の職務知識を理由なく伏せること、前提を提示せず当てさせることは、この規則による改善ではありません。早く気付いた読者にも、可能な行動や応答を用意し、真相や世界法則を後から変更しません。

## 14.5 場面の重さと語り口

各場面では、何を判断し、発見し、見届けるかに応じて長さと間を配分します。緩い場面、遊び、沈黙、反復も使えます。すべての場面へ新情報、対立、反転を押し込みません。

人物の役職を替えたときにも同じ口調で同じ確認だけをするなら、その人物の語彙、欲望、言いよどみ、相手への態度、仕事の癖を見直します。全人物へ奇抜な口癖を付ける必要はありません。読者が人物と場の違いを感じ取れる具体的な行為を優先します。

# 15. 戦績・NPCの自律・時計・保存

## 15.1 戦績から人物の判断へ

戦績は実際の戦闘の正本です。その記録を人物が取得した経路、人物の解釈、次の行動を別に設計します。討伐数を勇敢さや正義そのものへ変換しません。

累計、受注後、特定の同行や約束の期間を区別します。累計差分から復元できない同行中の討伐、連勝、行動順は、必要ならその文脈を含む出来事を追加記録します。記録されていない履歴を推測で補いません。

偽の報告や改竄台帳は世界内の文書・証言として持ち、客観的な戦績の正本を改変しません。

## 15.2 時間と画面外の行動

時計の単位、何によって進むか、評価地点、同時刻の完了と締切の優先順、中断中の扱いを宣言します。読む速さや現実の放置時間で、説明なく人物の死を決めません。

NPCは本人の取得情報と計画から判断し、実行は世界の実際の条件で検査します。通知を受けた、出発した、捜索した、対象を発見した、運搬した、という画面外の出来事も、通常の行動契約へ接続します。

競合する行為には順序または競合解決規則を置きます。NPC同士の反応が無限に呼び合わない停止条件も持たせます。汎用AIや全世界シミュレーターは必須ではなく、明示的な有限分岐でも実現できます。

## 15.3 保存・再開

保存には、必要な世界状態、進行ノードと待機位置、認識・提示履歴、時計、保留中の行為、処理済み出来事、予約行動、乱数状態を含めます。同じ保存状態と入力・判定結果から、同じ物語上の結果を再現できるようにします。

旧版から一意に復元できる値には根拠を付けて移行します。曖昧な値は旧経路の継続や明示した再開方針で扱い、新版の成功に便利な値を付与しません。報酬・物品・救助の二重取得と、保存された停止点の取り違えを防ぎます。

# 16. グラフ投影と変形操作

## 16.1 四つのグラフ

因果・動機グラフは、出来事、目的、作用機構、制度、根拠の関係を表します。必要条件、原因、許可、動機、証拠の支持をエッジの種類として分けます。

実行グラフは、場面・行動・判定・更新・合流・終端を表します。検査する実行状態は、ノードと、必要な世界状態・認識・提示履歴・時計・保留行為の組です。

情報・開示グラフは、観測、証言、仮説、推論、提示、Revealの依存関係を表します。証拠のAND・ORと、主人公の取得・読者への提示を区別します。

意味・回収グラフは、仕草、品物、台詞、約束、人物への評価がどこで読み直されるかを表します。感情的な応答を実行条件と混ぜません。

四つは共通IRから投影します。図を別の正本として手直しせず、参照IDから本文と条件へ戻れるようにします。根拠関係も因果・動機または情報グラフの型付き関係として扱い、独立した第五の真実を作りません。

## 16.2 Transformation / Operator

世界への操作は、過去の事件、資源、所有、法則、制度、外部への波及を変えます。人物への操作は、目的の優先順、信念、負い目、共有する価値、許せる手段を変えます。

提示への操作は、結果先行、視点交換、証言順、再訪、名称、台詞と動作の組合せを変えます。受け手・開示への操作は、犯行や保護の理解、成功や責任の読み方を変えます。介入への操作は、証拠を得る問題を、誰にいつ示すかという問題へ変えるなど、プレイヤーの行為の意味を変えます。

各操作に、入力条件、変更箇所、保持する事実、影響する行動・状態・開示・結末、狙う感情、再検査する契約を持たせます。目的の変更はGoal Transition、制度や機構の変更は該当契約へ反映します。作者の改稿とプレイ中の状態更新を区別します。

# 17. 結末と報酬

Ending Contractには、到達条件、終了時に必要な状態、成立した出来事、各人物の目的の帰結、関係と約束、負担を負った者、判明した範囲、残る問題、経路別本文、最後の具体的な像、報酬と一回性、終了後へ保存する差を記します。

契約達成、真相把握、救助、制度上の決着、信用、感情的な和解は別軸です。救助に成功しても原因調査が終わらない場合があり、真相を知っても被害を取り戻せない場合があります。

結末の各重要断定は、必要な状態と出来事に加え、作用機構・推論・制度・合意実行の根拠へ接続します。計画、約束、実施、確認、維持のどこまで成立したかを明記します。結末IDへ到達しただけで全達成を与えません。

報酬はゲーム上の報酬と、世界内で誰が何の条件で払う対価かを分けます。抽象的なゲーム報酬ならその扱いを宣言できます。不正を暴かれた依頼人が支払う設定なら、支払いの理由や保証も必要な範囲で定めます。報酬額を作者の道徳的な正解表示にはしません。

初回確定と再表示を区別し、報酬や制度変更を再発生させません。プレイヤーが経験していない会話や関係を結末の感動の前提にせず、必要なら同じ世界結末でも提示を変えます。

主題は、結末で説明するだけでなく、変わった振る舞いや残された物に表します。説教を除いても何を引き受けたかが伝わるかを読み直します。

## 17.1 結末で見届けるもの

結末では、中心に置いた問いへ、何を選び、何が起こり、誰がどう振る舞ったことで応じたかを確認します。全問題の解決も、必ず明確な教訓を述べることも要求しません。問いを残す場合は、何を見届けたうえで残すのかを具体化します。

最後の像は、成功条件を言い換えるだけでなく、経路で変わった関係や扱い方を表せます。約束を破られた相手の短い返事、他人へ渡した鍵に手を伸ばしかけて下ろす動き、以前と違う呼び方などが候補です。これらを全作品の定型にせず、その作品の人物と出来事から選びます。

何が未確認かを正確に扱うことと、読後の感情を未確認事項の列挙で終えることは別です。作者資料には断定の限界を残し、本文では必要な範囲を伝えたうえで、人物の声、場の変化、残った物などへ着地できます。

# 19. 生成・改稿の手順

## 19.1 入力と体験の焦点

長さ、ジャンル、固定設定、主人公の自由度、介入範囲、対象媒体、使える機能と版を確認します。未指定の通常の補足は、採用した創作前提として区別して進めます。固定条件と矛盾する改変を補足と呼びません。

最初に、誰の何を扱い、読者が何を判断・発見・経験し、最後に何を見届ける作品にするかを短く定めます。指定された場面数・選択数・結末数は制約として扱い、人物や意味を空欄埋めのために作りません。

## 19.2 中心となる場面を仮に書く

主要な判断、出会い、発見、関係の変化が起きる場面と、その後の具体的な反応を短く試作します。何を選ぶのか、なぜその人物がそうするのか、相手がどう応じるのかが本文から読み取れるかを先に確かめます。

試作は成立を保証する完成稿ではありません。世界法則や既存設定に反する効果を採用済みにせず、次の工程で必要条件を整えます。演出上の狙いを確かめてから根拠を整えることで、すべての欄を満たした手続の順を物語へ転写する生成を避けます。

## 19.3 世界・人物・根拠をつなぐ

固定過去、初期状態、通常運用、今回崩れた理由、発見と依頼成立を定めます。人物の知識、価値、欲望、恐れ、企み、代案、目的が変わる出来事をつなぎます。

必要な機構、制度、証拠と推論、同意または強行、資源、実行者、時間、結果確認を定義します。結末からも逆にたどり、達成に必要な根拠が途中にあるか確認します。作品に使わない制度や手続を、契約を埋める目的で増やしません。

## 19.4 代案から核へ戻る

非介入、通常の担当者への連絡、待機、簡単な工夫、早期開示を検討します。有効な代案は認め、それによって中心課題が解ける場合は、核、従来の選択理由、以後の場面を再評価します。

世界法則やNPCの目的を整える過程で新しい別解が生まれた場合も、同じ戻りを行います。元の悲劇や葛藤を維持するための禁止規則、隠れた罰、不自然な無能を足しません。

## 19.5 選択と情報の配置

各重要選択について、提示済み情報から選べる理由、既知の負担、残す推測、行為の実際の効果、相手の反応、後へ残る差を対応させます。主要な決断をwhy欄の一文だけで支えません。

推理や工夫を狙う場面では、読者が結び付ける部分を残します。結果を見通したうえで価値を選ぶ場面では、その見通しを明示できます。作者の採点をラベルへ付けず、重大な既知の負担を隠しません。

## 19.6 状態と、全経路の本文を整える

対象ID、所在、接続、身体、保持、数量、時計、状態台帳、行動の成功・失敗・中断を整えます。合流時の経験差、NPCが引き受けた負担、結末条件を対応させます。

SceneとBeat、視点、語り口、提示順、本文変種、再訪、最後の像を作ります。作者の整合性確認をそのまま地の文へ置かず、必要な事実を行為・会話・物・説明の適切な方法で伝えます。

## 19.7 構造・意味・本文を照合する

構造と状態付き経路を検査し、因果・動機・制度・推論・合意実行を点検します。それに加え、読者が見る順で一つの経路を最後まで読み、作者資料を根拠に補わず、実際に迷う・気付く・見届ける箇所を確認します。対比する重要経路も読み、分岐の違いが本文へ現れているか比較します。

宣言した危険や喪失と、実際の到達可能性が一致するかも照合します。全状態探索、代表経路の本文レビュー、実読者の試読は別の検査として記録します。

## 19.8 原因へ差し戻し、完成させる

問題ごとに、対象版・経路・本文位置、読者にある材料、欠けた根拠または反例、原因となる契約、修正方針を記します。文だけを直すべき問題と、核・人物・機構・分岐から直すべき問題を区別します。

変更した根拠の影響先を再検査します。代案や期限を変更した場合は構造検査だけで止めず、中心の選択へ戻ります。本文の説明を削った場合は、判断に必要な情報まで失っていないか確かめます。

制作範囲内で直せる不備は生成側で修正し、要求された媒体の完成出力まで作ります。固定されたユーザー条件同士の衝突など、作者が決められない事項だけを、完成した部分と具体的な選択点を伴って確認対象にします。未完成の原稿を承認待ちにして、必要な作業を止めません。

# 20. 検査基準・差戻し・完了判定

## 20.1 検査の種類を分ける

構造検査は、型、参照、初期値、更新者、数量、所在、接触、能力、時計、再実行、保存、状態付き経路、本文条件、終了条件を対象にします。

意味の検査は、依頼成立、因果の機構、動機、制度、推論、交渉、代案、選択理由、設定の影響を対象にします。自然文の論理を完全に自動証明できるとは仮定せず、人またはAIによる本文と根拠の照合を含めます。

演出の検査は、人物の固有性、企みへの応答、情報の順序、選択の責任、伏線の読み直し、文章の間、感情的な帰結、作品群の多様性を対象にします。検査主体が同じAIでも、作者用設定を参照する点検と、提示された本文だけを読む点検を分けます。

## 20.2 v1.2から継承する九つの意味検査ID

V12-SITUATION：通常運用、今回の破綻、発見、依頼人の認識、外部へ依頼する理由がつながっていること。役職名を言い換えただけで業務が不明なら差戻します。

V12-MECHANISM：原因・介入・結果が、対象範囲、量、時間、適用条件を通してつながっていること。警報の停止を増水の解消と扱う、時間分散だけで使用総量が減ると扱う場合は差戻します。

V12-GOAL：目的の発生・変更に、その人物へ届いた出来事と判断根拠があること。後から生じる副目的を、受注時からの要求として描いた場合は差戻します。

V12-INSTITUTION：権利・義務・資格の効力、判断権限、証明、執行、当該経路で問題になる例外が整合すること。原本の保持だけで、未定義の失効や処罰を発生させた場合は差戻します。

V12-INFERENCE：取得した証拠が、実際の断定の範囲を支えること。記録欠落や物性の観測から、必要な補助前提なしに犯人・安全・給金不足まで確定した場合は差戻します。

V12-RESOLUTION：解決の同意または強行の条件、資源、実行者、時間、確認、維持が対応すること。提案や試験だけで合意・工事・長期運用を完了させた場合は差戻します。

V12-ALTERNATIVE：非介入と目につく代案を検討し、選べない理由を人物・世界・介入範囲のいずれかで説明できること。有効な別出口を無視して全救助不能と断定する場合は差戻します。

V12-CHOICE：選択時点の情報、見通し、負担、意図と実際の作用が対応すること。知っていることを経路間で混ぜる、選択に含まれない重大行為を追加する、選ぶ理由のない愚策だけを比較対象にする場合は差戻します。

V12-ASSUMPTION：追加設定の出典・採用・範囲・依存先を明示し、影響先と提示の必要度を検査すること。注釈に書いたことだけで整合確認済みとする、結末後の規則を過去へ流用する場合は差戻します。

## 20.3 構造・経路の継承検査

参照される全実体が存在し、初期状態が固定過去と一致することを確認します。所在の一意性と包含の非循環、接続、能力、保持者、数量の非負、容量、収支を検査します。

表示・実行・成功提示の条件、戦闘勝利前後、敗北・逃走・拒否・資源不足、合流・再訪、報酬の一回性、通知前後、情報の取得時点、期限の境界、保存・再開・移行を確認します。

有限状態の全探索、深さを限った探索、代表経路の実行、静的検査、本文レビューを区別します。抽象化した反例は必要に応じて具体的な状態へ戻して確認します。上限付き探索を全経路の証明とは呼びません。

## 20.4 網羅性と検査結果の状態

coverageには、重要な依頼・行為・目的変更・推論・合意・結果・本文断定を列挙し、対応する契約、検査方法、対象経路、結果を結びます。契約から本文だけでなく、本文から契約への対応も点検します。

検査状態はpass、fail、needs_review、not_run、not_applicableを区別します。not_applicableには理由、passには実施方法・根拠・対象版、failには再現内容を必要とします。単に検査名が存在することはpassの根拠ではありません。

重大な行為や結末の根拠が未定義、対応する意味検査が未実施、構造違反が未修正の場合は、当該範囲をv1.2b準拠の完成品としません。部分対応なら、対応範囲と未解決事項を明示します。無関係な検査の点数で相殺しません。

## 20.5 差戻し報告

各問題は、シナリオIDと版、対象経路または本文位置、問題の断定・行為、対応検査ID、利用可能な根拠、欠けた条件または反例、期待と実際、修正方針、影響先、再検査の結果を持ちます。

状態矛盾には最後の更新イベントを、意味の飛躍には結論を覆す具体的な別解や不足条件を示します。「説得力がない」だけで止めません。初期設定の問題なら、その初期条件自体を再現単位とします。

差戻し先は、Situation、Mechanism、Goal Transition、Institution、Inference、Resolution、Choice、Presentationなど原因の定義へ向けます。設定を変えたのに本文だけ再読して終えず、依存先の検査結果を古い版として無効化し、必要な範囲を再確認します。

## 20.6 物語としての完成

Coherence、Causal Necessity、Character Necessity、Economy、Surprise、Fairness、Retrospective Gain、Emotional Payoffを別々に見ます。加えて、介入の意味、経路ごとの成立、情報境界、媒体変換、作品群の構造差を確認します。

人物名を替えても同じか、情報を早く渡しても人物が行動できるか、分岐を削ると何が失われるか、説教を削っても主題が残るかを点検します。これらは一律の失格式ではなく、生活感・緩急・小さな態度表現を残すための判断を伴います。

モデルが保証できるのは、定義した条件と実施した検査の範囲です。人物の深さや面白さを機械的に保証しません。その限界を理由に、具体的な矛盾や飛躍の検査を省略することも認めません。

## 20.7 本文だけで一つの経路を読む方法

レビューする作品版、開始条件、選択列を固定します。材料は、その経路で実際に見える導入、規則、本文変種、選択肢、公開記録、および提示に使う画像・音等です。作者用のfacts、why、event、未到達節、他周回の情報で本文の不足を補いません。

重要な分岐ごとに、次のことを本文位置とともに記録します。

1. 読者が何を知り、何をまだ知らないか。主人公が使える知識との違いはあるか。
2. 各行為を選びうる欲望・利点・義理・恐れ等が、どの提示で成立しているか。
3. 読者に残された推測・工夫・価値判断は何か。解答や作者の採点を先に渡していないか。
4. 選択後に何が起こり、誰がどう応じ、次の判断または結末へ何が残ったか。
5. 宣言された大きさに見合う違いがあるか。ない場合、その枝は小さな態度・情景の役割として適切か。

少なくとも、中心となる判断を通る完成経路、その重要な比較対象、核心となる開示を通る経路と取り逃す経路、重大な約束や負担が合流する経路を、該当する範囲で選びます。同じ経路で複数の目的を確認できます。有限状態の全探索をしていても、全本文経路を読んだとは報告しません。未確認範囲を記録します。

本文レビューの後に作者資料と実行条件を照合し、読者に足りない情報と、作者の設定自体の不足を切り分けます。作者資料を先に知っている同じAIによるレビューは、厳密な盲検とは呼びません。別担当へ作者資料を渡さない点検、実読者の試読を行った場合は、その方法と対象を別に記録します。

「読者は必ずこう感じる」と断定せず、提示から成立しうる読みと、それを支える箇所を示します。好みの違いだけならneeds_reviewとし、作者資料にしかない重要前提や、経路と矛盾する断定は具体的な不備として扱います。

## 20.8 v1.2bの本文・経路検査ID

以下は、対応する体験や主張が作品にある場合に適用します。カードを埋めたことを合格にせず、本文位置・経路・根拠を示します。v1.2の九検査を置き換えず、構造と意味の検査に追加して使います。

V12B-PRESENTATION：作者の誤記防止や実装上の注意が、作中の必要性なしに本文へ流れていないか。誰もしていない誤解への訂正が続き、判断・人物・語りの効果も説明できない場合は提示を差し戻します。必要な説明や、作中の否認・皮肉は対象外です。

V12B-INFERENCE-SPACE：推理・工夫・発見を狙う場面に、読者が結び付ける部分があるか。答えを導入で確定しておき、後の同じ説明だけを発見の山場とする場合は、情報配置か場面の狙いを差し戻します。実演、既知の解答を使う実行、価値の選択では、答えの提示自体を不合格にしません。

V12B-MOTIVE：主要な決断を支える理由が、選択時点の本文と人物の認識から成立するか。whyにしかない約束や欲望で大きな代償を正当化する場合は差し戻します。不合理な選択も本人の理由があれば扱えます。自由に演じる主人公には、選べる意図としての根拠を確認します。

V12B-KERNEL：危険、失う成果、両立不能などの中心的な説明と、実際の到達経路が一致するか。無条件に元の成果へ追加できる方法を、成果を失う不可逆な賭けと断定する場合は差し戻します。人物の不安と世界の危険を区別し、核を改める方法も認めます。

V12B-ALTERNATIVE-RETURN：自然な別解や新しい設定を採用した後、従来の選択理由と中心課題を再評価したか。解けた危機を未解決として引き延ばす、または元の筋を守るためだけに不利益を追加する場合は差し戻します。代案で十分に終わる作品も認めます。

V12B-REACTION：主要人物の判断や重要な負担が、後の言葉・行為・関係・可能な選択へ接続しているか。場面の中心である予定変更や約束が合流で無かったことになる場合は差し戻します。素直な協力、一言だけの反応、あえて沈黙する反応も成立根拠にできます。

V12B-PAYOFF：分岐が約束した違いを、実際に経験する場面へたどれるか。大きな戦略的選択として提示しているのに、使える情報・結果・関係・解釈・読書体験の差を説明できない場合は、分岐か提示の重さを差し戻します。局所的な味わい、態度、緩急の枝は認めます。

V12B-FAILURE：主要な失敗の結果と、以後の判断または終わり方が、作品の狙いに対応するか。失敗による差を消す、約束した再判断を欠く、意図しない行き止まりを結末とする場合は差し戻します。短い失敗終端そのものは違反ではありません。

V12B-VARIETY：複数作品を制作する場合、主人公の欲望、介入、NPCの応答、情報の仕事、語り口、感情の着地点まで比較したか。多様な短編集を求められたのに、名詞を替えた同じ確認手順と結末を反復する場合は、該当作品の設計へ戻ります。意図的な連作の共通形式や、単一作品には同じ要求を課しません。

## 20.9 作品群の比較と、完了の判断

作品群では、事件の機構・分岐図に加え、誰が何を欲するか、プレイヤーがどう介入するか、NPCがどう返すか、どこで何を感じる設計か、どんな言葉や像で終えるかを横断して読みます。舞台名や職業名だけの違いを、体験の違いとは数えません。

似ていること自体は違反ではありません。連作の狙い、反復による対比、統一された読後感は保持できます。多様性のためだけに暴力、死、裏切りを足したり、すべての作品を別のジャンルへ振り分けたりしません。

完成報告では、構造・意味・本文の検査範囲と未解決事項を分けます。主要な行為・結末の矛盾、成立に必要な情報の欠落、中心に掲げた体験と実際の経路の明白な不一致を、他の長所や点数で相殺しません。美的な判断が分かれる箇所は理由付きで残せます。モデルは面白さの自動証明を保証しません。

# 21. GAMEBOOKの実例による適用と判定

## 21.1 例の扱い

以下は、コミット`bca4aafa925872bfc03231047d3e846f264ac649`の原稿に対する適用例です。観察できる本文・選択・効果と、モデル上の評価、改稿の候補を区別します。ここに示す案をGB原稿へ実装したという報告ではありません。個々の指摘だけで作品全体を失敗作と判断するものでもありません。

## 21.2 作者の注意と、語り手の言葉を分ける

GB04「王女を運ばない馬車」の節12には、会談を始めたことに言い換えない、見ていない監察人の行先を書き加えない、という趣旨の説明があります。作者が守る断定の範囲としては必要です。一方、その場面で誰が誤報を求め、主人公が何に抗して正確に記すのかが本文にないなら、作者の検査が語りへ出た箇所として点検します。[参照原稿：GB04・節12](https://github.com/TomTomYoung/GAMEBOOK/blob/bca4aafa925872bfc03231047d3e846f264ac649/data/stories/gb04.json)

改稿では、空の馬車の返却、受け取った中止報告、記録する主人公の手つき等で必要な事実を示せます。具体的な改稿案を選ぶ際には、作中に虚偽報告への圧力があるかも確認します。その圧力が実際にあるなら、否認の一文は人物の判断として機能し得ます。V12B-PRESENTATIONは否定文の禁止ではありません。

## 21.3 先に教える規則と、後で見つける関係を分ける

GB11「暗礁の二重灯台」は、導入で灯色を担当航路と船の喫水に組み合わせて読む規則を説明し、節02と05でも異なる灯が異なる船を対象にすることを明かします。この関係そのものを発見の中心に置くなら、導入で既に説明している量を再検討する必要があります。選択03bのラベルは「喫水対象を確かめず、青灯の切れ目へ進む」です。確認を省く行為の説明として成立する一方、導入の情報と合わせて、選ぶ前から失策として強く読まれないかを点検します。この評価は、原稿にある文言と区別して扱います。[参照原稿：GB11・導入、節02、03、05](https://github.com/TomTomYoung/GAMEBOOK/blob/bca4aafa925872bfc03231047d3e846f264ac649/data/stories/gb11.json)

改稿には、発見を狙って情報配置を調整する方法と、規則は既知として、どの情報を照会し、何を優先して運航するかへ中心を移す方法があります。いずれでも、本船の喫水、引き返せる範囲、進入の既知の危険など、判断に必要な条件は残します。全規則を隠す方法は採りません。

## 21.4 大きな代償を、whyだけで支えない

GB10「返却期限のない図書館」では、永久的に記憶を渡せば旧機の調整書をすぐ得られます。同じ本を二日間の整理作業で得る方法、明夜を星幕の会にする方法、三十日後の通常交換も用意されています。記憶を守る代案が成立していること自体は長所です。[参照原稿：GB10・導入、節02〜07](https://github.com/TomTomYoung/GAMEBOOK/blob/bca4aafa925872bfc03231047d3e846f264ac649/data/stories/gb10.json)

点検するのは、それでも明夜の旧機を優先する切実さが、主人公の経験や欲望から読み取れるかです。「早く動かしたい」だけで十分かは、不可逆な喪失の重さと本文の描き方に照らして判断します。改稿するなら、本人が抱く具体的な約束や自己像を本文で育てる、取引の便益と負担を再設計する、または誘惑を退ける判断を中心に据える方法があります。新しい約束を採用する場合は創作上の追加であり、既存事実として扱いません。

## 21.5 賭けという説明を、実際の手順に照合する

GB15「一度だけ戻れる敗戦」の選択09aは、確定した帰還を手放して別の救出機会に賭ける趣旨です。しかし節14では、巻戻し前に知った組を五分、別の組を十分で救出でき、どちらの順も可能です。確認した原稿の条件では、以前の組の救出を回復しながら追加の組へ進む手順が用意されています。[参照原稿：GB15・選択09a、節14](https://github.com/TomTomYoung/GAMEBOOK/blob/bca4aafa925872bfc03231047d3e846f264ac649/data/stories/gb15.json)

したがって、元の救出を失う危険が中心だと説明するなら、その条件を確認し直します。改稿は、未知の事故を足すだけでなく、「記憶を使って追加で誰を救うか」へ核を合わせる方法でも成立します。登場人物が時間のやり直しを怖がることは描けますが、その不安と実行上の危険は分けます。

## 21.6 待てるようにした後、何を選ぶ物語かを見直す

GB05「雨を買った村」では、音が届かない場所で最後の一打を待てば、水を失わず通常受付中に六升を運べます。選択02dから節06の待機後の経路を通り、六升の散水と検収へ到達できます。器具の取付けや水の損失を伴わない自然な解決です。[参照原稿：GB05・選択02d、節06、08、10](https://github.com/TomTomYoung/GAMEBOOK/blob/bca4aafa925872bfc03231047d3e846f264ac649/data/stories/gb05.json)

待機案を削る必要はありません。その成立後も従来の運搬損失を中心的な難題として見せるなら、選択の意味を再評価します。納品後の配分や贈与、同行者との仕事、雲を運ぶ楽しさへ焦点を合わせることもできます。具体的な追加案は新規の設計判断として扱い、隠れた締切や蒸発を便宜的に追加しません。

## 21.7 同意した人物の、その後を消さない

GB20「世界を閉じる小さな店」の選択06aでは、ナオは条件付きで引受けを承諾し、今夜の街道便を見送って残ります。最終的に閉店へ変わる可能性にも同意しています。後から11aで閉店を選べること自体は矛盾ではありません。[参照原稿：GB20・選択06a、11a、節13、15](https://github.com/TomTomYoung/GAMEBOOK/blob/bca4aafa925872bfc03231047d3e846f264ac649/data/stories/gb20.json)

ただし、予定を変えて待った差が後の本人の言葉や行為にほぼ現れないなら、中心人物の反応として改善できます。次の便について相談する、自分で片付ける役割を選ぶ、条件が成立しなかったことへ一言応じる等は改稿候補です。必ず怒らせる、引受けを撤回させるという意味ではありません。

## 21.8 同じ結果へ合流しても、違いは成立する

GB19「十二人目の帰還者」の07bから11を経て10へ進む枝は、岩屋を調べた後に足跡の経路へ合流します。追加の場面を味わう分岐としては扱えますが、大きな戦略差を約束するなら、その後に使える情報や関係の違いがあるかを確認します。[参照原稿：GB19・節07、10、11](https://github.com/TomTomYoung/GAMEBOOK/blob/bca4aafa925872bfc03231047d3e846f264ac649/data/stories/gb19.json)

一方、同作の救助同行と受入側に残る経路は、どちらも全員帰還する結果を持ちながら、節13〜14の共同の帰路と帰還時のやり取り、節12の用意された食器をオルが受け取る場面で関わり方が異なります。世界の成功状態が同じであることだけを理由に、無意味な分岐と判定してはいけません。[参照原稿：GB19・節12〜14](https://github.com/TomTomYoung/GAMEBOOK/blob/bca4aafa925872bfc03231047d3e846f264ac649/data/stories/gb19.json)

## 21.9 小さな本文差が、約束の重さを伝える

GB06「最後の一席」では、節01で観劇を約束したかどうかが、トワへ席を渡した後の節14のナオの返事に残ります。約束した経路では、次は決めてから約束してほしいという言葉と、来てくれた礼が別々に置かれます。約束フラグを説明せず、相手がどう受け取ったかを本文にできている例です。[参照原稿：GB06・節01、14](https://github.com/TomTomYoung/GAMEBOOK/blob/bca4aafa925872bfc03231047d3e846f264ac649/data/stories/gb06.json)

この種の回収は、別エンディングの大量追加や、好感度の減点を必要としません。約束をした本人、聞いた相手、実際に選んだ行為、後の返事が接続していることが重要です。すべての作品で同じ叱責を使う意味でもありません。

## 21.10 状態の変化を、手の動きで見せる

GB20の継承結末である節14には、主人公が鍵を受け取ろうとして手を下ろし、ナオが自分の鍵を鳴らす場面があります。引渡しの成立が、所有の説明だけでなく、主人公の手の動きと新しい店主の動作へ現れています。最後に営業時間の札を掛け直す行為も、本人が店を営み始めたことを支えています。[参照原稿：GB20・節14](https://github.com/TomTomYoung/GAMEBOOK/blob/bca4aafa925872bfc03231047d3e846f264ac649/data/stories/gb20.json)

前段の合意・引渡し・試験を根拠として保持しながら、読者には人物の動作で変化を見届けてもらう例です。全ての作品を説明の少ない文体へそろえる指示ではなく、各作品で状態と感情をつなぐ方法を探します。

## 21.11 最小限の判定記録例

記録例A：重要な選択のwhyに「妹との約束を守る」とあるが、その経路の本文にも初期設定にも約束がない。V12B-MOTIVEはfail。約束を前に提示する、選択の動機を改める、自由な主人公の意図として選べる形にする等の修正を行い、影響経路を読み直します。

記録例B：双方の帰還結果は同じだが、同行の有無による本人とのやり取りが結末にある。V12B-PAYOFFでは、その関係の違いを証拠として採用できます。結末IDが同一であることだけではfailにしません。

記録例C：既知の安全な代案で問題が解けたのに、以後の地の文が「今すぐ危険な手順を選ばなければ全員助からない」と断定する。V12B-ALTERNATIVE-RETURNとV12B-KERNELはfail。制約を後付けする前に、核と後続場面を修正します。

記録例D：規則を先に示し、理解した規則を使って複数の依頼をどの順に実行するか選ばせる。発見型の謎でないことを明記し、実行判断が成立していれば、答えを伏せないことだけではfailにしません。

これらは判定方法の例です。実際の原稿のpassには、その版、経路、本文位置、実施方法の記録が必要です。本書の作成をもって、既存20作をv1.2b検査に合格したとは扱いません。

# 22. ゲームブックへの直接適用

人物、固定過去、法則、目的、行動の意味、状態更新、情報取得、結末を共通IRとして保持し、UIやカメラ表現を番号付き本文と記録用紙へ変換します。

読者に記録させるのは、公開された数値、コードワード、所持品、同行者、取得した手掛かりなど、自分の記録から判定できるものです。作者だけが知る真相を読者へ直接判定させません。秘密の差は必要に応じて節分割や経路へ埋め込みます。

現在の節から一意に決まる所在まで、毎回全員分書かせる必要はありません。合流後に使う差は残します。q001で先に老人を詰所へ運んだ経路は、詰所の再会節へ接続し、支道に老人がいる本文を共用しません。

印を付ける時点、数量の増減、次の節、再訪時の扱いを明記します。不可分な行為の記録は一まとまりで更新し、再読で再実行しません。中断は整合した記録を保存できる区切りで行います。

戦闘は勝敗、部分討伐、逃走、消費、記録の方法を定義します。媒体に合わせて単純化するなら、何を変更し、どの物語上の結果を保持するかを明示します。

v1.2から継承する九つの根拠契約は作者用のまま保持できます。読者へ制度や因果の全台帳を記入させません。ただし、選択の意味、推理の根拠、当事者の目的の変化がゲーム版で提示されていたなら、紙でも行為・段落・会話として等価に伝えます。

変換後は、すべての節の参照先、読者が判定できる条件、記録の増減、秘密の漏洩、合流と再訪、終了条件を検査します。同じ選択と判定結果で、関連する世界・関係・知識・約束・結末が対応することを確認します。

実際のゲームブック生成を依頼された場合は、設計図だけで終えず、記録用紙と全参照先が解決した番号付き本文を出力します。この章はその変換仕様です。

v1.2bの本文レビューは、変換後の番号付き本文にも適用します。節番号や記録欄の名前が真相を漏らしていないか、選択前の必要情報と考える余地が残っているか、人物の返事が合流で消えていないかを確認します。端末で情報を示していた図や音を省く場合は、判断に必要な意味を本文や利用可能な別表現へ移します。

# 23. 実装への適用と版の管理

## 23.1 設計仕様と実行能力を分ける

参照したGAMEBOOKの[実装対応文書](https://github.com/TomTomYoung/GAMEBOOK/blob/bca4aafa925872bfc03231047d3e846f264ac649/doc/MODEL_IMPLEMENTATION.md)では、20作は独立した有限状態の作品です。作者用の人物・法則・制度・推論の根拠をauthorの日本語に保持し、実行に必要な条件と効果をstateとnodesへ具体化しています。汎用IRをそのまま実行するエンジンではありません。

参照版の設計モデルは1.2、実行アダプターは1、作品内容は各作品のrevision、保存形式はgamebook-sessionとgamebook-shelfのversionで区別されています。これは参照コミットの実装範囲です。本書のv1.2b作成だけで、既存の作品JSON、エンジン、保存データの版を更新したことにはなりません。

v1.2本文に記載されたadvの作品版や実装範囲は、当時の参照記録です。本書ではそれをadvの現在の状態として再認定しません。adv等の別実装へ導入するときは、その対象版と能力をあらためて照合します。

## 23.2 既存作品へ導入する手順

まず、固定過去、採用設定、人物の目的、本文を継承契約へ対応させます。そのうえで、体験の焦点、重要な選択の理由、情報配置、NPCの応答、分岐の回収を、実際の本文と経路へ結びます。自由文のauthor欄が存在することだけで対応済みとはしません。

改稿に必要な現在値と履歴を、既存の正本へ割り当てます。進行節から一意に分かる差や、その場限りの態度を無理にフラグへ増やしません。後で使う約束や人物の取得情報は、参照可能な経路または状態で保持します。

原稿の正本、生成器、生成済みデータ、実行側、検査の対応を保ちます。GAMEBOOKではdata/storiesの原稿が正本であり、js/stories.jsは生成された配布データです。生成物だけ直して再生成で消える修正にしません。[参照：データと改稿の手順](https://github.com/TomTomYoung/GAMEBOOK/blob/bca4aafa925872bfc03231047d3e846f264ac649/doc/MODEL_IMPLEMENTATION.md)

対象アダプターの条件・効果・本文変種の意味を確認します。たとえば参照版GAMEBOOKのvariantsは、一致するものを原稿順にすべて加える処理です。一致した最初の一つだけと誤認して、排他的な台詞を同時表示させないようにします。新機能を自由文に書いただけで実装されたとは扱いません。[参照：効果と本文](https://github.com/TomTomYoung/GAMEBOOK/blob/bca4aafa925872bfc03231047d3e846f264ac649/doc/MODEL_IMPLEMENTATION.md)

変更した原稿と影響経路を検査し、作品のrevision、保存互換、再開方針を決めます。意味・演出のレビュー、状態付き経路、画面表示、保存・再開の検査範囲を別々に報告します。内容を保存できない単純化や未対応機能があれば、対応する有限分岐へ変換するか、部分対応として記録します。

## 23.3 動的生成と世界観wiki

動的な本文生成にも、確定状態と許可された断定を入力します。新しい行為は構造化して前提と作用を検査してから確定します。契約に反する文は採用せず、必要なら状態に対応する既定文を用います。文を出したことと、世界内の行為を確定したことを同一視しません。

世界観wikiには、採用済み設定、証言・信念、推測、経路依存の帰結、提案中の設定を区別して転記します。根拠の正本とIDを参照し、記事の都合で全経路共通の過去へ統合しません。演出上の解釈や読者の感想も、客観的な世界法則へ自動昇格させません。
