# 全滅時のイベント区間チェックポイント

2026-09-27、作品版1.22.0。[イベント一覧](README.md)、[イベント仕様](EVENT_SYSTEM.md)、[封印・禁止](../dungeons/DUNGEON_RESTRICTIONS.md)。

途中で全滅したら、依頼の決められた場面からやり直すための共通部品です。実装は `src/core/event-checkpoints.js`。Coreにはq001のIDや台詞を置かず、原稿で区間の開始・成功・復元対象を宣言します。

## 全滅からの復帰

既存の `GameEngine.defeat()` が所持金の15％を救援費として失わせ、町の起点へ戻し、HP・MPを既定の割合まで回復し、状態異常を解除します。通常戦闘、イベント戦闘、フィールドの致死ダメージ、環境システムの全滅救助は、この共通処理を使用します。

今回、町への移動より前に未確定のチェックポイントを巻き戻します。町への移動後に探索隊の物語上の所在を現在地へ同期するため、老人の座標にプレイヤーだけが残る状態を作りません。会話、戦闘、立ち絵、メッセージ、区間内の移動予約は破棄します。巻き戻した戦闘の `on_lose` は実行せず、古い継続処理によって取り消した進行を再度進めません。チェックポイントがない場合は既存の敗北継続を維持します。

## 原稿の指定

復元したい副作用を起こす前に、開始場面で次の命令を実行します。現在は実在するダンジョンの場面を持つ物語クエストが対象です。

```json
{
  "op": "event.checkpoint.begin",
  "id": "q001.elder_rescue",
  "quest": "q001",
  "scene": "old",
  "dungeon": "kagaribi",
  "flags": [
    "worldSceneEffects.q001.old",
    "worldSceneEffects.q001.outage"
  ],
  "objects": ["kagaribi_f1/q001_last_lamp"],
  "eventKeys": ["kagaribi_f1/q001_elder", "kagaribi_f1/q001_return"],
  "restrictionSources": ["q001.elder_rescue"]
}
```

指定クエストの物語状態（場面・人物と物品の所在・知識・行動履歴・数量）を自動記録します。`flags` と任意の `vars` は、それぞれの領域内のドット区切りパスです。`objects` は `map/object`、`eventKeys` はイベント記録の完全なキーを列挙します。省略した配列は空として扱います。親子パスの重複や同時進行の区間間での復元対象の重複は拒否します。

復元は「開始前にはキーが存在しなかった」ことも記録します。q001の消灯済みフラグは削除されるため、再挑戦でも壁灯・携行火の消灯が実行されます。物体の保存キーが存在しなかった場合も削除し、配置物の初期状態へ戻します。

封印は指定迷宮かつ `restrictionSources` に列挙した発生元だけを対象にします。開始前から同じ発生元の封印があれば復元し、区間で新たに付いたものは取り消します。別の罠や別のイベントによる封印は変更しません。

同じ開始会話を中断・再開した場合は、最初の記録を維持します。区間IDは原稿内で一意にし、成功時は次の命令で確定します。確定後に全滅しても、その区間を巻き戻しません。確定の再実行は副作用を持ちません。

```json
{"op": "event.checkpoint.commit", "id": "q001.elder_rescue"}
```

開始はフィールドの場面で、確定はフィールドまたは戦闘中イベントで実行できます。区間の報酬やクエスト完了は成功確定後へ配置します。

## 戻さないもの

冒険全体のセーブを巻き戻す機能ではありません。消費した所持品、所持金、獲得経験値、戦績、歩数、乱数、踏査済み地図、別の依頼や宣言外のフラグ・物体は維持します。全滅時の救援費は実際の所持金に対して一度だけ計算します。クエストの受注・報酬・証拠手帳はこの部品の復元対象に含めません。

携行松明など、迷宮退場で消え再入場で作り直す探索中の環境状態は、既存の退場・入場処理に任せます。q001では老人との再遭遇で携行火8歩、帰路のイベントで0歩、救援成功で25歩の処理が再び実行されます。

## q001の区間

老人の場面 `old` に入った後、携行火の変更・帰還封印・会話表示より前に区間を開始します。老人に肩を貸す帰路での通常戦闘、罠、くらがりとの強制戦闘で全滅した場合も、同じ区間を取り消します。

町へ戻った時点で、次の現場は老人セル `kagaribi_f1` (13, 3) です。老人は支道、新人は入口へ戻り、帰還印はq001由来の封印が解けています。入口・巡灯路を通っても帰路のくらがりイベントは始まらず、老人に再遭遇した時点で新しい区間を開始します。そこから再度老人を介助して帰路へ向かうと、消灯と救援戦闘が起きます。

新人の発言を送ると、救援行為・点灯・`battle.end`・q001の封印解除・チェックポイント確定が連続して実行されます。救援会話 `rescue` を表示した時点で区間は確定済みです。成功後の全滅では新人の救援を取り消しません。

## 保存と検証

`state.eventCheckpoints` に開始命令の位置、物語状態、対象キーの存在有無と値、対象封印を保存します。保存ファイル内の任意パスを復元先に使わず、配布原稿の命令から対象を引き直します。読み込みでは命令・クエスト・場面・復元値・封印の発生元・重複を検査し、不正な保存で現在の状態を置き換えません。

[回帰試験](../../tests/event-checkpoints.test.mjs)では通常敗北、区間の各段階、会話・移動・戦闘中の保存、実際の帰路歩行と再遭遇、連続失敗、罠の致死ダメージ、古い敗北継続の破棄、救援成功後、別クエストでの再利用、宣言外の状態維持、不正な原稿・保存を検査します。
