# ゲームシナリオの設計と実装

更新日: 2026-09-25。作品版1.20.0の実装を対象とします。全200本を一つの手順へ揃えず、人物の目的、固定された過去、得た情報、行為の成立、応答と代償を各原稿で定義します。

## 適用モデルと経路

q001〜q010はモデルv1.1、実装アダプターは `adv-story-state/1` です。人物・物品・場所・保持者・同席・介助・同意・情報の取得条件を検査し、新規進行は `.v11.*` を使います。[モデルの実装範囲](SCENARIO_MODEL_V11.md)と[本文](QUEST_CATALOG.md#q001-帰らない灯番)を参照してください。

q011〜q020はモデルv1.0に基づくカタログ改稿を `.catalog1.*` へ反映しています。個別フラグ、費用、作業、同意、結末条件を宣言します。v1.1の所在検査を持つものとしては扱いません。[現在の本文](QUEST_CATALOG.md#q011-塩の花嫁)を参照してください。

q021〜q200は各依頼の場面グラフと固有条件を使います。内部移動が会話選択として扱われる場面もあり、全ての場所を別の歩行マップにはしていません。

## 状態と情報

`quests.<id>` は受注・証拠・結末、`flags.flow.<id>`／`flags.quest.<id>` は原稿ごとの内部進行、`stories.<id>` はv1.1の検査対象状態、`records` はエンジンが自動記録する戦績です。

`model.world.history` と `truth` は固定された過去を表します。`knowledge` や取得済みの観察は、人物やプレイヤーが何を知ったかを表します。過去の事実と知った時点を同じフラグにしません。作者向けの注釈は制約として保持し、本文へ機械的に流し込みません。

q001では老人・新人・油の所在、q010では住民の到着・帳簿・証言を区別します。q011〜q020の原稿では貸借、避難の標示、筆写、機材の使用目的などを場面の行為と条件へ落とし込みます。場面数や結末数を揃えることを生成器の目的にしません。

## ダンジョンとの接続

歩行マップの固有部品は `dungeons` の状態を管理します。PR #8で追加済みの現地調査はその状態を読み、関連依頼の手帳へ観察を残します。確認対象、調査地点、本文は `config/quests/qXXX.events.json` です。

物理的な装置の操作と、救助・合意・証言など別の事実を区別します。本筋の分岐へ接続を深めるときは、行為が何を成立させたかを明示した条件へ反映し、異なる事実を一つの完了フラグへまとめません。

## 正本と生成順序

カタログの短い経過は `authoring/quest-route-notes.json` が正本です。全200件を「【ダンジョン名／町名】[場所]：経過」の箇条書きで掲載します。経過は概要の直後に置き、場所の移動・再訪・途中で終わる経路・最終分岐を残します。座標、場面ID、条件式は詳細へ分けます。同じ場所の往復を場所別にまとめ直して時系列を崩さず、未接続の場所や未設定の町名を実装済みの所在地として扱いません。

描画は `tools/quest-route-summary.mjs` が担当します。ダンジョン・町の名前は配布データのIDから解決し、地下室内の親に `dungeonEntrance` がある場合は、そのダンジョン名を使います。q005以降には本文上の場所と実移動未接続の注記を付け、周辺集落の話へ既存の町名を勝手に割り当てません。

経過の `sourceHash` は本文・分岐・結末・所在の照合用です。シナリオ変更で不一致になった場合は、先に経過の文章を読み直して修正し、確認後に `questRouteSourceHash(q)` の値へ更新します。指紋だけを自動更新して古い要約を通してはいけません。`npm run build:catalog` で反映し、`npm run check:docs` が全200件の原稿との一致を検査します。`npm run build:docs` だけでは経過を上書きしません。

```sh
npm run build:scenarios
```

基礎データと互換用スクリプト、追加篇、個別構造、v1.1とカタログ改稿、ダンジョン、スキーマの順に生成します。最後に配布JSONから統合カタログを生成し、他の文書を更新します。

q001は `story-q001.mjs`、q002は `story-q002.mjs`、q004は `story-q004.mjs`、残るq003〜q010は `stories-v11-*.mjs`、q011〜q020は `catalog-q011-q020.json/.mjs`、その他は `structures-*.mjs` と `scenarios-*.mjs` が主な編集先です。詳細は[HANDOFF.md](../HANDOFF.md)へ記載します。

[QUEST_CATALOG.md](QUEST_CATALOG.md)をユーザーが改稿した場合は、内容を確認して正本へ反映してから再生成します。文書更新だけの依頼でカタログ本文を配布JSONへ強制的に戻してはいけません。

## 保存と検証

利用者の指定により旧内容版セーブは移行しません。解析・検証でエラーが出た記録は最初から開始します。q001は旧進行を廃止し、他依頼の既存本文は維持します。

結末到達、同版の中断・再開、費用、勝敗時の成立、読込失敗からの新規開始を検査します。文章と人物の目的・情報取得との整合は具体的な選択列を読んで確認します。汎用Objective／Reward、自動期限、世界共通NPC配置は未実装です。

## 改稿全文の統合

q001〜q010の[個別ページ](quests/README.md)に本文・選択後の応答・条件・結末・マップデータ・イベント配置を掲載し、q011〜q020の全文は[QUEST_CATALOG.md](QUEST_CATALOG.md)の各項目に掲載します。q021〜q200は概要と進行・結末一覧です。二つの旧全文文書は廃止し、中間生成器によるカタログ出力も止めました。

npm run build:catalog は、最終生成済みのdata/を読み、現在の場面をmodel.narrative.unitsから特定し、実行するscriptsの本文・選択・分岐・戦闘後の継続を掲載します。物語の初期所在、固定された過去、作者向け制約、結末と報酬も同じJSONから生成します。対応していない命令は黙って省略せず生成エラーにします。

npm run build:catalog はq001〜q010の個別ページと一覧、q001・q002の座標付きSVGも生成します。個別ページは `doc/scenarios/quests/` に格納します。q003〜q010の解説は `authoring/quest-page-notes.mjs`、実装詳細は配布JSONから生成します。イベントIDは場面・配置物・結末の元キーから生成し、クエスト内で一意にします。check:docsは専用ページとSVGも配布データに照合します。

npm run build:docs はカタログと専用ページの本文を保持します。利用者がカタログを改稿した場合は先に正本へ取り込みます。check:docsは生成時の実装指紋と現在のJSONを照合し、古い実装のカタログを検出します。

## 1.11.0の移動と文体の原則

イベントの成立に必須の転移以外は、出発選択・通常探索・到着後の場面へ分けます。単なる制御フローのjumpは転移ではありません。原稿共通部品はauthoring/world-story-kit.mjsです。q001・既存q002・q003が接続済みで、q004以降は次工程です。個別の行為・費用・戦闘・帰路を省略する一律変換はしません。

全200件の配布文章はauthoring/narration.mjsを生成末尾に適用し、地の文を常体に揃えます。引用・話者付きの台詞は人物の口調として保持します。未知の活用は生成差分を確認し、命令名・ID・条件・数値を変換対象に加えないでください。詳細は [探索と文体の改訂](EXPLORATION_AND_PROSE.md) に記載しています。

## 人物の演出

立ち位置と同席条件はシナリオで設計します。story.scenes.cast.displayとscene.cast命令で位置・倍率・反転・重なり・登退場を指定し、say.characterで発話者を識別します。三人以上は関係のある人物をまとめ、発話者の前後関係だけを変えます。q001の帰還報告では老人とルーキーを左、リネを右へ配置します。人物の物理的な所在は演出命令で変更しません。JSON例、カード表示、保存と解除の規則は[人物配置の仕様](../ui/CHARACTER_STAGING.md)を参照してください。

## 作業の不足分岐と再開（1.24.0）

全場面へ共通の「ここで中断し、同じ場面から再開する」を追加しません。会話と判断は原稿にある行為で進めます。ゲームを閉じる場合は通常の保存がメッセージ・選択待ち位置を保持します。

費用や資材の不足は未完了の作業に固有の分岐です。元の行為は実行不可のまま、必要な品・数量または金額を示す「用意しに戻る」が不足時だけ現れます。選ぶと不足理由を表示して会話を終え、作業・支払い・報酬を実行せず、探索や補給へ戻れます。NPCやアイテムの所在は変更せず、町への自動移動もしません。

生成元は各原稿のcost、story.actionsのcost、および選択条件にある資材・所持金条件です。tools/build-quest-interruptions.mjsが各作業に.shortageと.resumeのスクリプトを作り、model.interruptionRoutesへ必要量・出発場面・再開先を明記します。build:dungeonsとbuild:scenariosの末尾で適用します。配布JSONだけを手修正しません。

不足時はflags.questResumeの依頼別キーへ再開スクリプトを保存します。現場への再訪では.visitからその再開経路へ分岐し、未着手の作業がある場面へ戻ります。残高を確認しただけでは支払いません。元の行為が成立したときだけ消費し、戦闘付き作業は既存の勝利後処理で消費します。補給せず再訪した場合も不足分岐を選べます。完了した依頼の再開先は消去します。

戦闘からの逃走・全滅や物語上の離脱は、各イベントのon_escape・on_lose・再訪スクリプト・チェックポイントで未完了部分へ戻します。共通の空コマンドで代用しません。q001の救助前全滅は老人遭遇へ巻き戻し、救援済みなら巻き戻しません。

条件付きの選択肢だけで成立する場面もあります。内容検証は空の選択肢と全項目が明示的にfalseの選択肢を拒否します。全200依頼の到達可能な場面について、通常資源と所持金・資材ゼロの両方で進行経路を検査します。不足・再開の途中保存、実地点へ戻る制約、二重消費・二重報酬も試験します。

1.24.0は選択肢とスクリプト継続位置が変わるため、旧内容版のセーブを移行せず新規開始とします。
