# ゲームシナリオの設計と実装

更新日: 2026-09-19。作品版1.15.0の実装を対象とします。全200本を一つの手順へ揃えず、人物の目的、固定された過去、得た情報、行為の成立、応答と代償を各原稿で定義します。

## 適用モデルと経路

q001〜q010はモデルv1.1、実装アダプターは `adv-story-state/1` です。人物・物品・場所・保持者・同席・介助・同意・情報の取得条件を検査し、新規進行は `.v11.*` を使います。[モデルの実装範囲](SCENARIO_MODEL_V11.md)と[本文](QUEST_CATALOG.md#q001-帰らない灯番)を参照してください。

q011〜q020はモデルv1.0に基づくカタログ改稿を `.catalog1.*` へ反映しています。個別フラグ、費用、作業、同意、結末条件を宣言します。v1.1の所在検査を持つものとしては扱いません。[現在の本文](QUEST_CATALOG.md#q011-塩の花嫁)を参照してください。

q021〜q200は各依頼の場面グラフと固有条件を使います。内部移動が会話選択として扱われる場面もあり、全ての場所を別の歩行マップにはしていません。

## 状態と情報

`quests.<id>` は受注・証拠・結末、`flags.flow.<id>`／`flags.quest.<id>` は原稿ごとの内部進行、`stories.<id>` はv1.1の検査対象状態、`records` はエンジンが自動記録する戦績です。

`model.world.history` と `truth` は固定された過去を表します。`knowledge` や取得済みの観察は、人物やプレイヤーが何を知ったかを表します。過去の事実と知った時点を同じフラグにしません。作者向けの注釈は制約として保持し、本文へ機械的に流し込みません。

q001では老人・新人・油の所在、q010では住民の到着・帳簿・証言を区別します。q011〜q020の原稿では貸借、避難の標示、筆写、機材の使用目的などを場面の行為と条件へ落とし込みます。場面数や結末数を揃えることを生成器の目的にしません。

## ダンジョンとの接続

歩行マップの固有部品は `dungeons` の状態を管理します。PR #8で追加済みの現地調査はその状態を読み、関連依頼の手帳へ観察を残します。確認対象、調査地点、本文は `config/quests/qXXX.events.json` です。

物理的な装置の操作と、救助・合意・証言など別の事実を区別します。本筋の分岐へ接続を深めるときは、行為が何を成立させたかを明示した条件へ反映し、異なる事実を一つの完了フラグへまとめません。

## 正本と生成順序

```sh
npm run build:scenarios
```

基礎データと互換用スクリプト、追加篇、個別構造、v1.1とカタログ改稿、ダンジョン、スキーマの順に生成します。最後に配布JSONから統合カタログを生成し、他の文書を更新します。

q001は `story-q001.mjs`、q002は `story-q002.mjs`、q003〜q010は `stories-v11-*.mjs`、q011〜q020は `catalog-q011-q020.json/.mjs`、その他は `structures-*.mjs` と `scenarios-*.mjs` が主な編集先です。詳細は[HANDOFF.md](../HANDOFF.md)へ記載します。

[QUEST_CATALOG.md](QUEST_CATALOG.md)をユーザーが改稿した場合は、内容を確認して正本へ反映してから再生成します。文書更新だけの依頼でカタログ本文を配布JSONへ強制的に戻してはいけません。

## 保存と検証

利用者の指定により旧内容版セーブは移行しません。解析・検証でエラーが出た記録は最初から開始します。q001は旧進行を廃止し、他依頼の既存本文は維持します。

結末到達、同版の中断・再開、費用、勝敗時の成立、読込失敗からの新規開始を検査します。文章と人物の目的・情報取得との整合は具体的な選択列を読んで確認します。汎用Objective／Reward、自動期限、世界共通NPC配置は未実装です。

## 改稿全文の統合

q001の[専用ページ](QUEST_Q001.md)とq002の[専用ページ](QUEST_Q002.md)に本文・選択後の応答・条件・結末・マップデータ・イベント配置を掲載し、q003〜q020の全文は[QUEST_CATALOG.md](QUEST_CATALOG.md)の各項目に掲載します。q021〜q200は概要と進行・結末一覧です。二つの旧全文文書は廃止し、中間生成器によるカタログ出力も止めました。

npm run build:catalog は、最終生成済みのdata/を読み、現在の場面をmodel.narrative.unitsから特定し、実行するscriptsの本文・選択・分岐・戦闘後の継続を掲載します。物語の初期所在、固定された過去、作者向け制約、結末と報酬も同じJSONから生成します。対応していない命令は黙って省略せず生成エラーにします。

npm run build:catalog はq001・q002の専用ページと座標付きSVGも生成します。イベントIDは場面・配置物・結末の元キーから生成し、クエスト内で一意にします。check:docsは専用ページとSVGも配布データに照合します。

npm run build:docs はカタログと専用ページの本文を保持します。利用者がカタログを改稿した場合は先に正本へ取り込みます。check:docsは生成時の実装指紋と現在のJSONを照合し、古い実装のカタログを検出します。

## 1.11.0の移動と文体の原則

イベントの成立に必須の転移以外は、出発選択・通常探索・到着後の場面へ分けます。単なる制御フローのjumpは転移ではありません。原稿共通部品はauthoring/world-story-kit.mjsです。q001・既存q002・q003が接続済みで、q004以降は次工程です。個別の行為・費用・戦闘・帰路を省略する一律変換はしません。

全200件の配布文章はauthoring/narration.mjsを生成末尾に適用し、地の文を常体に揃えます。引用・話者付きの台詞は人物の口調として保持します。未知の活用は生成差分を確認し、命令名・ID・条件・数値を変換対象に加えないでください。詳細は [探索と文体の改訂](EXPLORATION_AND_PROSE_1_11.md) に記載しています。

## 人物の演出

立ち位置と同席条件はシナリオで設計します。story.scenes.cast.displayとscene.cast命令で位置・倍率・反転・重なり・登退場を指定し、say.characterで発話者を識別します。三人以上は関係のある人物をまとめ、発話者の前後関係だけを変えます。q001の帰還報告では老人とルーキーを左、リネを右へ配置します。人物の物理的な所在は演出命令で変更しません。JSON例、カード表示、保存と解除の規則は[人物配置の仕様](../ui/CHARACTER_STAGING.md)を参照してください。
