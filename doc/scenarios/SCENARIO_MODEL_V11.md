# シナリオモデル v1.1 の実装範囲

作品版: 1.14.0。更新日: 2026-09-18。v1.1の状態モデルは1.4.0から導入しています。

設計基準は [ゲームシナリオモデル v1.1](https://app.notion.com/p/v1-1-3dac3c1966b38069ab3bf87729e453c4)。q001〜q010 をこの基準で改稿し、人物・物品の所在と行為の成立条件を `adv-story-state/1` として実装した。q011〜q200 の準拠モデルは v1.0。q011〜q020はカタログ改稿を[シナリオ一覧](QUEST_CATALOG.md#q011-塩の花嫁)へ統合し、個別のフラグと結末条件を持つ `.catalog1.*` で実行する。v1.1の所在検査を備えたものとしては扱わない。

## 版の区別

値：`game.version: 1.14.0` / 意味：配布作品の内容版。保存内容の一致検査に使う

値：`game.storyVersion: 1` / 意味：保存する物語状態の形式

値：`model.standard.version: 1.1` / 意味：Notion の設計基準

値：`model.standard.adapter: adv-story-state/1` / 意味：このゲームで実装した解釈・機能範囲

値：`story.version: 1` / 意味：各物語の状態定義版

値：`story.revision` / 意味：同一形式内の状態構成の改訂。省略時は1。q001は実移動・戦闘イベントを含む4、q002・q003・q008は2

値：`model.flowVersion: 3` / 意味：新規開始時の `.v11.*` 実行経路

`model.standard` には基準ページの URL、改稿日、適用範囲も記録する。作品版とモデル版を同じ番号として扱わない。

## 五層と実行データ

設計層：World / 今回の実体：`model.world.history` の固定された過去、`story.places/connections/entities`、型付き初期状態

設計層：Agent / 今回の実体：同一性を保つ `data/characters.json`、人物の動機、物語内の所在・介助状態・認識

設計層：Narrative / 今回の実体：`.v11.*` の本文・選択肢。各場面は場所・同席者・遠隔会話の条件を宣言する

設計層：Audience / 今回の実体：ViewModel は表示中の人物・画像・本文・選択可否だけを渡す。作者向け真相や全人物の認識を渡さない

設計層：Transformation / Reveal / 今回の実体：情報源と取得条件を持つ `observe`、状態に応じた本文、行為後に成立する結末条件

人物名がない役割には役割 ID を割り当てる。`rine` は q001 と q010 で共通。故人を生存人物に混ぜず、集団は集団として登録する。肖像の外見は今回の美術設定で、旧シナリオから読み取れた事実とは分ける。

## 状態の保持と移動

`state.stories.<quest>` に `version / values / knowledge / events / scene` を保存する。`values` は `story.registry` に登録した boolean、範囲付き integer、enum だけを受け付ける。

人物・物品は実体ごとに一つの所在フィールドを持つ。物品は人物や別の物品を保持者にできる。例えば q008 の遺体は内室 `coffin` に、食料は `outerBase` に入る。外底は当初内室に取り付けられ、取り外した後は別の所在を持つ。保持者をたどると一つの実在場所に着かなければならず、循環や不明な保持者は拒否する。

効果：`move` / 検査する条件：出発地が一致し、経路の隣同士が接続されている。介助が要る人には同行者が、物品には運搬者が必要

効果：`transfer` / 検査する条件：物品の現在の保持者が合い、渡す側と受け取る側が同じ場所にいる

効果：`set` / 検査する条件：登録した状態だけを更新。所在フィールドへの直接書込みは不可

効果：`pour` / 検査する条件：容器の同席、残量、正の整数量、分配後の容量を確認

効果：`consume` / 検査する条件：容器の残量から消費量へ移す。q001 では油の総量を不変条件で確認

効果：`observe` / 検査する条件：登録済みの命題・観察者・情報源・前提条件。観察者が情報源に接触している

会話の開始には `story.scene` が場所・同席者を照合する。伝声管や面会窓は `mode: remote` と通信路の条件を持つ。声が聞こえても、人物や手紙を移動させたことにはならない。

## 行為・戦闘・結末

選択肢は `storyAction` で宣言済みの行為を参照する。投影時と選択時に同じ計画器で前提・資材・結果を確認する。原稿の宣言に矛盾があれば、無効な選択として表示し、静的検証と分岐探索で検出する。

`story.action` は状態・所持金・共通所持品の複製に効果を適用する。個々の移動・受渡しを検査した後、行為全体の型・不変条件・遷移先場面・結末条件を確認し、成功時だけ一括確定する。途中に会話待ち・保存待ちを挟まない。失敗時は支払いも状態変更も残らない。

戦闘を伴う作業は勝利後だけ実行する。逃走・敗北で勝利後の人物移動、作業、資材消費は発生しない。戦闘自体の HP、MP、戦績、救援費は従来の規則に従う。

結末スクリプトは `quest.complete` で物理条件を確認してから報酬・本文を出す。単に場面へジャンプしても全員救出にはならない。q010 は手前三人・奥二人の到着、帳簿、証言を独立して保持し、全員救出だけの `rescued` と調査記録付きの `informed` を分ける。

## 時刻と適用範囲

この実装はクエスト内の出来事を管理する。通常ダンジョンの座標と、物語内の支道・詰所などの所在は別の粒度を持つ。選択肢に記した一連の行動が物語内の移動経路を進める。

中断・帰還・敗北中はその物語の時計を止め、再訪時に最後の場面から再開する。q001〜q003の `partyAt` は実際の町施設・歩行座標と同期し、定義外の場所では `transit` とする。移動中は `state.journey` が出発場面・行為・同行者を保持し、到着時に自動続行する。q004以降の物語内の所在は従来の場面単位で管理する。「一晩待つ」「夜明けの帰還確認」などの時間経過は明示した行為で確定し、実時間で隠れて死者が増える締切は入れていない。

共通人物の ID は共有するが、複数依頼を同時進行した場合の全世界共通の NPC スケジュールや排他配置は未実装。v1.1 の設計全体を汎用シミュレーターとして完成させたという意味ではない。人物の所在、所持、介助、合意、情報取得、到着、終了条件のうち、この10本で必要な状態を作者が宣言して検査する。

自然文の意味を機械が完全に証明するものでもない。本文に宣言されていない主張が混入する場合は編集上の検査が必要。自由文を増やす時も、場面の cast・requires と対応する状態を増やす。

## セーブ

1.14.0は旧内容版のセーブを移行しません。不正または旧版の記録は最初から開始します。同版の記録では、型・実体の所在・情報参照・同席・結末成立を検証後に置き換えます。未知の状態名、数量超過、保持関係の循環、未成立の救出記録はエラーです。

q004のwindow別名とq008の同内容版内の改訂検証は残っています。旧作品版への移行保証ではありません。q001は改訂4だけを生成し、以前の新人同行・先行引継ぎ・油分配の経路を廃止しました。

## 編集・再生成

```bash
npm run build:scenarios
npm run build:docs
npm run check
```

q001の原稿は `authoring/story-q001.mjs`、q002は `authoring/story-q002.mjs`。共通記法と他8本の原稿は `authoring/story-kit.mjs` と `authoring/stories-v11-1.mjs / stories-v11-2.mjs`。`tools/build-stories-v11.mjs` が実行JSONと人物一覧を生成し、ダンジョン・イベントを反映した後に `tools/build-quest-catalog.mjs` が配布JSONから統合カタログを生成する。生成済み JSON だけの修正はしない。

カタログのAI向け注釈と世界設定上の事実は、原稿の `authoringNotes` とJSONの `model.world.authoringNotes` に保持する。台詞へ機械的に挿入せず、人物の目的・情報の取得順・状態遷移が制約と矛盾しないように編集する。

人物定義は `authoring/characters.mjs`、現在表示する36人の肖像は `assets/images/characters/generated/*.webp`。画像生成の英語・日本語プロンプトとハッシュを [生成記録](../../assets/source/characters/imagegen-manifest.json)へ保持する。旧112×128のAIPaint PNG、編集原稿、描画コマンドも保存している。`npm run build:characters` は旧素材の再現と人物・物語データの生成を行い、採用中のWebPを画像生成し直すコマンドではない。[PROVENANCE](../../assets/PROVENANCE.md)と[人物一覧](CHARACTERS.md)を確認する。
