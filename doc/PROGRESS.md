## 3. 現在の主要問題

### P0: シナリオ遷移が未完成

最優先です。

17選択肢中9件が存在しないシーンを参照しています。

選択時に `showScene()` がシーンを見つけられず return するため、ゲーム体験が途中で止まります。

### P0: 遷移整合性を検証する仕組みがない

現在は typo や未定義 scene ID を起動時に検出しません。

今回のように、多数のリンク切れが残ったままでもページ自体は起動できます。

シナリオが増えるほど問題になります。

### P0: `eval()` による条件評価

現在の `evaluateCondition(condition)` は `eval(condition)` を直接実行します。

コード内に固定された信頼済み文字列だけを扱う試作では即時事故にはなりにくいものの、JSON化、外部編集、ユーザー生成シナリオなどへ進める場合には不適切です。

### P1: アセットが存在しない

画像・音声を読み込む設計はありますが、実ファイルがありません。

現在の見た目と音は製品品質には到達していません。

### P1: フォールバック処理が複雑で未検証

`load.image()` / `load.audio()` を `try/catch` で囲っていますが、一般的なロード失敗は非同期の `loaderror` として通知されます。

したがって同期例外を前提にした catch ブロックの一部は期待したタイミングでは動きません。

RenderTexture を使う代替画像生成、SoundManager の関数差し替えも含め、意図を整理して単純化する余地があります。

### P1: 1ファイルに全責務が集中

`index.html` に以下が混在しています。

```text
HTML
CSS
シナリオ
状態管理
ロード
描画
入力
選択肢
音声
セーブ
設定スタブ
```

試作段階では成立しますが、シナリオと機能が増えると保守しにくくなります。

### P1: セーブ互換性の設計がない

シナリオID変更や flags 構造変更時に既存セーブをどう扱うか定義されていません。

### P2: 画面固定

800x600 固定で、Phaser Scale Manager を利用した FIT / CENTER_BOTH 等の対応がありません。

### P2: テスト・CIなし

自動テスト、scenario validation、GitHub Actions はありません。
