# 前中後衛の戦闘とバトルテスター

導入日：2026-10-14（作品版1.25.0）。現行作品版は1.26.0です。`frontline` はClassic/Gridと共存する第三の方式です。「記録 → 戦闘方式 → Frontline（前中後衛）」から次の戦闘へ適用できます。イベント・遭遇の指定が希望値より優先します。既定はClassicです。

## 操作と射程

町の「隊 → 前中後衛の陣形」で人物ごとに段を選びます。左右順は範囲攻撃の補助設定です。初編集前はGrid陣形を参照し、初編集時に独立した `state.partyFrontlineFormation` へ保存します。以後の加入・離脱・交代は両方の陣形へ同期し、互いの手動編集は上書きしません。

敵への必要レンジは `1 + 行動者のdepth + 標的のdepth` です。depthは前衛0、中衛1、後衛2。横位置・斜め距離・途中のユニットによる遮蔽はこの判定に使いません。味方への支援は段差の絶対値と `allyRange` を使います。通常の「移動」は段を選び、1手番を消費します。左右順は原則維持し、塞がる場合は最寄りの空き位置（同距離は左）へ入ります。

範囲は単体、上下左右4方向、明示指定の周囲8、横1段、同じ横位置の縦1列、陣営全域です。巻き込みと射程を別に表示し、プレビューと取消では状態を進めません。範囲外の標的も確認用一覧に残します。通常画面に格子・座標を常時表示しません。

## ターン開始と自動前進

敵味方混合のAGIキューを全員が一巡した区間が1ターンです。個体の行動開始時には前衛補充を行いません。第1ターンと以降のターン開始時、陣営ごとに前衛の生存者を調べます。前衛がいなければ中衛全員→前衛、後衛全員→中衛を一斉に実施し、直後に再検査します。後衛のみなら独立した2ステップとして記録します。前衛が1人でも生存していれば、その陣営の自動前進は停止します。

敵AIは射程外を理由に段を変更しません。その場で使える技能がなければ防御します。前衛がターン途中で倒れても、その直後の敵手番では進まず、次の全体ターン開始を待ちます。プレイヤーが明示的に選ぶ「移動」は別の行動として維持します。2026-10-15に、敵AIが射程確保のため前衛へ移動していた不具合を修正しました。

第1ターンは前進→開始イベント→先制→通常キュー。以降は状態等のターン終了処理→ラウンド加算→前進→round_startイベント→キュー作成です。各前進は専用イベントと移動反応を通し、反復回数をターン数へ足しません。

## 戦闘不能・離脱と可変行数（2026-10-15）

味方の行数は `battle.frontline.rows`（1〜3）へ保存し、敵は常に3行です。全体ターン開始の前進では、生存者全員の進入先を先に確保します。重なる戦闘不能者だけが同行の最寄りの空き横位置（同距離は左）へよけ、同行が満員なら後方の行へよけます。各一歩の反復を終えた後、独立した縮小処理で味方の最も後ろの生存者の行までを残します。削除行の戦闘不能者だけが離脱し、残った行の戦闘不能者は保持します。前衛が存在して前進しない場合も縮小を判定します。

`battle.frontline.removed` は個体キー→離脱理由（`defeated / shrink / skill`）です。最後の座標は履歴として残しますが、離脱者は占有・技能対象・行動キュー・生存数・勝利時の経験値受給から除きます。HPを残した直接排除にも対応します。戦闘終了後は戦闘内の離脱指定を破棄し、人物のHP・MPは通常どおり保持します。

味方生存者が1人だけの間は任意後退を拒否します。グリッド内の戦闘不能者への明示的な復活効果は元位置で復活させ、行数を増やしません。その後、複数生存者がいる状態で合法な任意後退をすれば、移動先まで2行・3行へ拡大します。以前の離脱者は復帰しません。ノックバック自体では拡大しません。

敵定義の `frontlineDefeat: "remain"` を指定した敵だけが撃破後に戦闘不能として残ります。省略または `"remove"` は撃破時排除です。残留敵にも前進時の退避を適用します。敵の生存者が0人になった時点で勝利し、残る戦闘不能者の排除は要求しません。撃破・排除の戦績は個体ごとに一度だけ記録し、復活後の再撃破で重複計上しません。

技能の `frontlineTargeting.targetStates` は `['alive']`（省略時）、`['down']`、または両方を指定します。状態条件と技能効果は独立しており、戦闘不能者へのMP回復・状態付与等を自動で排除へ置き換えません。離脱者を対象にする指定はありません。復活は `targetStates: ['down']` と既存の `heal` 効果を組み合わせます。

専用効果 `{"type":"frontline_remove"}` はHPを変更せず排除します。`{"type":"frontline_knockback","distance":1,"collisionDamage":25}` は指定された段数だけ後方へ一段ずつ押し、現在の陣地外・人物（戦闘不能者を含む）・衝突物体にぶつかった時点で止めます。追加ダメージは押された本人だけに入り、衝突先はよけず、損傷しません。後衛へ到達しただけでは端との衝突になりません。この例の数値は検証用であり、本編の採用値ではありません。専用効果はClassic/Gridでは使用不可です。

遭遇の `frontlineObjects` は衝突検証用の固定配置 `[{"id":"rock","side":"enemies","depth":2,"lane":2}]` を指定できます。今回の物体はノックバック衝突の判定点で、通常移動を妨げる地形・耐久値・破壊処理・画像素材は未実装です。`frontlineDown` は開始時から戦闘不能にする個体キーの配列です。テスターの「開始時」「撃破時」設定はこれらの同じCore定義へ変換します。本編の既存遭遇や敵には一括適用しません。

保存には行数・離脱者・衝突物体・各イベント時点の参加状態を含みます。新形式の不正な行数、占有重複、存在しない離脱者等は拒否します。これらの項目がすべて欠ける同内容版の旧Frontlineセーブだけは3行として補完し、旧仕様で重なっていた戦闘不能者を空き位置へよけます。生存者・キュー・乱数・イベント番号を維持し、読込時に前進・縮小・技能を再実行しません。

## 技能・遭遇の設定

正本は `config/jobs.json` の `frontlineProfiles` と `battle.frontlineWeaponRanges` です。通常攻撃を除く87技能の専用プロファイル（導入時75技能と購入技能12件）と、通常攻撃の武器9種のレンジを生成し、Gridの `targeting` と射程表を変更しません。初期の既存技能は従来の単体／陣営全体を保持します。数値の実戦バランス調整は継続です。

```json
{
  "aim": "unit",
  "range": {"min": 1, "max": 3},
  "allyRange": {"min": 0, "max": 2},
  "area": {"shape": "cross4"},
  "friendlyFire": false,
  "maxAffected": 5,
  "resolution": "sequential",
  "order": "front_to_back",
  "reevaluate": "alive",
  "damageSeries": {"mode": "decrease", "basis": "power", "start": 1, "step": 0.25}
}
```

`frontlineTargeting` として技能に格納します。`aim=cell` は `front:enemies:depth,lane` または `front:allies:depth,lane` で地点を指定します。空地点も範囲に有効な対象がいれば選択できます。

1. `area.shape` は `single / cross4 / around8 / row / column / side_all`。斜め単独・斜め直線はありません。
1. `resolution` は `simultaneous / sequential`。同時は攻防能力・耐性・防御・命中・クリティカル確率を開始時に固定し、全適用後に反応。逐次は一体ごとに反応し、後続命中中止要求が成立すれば停止します。
1. `order` は `front_to_back / back_to_front / left_to_right / right_to_left`。同順位は横位置／段、陣営、個体IDで決定します。
1. `reevaluate=alive` は指定した対象状態（省略時は生存）、`position` は対象状態と開始時位置を各逐次命中前に確認します。新しい対象の補充はしません。
1. `damageSeries.mode` は `constant / decrease / increase`。命中順i（0始まり）の係数は `max(0, start ± step × i)`。
1. `basis=power` はSTR/INTと固定威力を係数倍してから既存式へ渡します。`final` は最初の命中で得た防御・耐性適用後の値を基準にし、後続対象ではその値を係数倍します。後続対象固有の防御・耐性では再計算しません。命中判定は対象別です。

遭遇の `frontlinePositions` は敵出現順の `{depth,lane}` 配列です。省略時は決定的な配置順で初期化します。敵15体を上限とし、同じ陣営の参加個体（生存・戦闘不能）が同じ位置を占有する配置は拒否します。

`frontlineReactions` は次のように定義します。

```json
{
  "enemy:enemy_0": [
    {"on": "onHit", "skill": "guard", "cancelRemaining": true}
  ]
}
```

`onHit` は攻撃・スタン・MP攻撃の命中後、`onAdvance` は各一歩前進後です。生存・行動可能・技能権限・費用・射程を確認し、共通の技能効果を実行します。反応から反応は再帰発動しません。同時攻撃の反応は適用済みの他対象を取り消しません。かばうは直交隣接する単体対象に限ります。

## 画像と保存

敵画像はアルファ値から可視領域を測り、その領域を縦横比を保って描画します。同段の集団は可視幅の約33%を隣と重ね、画面幅に収まる共通縮小率を使います。足元基準、前中後衛100/85/70%、後衛から前衛の描画順です。画像面積は命中判定へ使いません。隠れた敵も名前・段・HP付き対象一覧から選べます。

戦闘内の位置・ラウンド開始済み番号・反応定義・最大512件の診断イベントを保存します。戦闘方式はロード時に再決定しません。1攻撃の費用支払い・全命中・反応は原子的で、途中セーブはありません。テスターの命中別表示はCoreが確定済みの結果の再生です。再生で乱数・費用・行動機会は再消費しません。

## 独立テスター

[バトルテスター](../../battle-tester.html)を `npm run serve` のHTTP配信から開きます。外部CDNやAPIキーは不要です。本編の保存領域へアクセスしません。

編成欄で味方／敵1〜15体、段、左右順、能力、HP/MP、通常攻撃レンジ、状態、被弾反応を設定します。後衛のみ、前衛0、前衛＋後衛、同段5体、異なる画像幅、4方向と斜め、割り込みのプリセットがあります。設定攻撃は実GameEngineの技能として追加し、Coreの対象計画と効果処理を呼びます。

「攻撃者」でプレビュー対象を切り替え、実行は実際の手番の個体だけ許可します。「1手番」は味方の防御／行動不能処理、敵の実AIを1枠進めます。「次のターン開始まで」で一巡を進めます。先制も共通キューの追加行動です。通常のゲームでは敵行動を自動進行し、詳細検証だけ `manualTurns=true` で敵の手番でも停止します。

各命中・反応・中断・前進のイベントを選ぶと、その時点のHPと位置で表示します。仮想グリッドは診断スイッチでのみ表示します。シード、キュー、ラウンド、レンジ、対象、HP変化、前進回数を確認でき、Reset・戦闘保存再開・ケースJSON入出力に対応します。戦闘不能者の退避→縮小、復活→拡大、2行でのノックバック、残留敵のプリセットを追加しました。「検証：」で始まる復活・排除・ノックバック・戦闘不能者のMP回復技能は、詳細検証と実エンジン試遊の両方で使えます。本編の技能追加ではありません。Classic/Gridも同じエンジンの比較対象として開始できます。

### 本編の戦闘画面で試す（2026-10-15）

[バトルテスター](../../battle-tester.html)上部の「実エンジンで試遊」「詳細検証」「両方表示」で画面を切り替えられます。「この編成で開始 / Reset」は両画面を開始し、「設定を実エンジンへロード / Reset」は入力中の編成・方式・シード・先制・状態・攻撃設定を試遊画面だけに読み込みます。編成を変えた後は再ロードしてください。画面の切替だけでは進行をリセットしません。

試遊はダンジョンテスターと同じiframe方式で、[実エンジン試遊ページ](../../battle-engine-playtest.html)に実際の `GameEngine` と本編の `SceneView`／`GameView` を生成します。「背景内表示」「従来表示」は進行を保ったまま切替可能です。通常のコマンド・対象プレビュー・決定・取消・移動・逃走・勝利報酬を操作でき、敵の手番と敵先制は本編と同様に自動処理します。設定した状態異常は敵の最初の行動より前に適用します。独立ページでは既定編成で始まり、再戦ボタンを利用できます。

詳細検証は引き続き手動で各個体を進める方式です。試遊と詳細検証の戦闘状態は独立しており、一方を操作しても他方の進行は変わりません。試遊の画面には指定した重なり率・段倍率を適用し、Grid比較でも入力した味方配置を使います。通常の冒険セーブは読み書きしません。
