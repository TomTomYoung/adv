# 灯番：油と種火のクラス仕様

採用方針の決定日: 2026-10-11。本書は、灯番へ追加する役割と技能の方向、未確定の詳細、現行実装との差をまとめる。採用方針を実装済みの機能として扱わない。

既存の灯番 `lantern_keeper` を、油による攻撃・補給・取得と、MPによる種火生成を担うクラスへ拡張する。別の重複クラスIDは作らない。

火・火台・油の役割、通常の火の生成と移火の関係は [火の仕様](../dungeons/FIRE_SYSTEM.md) に従う。本書では灯番の技能と、その例外となるMP種火の生成経路を定める。

## 採用する三系統の技能

下表の系統名は設計上の分類であり、個々の技能の正式名称ではない。

| 系統 | 採用する機能 | 条件・バリエーション |
| --- | --- | --- |
| 油を用いる攻撃 | 油を消費して敵を攻撃する | 消費する油、攻撃の効果・対象・威力を技能ごとに定める |
| 油の回復・生成・取得 | MPを使って油を回復・生成する。別の技能では敵を攻撃し、敵の種類に応じた油を得る | HPを使う型、水辺で使用する型など、費用・利用場所が異なるバリエーションを設ける |
| MPによる種火生成 | 油を使わず、MPで効果を持つ種火を作る | 戦闘中は発動時にその場で効果を発揮し、戦闘外では火台へ移して使う |

MP使用、HP使用、水辺限定、敵への攻撃は、それぞれ技能の方式・変種を表す。全ての灯番技能へ同時に要求する共通条件にはしない。どの技能へどの条件を割り当てるかは別途定める。

## 油を使う・増やす・敵から得る

油を用いる攻撃は、火を維持するための油を戦闘にも使う技能として扱う。油の種類と攻撃効果の具体的な対応、消費量、MP等の追加費用は未確定である。

油の回復・生成は、MPなどの費用を払って油を確保する技能とする。回復・生成先を所持品の油にするか、火台に入っている油にするかは、まだ定めていない。HP使用型・水辺限定型などの変種についても、支払いと使用条件を技能ごとに定める。

敵からの取得は、敵を攻撃し、その敵の種類に応じた油を得る、盗む行為に近い能動技能とする。取得できる油を全ての敵で同じに固定せず、敵種との対応を持たせる。攻撃の成立と取得の成功を同じ判定にするか、取得だけ別に判定するかは未確定である。

戦後の通常ドロップとは発動の契機が異なる。攻撃による取得と戦後ドロップで同じ取得枠を使うか、敵1体から何回得られるか、取得済み状態をどう保存するかも別途定める。

## 油を使わないMP種火

### 生成経路

灯番はMPを消費し、油を使わずに種火を作れる。この種火は、通常の「火台の固有効果＋最後に給油した油の効果」による新規生成とは別の経路で作る。

MP種火には、その技能によって定まる効果を持たせる。種火を作るために火台と油の組み合わせを要求しない。くらがり避けの種火を設け、その他の種火の種類・具体的な効果値やMP費用は別途定める。

### 戦闘中の発動

戦闘中は、技能が発動した時点でその場に種火の効果が生じる。くらがり避けの種火であれば、発動前に周囲の火による守りがない状態からでも、くらがりを逃走させられる。

これは「発動した種火の効果がその場で働く」という仕様である。技能を選べる行動順、通常の1行動を使うか、敵の行動へ割り込めるかは未確定とする。くらがり以外の敵や、複数種類の敵が同時にいる場合の対象範囲も別途定める。

### 戦闘外の移火

戦闘外では、作った種火を固定火台または携行火台へ移して使う。移火先では種火の効果をそのまま適用し、移火先の火台固有効果や油の効果を加えて再合成しない。

種火生成に油を使わないことと、移火先の燃料を満たすことは別の処理である。MP種火を移しただけで移火先の油や燃料が満タンになることは、この仕様では定めていない。移火後の火を維持するための燃料条件、油がない火台への移火可否、消火後の残油などは別途定める。

戦闘で使った種火が終了後にも残るか、探索へ持ち出せるか、一つの種火から何回移火できるかも未確定である。

## 具体化する事項

| 項目 | 未確定の詳細 |
| --- | --- |
| 技能の名称と習得 | 正式名称、技能数、習得Lv、既存技能と合わせた習得構成 |
| 費用 | MP・HPの消費量、油攻撃の油消費量、費用の併用・代替、失敗時の支払い |
| 油攻撃 | 攻撃倍率、属性・追加効果、対象と範囲、油の種類による違い |
| 油の回復・生成 | 所持油と火台油のどちらを対象とするか、生成する油の種類、回復・生成量、上限 |
| 敵からの油取得 | 油と敵種の対応、攻撃と取得の成否の関係、成功率、取得量、1体からの取得回数、通常ドロップとの関係 |
| 使用場所 | 水辺の判定基準、各変種を使える場所、戦闘中・戦闘外の対応範囲 |
| MP種火の発動 | 種火の種類と効果、通常の行動消費、行動順や割り込み、混成戦闘での対象 |
| 移火後の維持 | 移火先に必要な燃料、油切れ時の扱い、消火後の残油、火の継続条件 |

これらの数値・条件には、現行のMP3・4、携帯火90歩、Lv1・5・10などを自動的に引き継がない。後述の数値は現行実装を識別するための記録である。

## 現行実装との差

確認対象は作品版1.25.0。現在の職業・技能の正本は [config/jobs.json](../../config/jobs.json)、共通の費用と許可判定は [jobs.js](../../src/core/jobs.js) にある。

| 対象 | 現行の実装 | 採用方針との差 |
| --- | --- | --- |
| 灯番の油攻撃 | 灯番に油を消費する攻撃はない。錬金術師の `fire_mix`「爆炎調合」にはMP5＋予備灯油1個による全体炎攻撃がある | 材料消費による攻撃の共通基盤はあるが、灯番への追加と油別の扱いは未対応。[技能原稿](../../config/jobs.json)、[戦闘処理](../../src/core/battle.js) |
| 油の回復・生成 | 油を出力する技能はない。探索の `inventory.convert` は材料・MPから別の品物を作るが、検証で空でない素材入力を必須とする | MPだけで油を作る方式は定義の追加だけでは対応しない。油を回復・生成する対象と共通処理を定める必要がある。[変換処理](../../src/core/jobs.js)、[入力検証](../../src/core/job-validation.js) |
| 攻撃による油取得 | 敵種ごとの戦後ドロップはある。戦闘技能で敵から油を取得する効果や、盗むための共通処理はない | 攻撃時の取得判定、取得可能な油、回数・保存の扱いが未対応。[報酬定義](../../config/battle-rewards.json)、[戦後報酬](../../src/core/battle-results.js)、[技能効果の一覧](../../src/core/jobs.js) |
| 探索でのMP点火 | `fire.kindling` は携帯松明や消灯火台を直接点火し、燃料を容量いっぱいにする。保持種火を生成する処理ではない | 油不要の種火生成と、種火の移火・燃料維持を分ける新仕様に未対応。[火の処理](../../src/core/systems/fire-network.js) |
| 戦闘でのくらがり撃退 | `repel_kuragari` はMP3を使い、携帯火をくらがり除け・90歩にして撃退終了する。現在の行動者の番に使う | 発動時の撃退はあるが、生成した種火を戦闘・探索で扱う共通経路ではない。[戦闘処理](../../src/core/battle.js)、[携帯火の点火](../../src/core/systems/fire-network.js) |

現行の灯番にはHP回復、味方への庇護、光属性攻撃と、旧灯油ゲージの節約もある。`lightSaveEvery: 3` は油を増やす効果ではなく、篝火の `fire_network` の燃料節約にも適用されない。現行一覧は [職業システム](JOB_SYSTEM.md)、火の動作の詳細は [火の仕様の現行実装](../dungeons/FIRE_SYSTEM.md#現行実装) を参照する。

q001のくらがり戦は、終了前の `win`・`escape`・`repel` を新人の救援イベントが捕捉する。MP種火による発動時の撃退を導入するときは、この固定救援と結果・演出・帰還封印の解除を整合させる。現行イベントが新しい種火仕様へ対応済みとは扱わない。[q001原稿](../../authoring/story-q001.mjs)、[篝火のイベント戦闘](../dungeons/KAGARIBI_DUNGEON.md#老人同行中の消灯はイベント戦闘)。

## 文書と実装の保守

本書は採用方針を記す手書き文書である。[JOB_SYSTEM.md](JOB_SYSTEM.md) の `generated:jobs` 区間は現行の職業・探索技能から生成する一覧なので、本書の未実装方針を実装済みとして書き込まない。

実装時の正本は [config/jobs.json](../../config/jobs.json)。[build-jobs.mjs](../../tools/build-jobs.mjs) が配布データへ反映し、[build-docs.mjs](../../tools/build-docs.mjs) が職業一覧の生成区間を更新する。新しい取得・種火・燃料の状態を導入する場合は、共通処理、入力検証、保存・再開と表示の契約も合わせて整備する。
