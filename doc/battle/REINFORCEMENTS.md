# 有限増援と根留め

2026-10-23、内容版1.31.0。Classic / Grid / Frontlineの共通Coreに有限の増援を追加しました。採用箇所は[庭園10Fの大剪定虫](../dungeons/GARDEN_SHALLOW_ROUTES.md)です。

## 登場条件と手番

遭遇の `reinforcements` は登場順の配列です。各行は一回だけ使用します。`id`、`enemy`、最短の `round`（2〜1000）を持ち、初期個体の `afterDefeat`（HP0）と `whileAlive`（生存）を任意指定できます。個体参照は `enemy_0` の形式で、後続増援を条件にできません。`position` は敵陣のGrid座標で、Frontlineではlane=x、depth=2−yへ変換します。

巡末の毒・勝敗・状態更新を終え、巡を進めた直後、Frontline自動前進と `round_start` イベントより前に判定します。その時点で条件を満たす先頭行から追加し、条件未成立・生存数5・空きなしの場合はその行以降を次の巡へ持ち越します。初期編成と予定増援の合計は15体以下、増援を持つ初期編成は5体以下です。既存の増援なしテスターの多人数編成は制限しません。

登場した敵には末尾の新しい `enemy_N` を付け、死亡個体のIDを再利用しません。巡のAGIキューを作る前に追加するため、その巡に一度だけ通常の手番を持ちます。先制を再抽選せず、配置にも乱数を使いません。全敵が倒れた時点で即勝利する従来動作を保ち、未登場の予定敵を待ちません。

## 配置・報酬・保存

指定セルが占有されていれば既存の敵セル順で空きを探します。Gridは生存者、Frontlineは生存者・残留した戦闘不能者・敵側オブジェクトを避けます。配置後のFrontline自動前進は通常どおり処理します。

戦闘は登場済みの増援IDと登場巡を保存します。読込時に遭遇の予定配列と順番・回数・巡を照合し、初期編成と登場記録から実在する敵を復元して能力・個体ID・配置・キューを検証します。Frontlineの過去履歴には、その巡までに登場した個体だけが必要です。後から過去の履歴へ増援を追加しません。

EXP・G・技能宝石・宝箱抽選は登場した編成だけを対象にします。勝利リザルトにも登場記録を引き継ぎ、レベルアップや宝箱の途中で保存しても再配布しません。本体を先に倒して蜂を呼ばなかった場合、蜂の報酬はありません。

## S15 根留め

庭園10F種床設備の修理後、町の技能教習所で人物別に180宝石を払い、樹術師（druid）が杖・道具で使えます。MP8、敵最大2体、地属性の基礎式 `max(2, 0.5INT + 6)`。Classicは遭遇順、Gridは十字、Frontlineはcross4の範囲です。射程は1〜5です。

Grid/Frontlineでは使用した巡の自発移動を止めます。Frontlineでは次の巡の自動前進も一回止め、その処理後、次の行動キューが始まる前に解除します。拘束されていない生存者は移動先が空いていれば前進し、拘束者のセルへ重なりません。強制ノックバック・戦闘不能者の退避は拘束対象外です。Classicでは同じ期限まで命中率を10ポイント下げ、0未満にはしません。同じ補正は重複加算しません。

補正は技能・付与元・対象・残り巡数を既存のバフ保存形式で検査します。移動の候補表示、実行、Grid敵の接近判定は同じCore関数を使います。[UI基本哲学](../ui/BASIC_PHILOSOPHY.md)に従い、移動できない理由を候補に出します。

`tests/garden-boss.test.mjs` は3方式の登場・延期・上限・配置・手番・保存・報酬、未登場勝利、移行、設備と購入・根留めを検証します。実攻略の24条件は[測定JSON](../development/GARDEN_BOSS_MEASUREMENTS.json)です。
