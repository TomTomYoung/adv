# 地下水道・廃坑の固有設定

更新日: 2026-09-14。現行作品1.8.0に含まれる仕様です。導入版は1.6.0。

出典は、ユーザー指定の[灯守の地下水道](https://app.notion.com/p/3dac3c1966b381f6b53ef67b31a65ebf)と[塩哭きの廃坑](https://app.notion.com/p/3dac3c1966b3810e8954cf22aeaafc13)です。2026-09-14に取得した「ダンジョン固有設定」を実装しています。Notion本文は編集していません。

1. 原文の要件と実装範囲

地下水道では、時間によって区画が水没し、完全水没した区画を通れなくすること、水路は基本的に通行不可とし、水門・バルブによって止水と通水を操作できることが要件です。既存の2階層に周期で水没する区画を各1か所、操作で渡れる横断水路を各1か所追加しました。

廃坑では、戦闘によって装備に−1が累積する腐食を生じさせ、当面は退出時に回復させること、対応するスキル・アイテムが必要な破壊壁を置くことが要件です。既存の2階層に破壊壁を各2か所設け、装備の実際の能力補正へ腐食を適用しました。

現在は13ダンジョン、10地域、26マップ、200クエストです。地域1のregion_1と篝火の迷宮kagaribiは別のダンジョンです。今回追加した処理はregion_1・region_2の定義で有効化され、他のダンジョンへ影響しません。

2. 地下水道の時間と水位

時間の単位は探索行動に対応する「刻」です。成功した1マス移動、1刻待機、成立した水門・バルブ操作で1刻進みます。現実の経過秒数には依存しません。回転、通行不能なマスへの移動、成立しない操作、会話、戦闘、メニュー表示、セーブとロードでは進みません。

初期周期は干潮12刻、増水6刻、満水8刻、減水6刻の計32刻です。各段階の長さ・名称・水位はphasesから変更できます。水位0は水なし、水位1は浅い水で通行可能、水位2は完全水没で通行不可です。現在の段階と、次の段階までの残り時間を探索画面に表示します。

周期水域はkindがtidalです。接続する水門が開いている場合だけ、周期に従って水位が変わります。水門を閉じると止水・排水され、その水域は水位0になります。水門を再び開くと現在の周期に対応する水位へ戻ります。

水路はkindがchannelです。接続するバルブが開いていると水位2、閉じると水位0になります。潮位とは別に制御します。controlを省略した水路は常に水が流れる通行不能区画として定義できます。

水門・バルブの操作は足元か正面から行います。別階層の装置、離れた装置、すでに目的の状態になっている装置を操作しても状態・時刻は変わりません。装置の位置を調べると、専用パネルに操作ボタンが表示されます。

水没判定は移動後にも更新します。足元が完全水没した場合は、増水直前に通れた通路をたどり、最寄りの水没していない足場へ退避させます。閉じた扉や元から水没している別の水路を横切りません。退避は歩数、イベント、遭遇、報酬を追加で発生させません。原文に溺水ダメージの指定はないため、HPへの追加被害はありません。

作者が全退路を塞ぐ地形へ変更した場合に限り、既存の帰還印で救出します。この場合の費用は既存の緊急帰還の計算を使います。配布する水域では通常の足場へ退避できます。入口、既存イベントのマス、操作盤に水域を重ねる定義は検証で拒否します。

水没区画は測量図で青く表示し、≈で識別します。浅い水は~、水門は門、バルブは弁です。疑似3D表示も水没した通路を青い水面の模様で区別します。未踏査の装置や区画はマーカーとして公開しません。

3. 地下水道の初期配置

上層の周期水域はregion_1_f1の(3,2)、(3,3)、水門は(2,1)です。横断水路は(4,3)、バルブは(2,3)です。下層の周期水域はregion_1_f2の(5,5)、(6,5)、(7,5)、水門は(2,1)です。横断水路は(6,1)、バルブは(5,2)です。

装置は初期状態で開いています。水路は初めから通行できません。水路2マスは既存の壁を横断する追加の通路であり、既存の階段・クエスト対象・鍵扉を削除しません。

水位時刻は同じ探索中の階層移動で保持し、町から入り直すと干潮の先頭へ戻ります。水門・バルブの開閉状態は退出後も保持します。セーブとロードでは両方ともそのまま再開します。

4. 廃坑の装備腐食

腐食は戦闘開始時に1回適用します。通常遭遇とシナリオ戦闘の両方が対象です。逃走や敗北でも、開始した戦闘による腐食は取り消しません。戦闘ターンや敵の数では増えず、戦闘中のロードでも再加算しません。不明な遭遇IDによる失敗では加算しません。

戦闘開始時に生存する出撃隊員が装備している装備IDを集め、それぞれの腐食量へperBattleを加えます。初期値は1です。武器、防具、装飾品が対象です。装備が持つ正の能力補正それぞれから累積量を引きます。例えばstr+5の剣は5戦で±0、6戦で−1になります。装備していない能力項目を追加で減らす処理はありません。元データのitemsは変更せず、能力計算時に適用します。

最終能力値の下限は既存ルールを使い、最大HPは1、その他は0です。ローブや杖の最大MP補正などが減った場合、現在HP・MPを新しい最大値までに収めます。腐食が解除されても、この調整で減った現在HP・MPを自動回復する処理はありません。

現行の装備は個体番号を持たず、所持品は装備IDごとの個数で管理します。その構造に合わせ、腐食も探索内の装備IDごとに共有します。同じ種類を複数人が装備していても1戦で重複加算しません。同種の予備へ持ち替えたり、別の人物へ渡したりしても、その種類の腐食は維持されます。個体別耐久度へ拡張する際は、先に所持品・装備・セーブを個体管理へ移行する必要があります。

腐食は廃坑内の階層移動で保持します。通常帰還、帰還印、敗北による救助、別ダンジョンへの移動で適用を終了し、次の廃坑探索は腐食なしで開始します。探索画面には装備名と累積した腐食量を表示します。

5. 破壊壁と使用手段

壁は初めは通常の壁と同様に通行できません。足元・正面の対象判定、未破壊であること、壁が許可したアイテム・スキルであることを確認してから破壊します。スキルでは現在の職業・習得レベル・出撃・生存・MP・追加材料の条件も確認します。

初期の消費アイテムは発破薬です。町の旅支度の店で基準価格25G、1回の破壊に1個使います。商人の既存割引が適用されます。壁の正面に立つと探索画面の破壊壁パネルから使用できます。

探索スキルは岩砕きです。戦士・拳闘士がLv1で使用でき、消費はMP3です。隊員の探索特技欄、または破壊壁パネルから使用します。双方が同じ事前検査・支払い・破壊処理を通り、消費は1回です。攻撃や炎など既存の戦闘技能を、探索用とみなして自動流用することはありません。

破壊済みの壁へ再度操作した場合や、対象が遠い・所持品がない・MPが足りない場合、消費は発生しません。壊れたマスは実際に歩ける床となり、疑似3Dと測量図も更新します。開いたマス上での保存・再開が可能です。破壊状態は階層移動と退出後も保持します。

初期配置は上層region_2_f1の(6,1)、(3,6)、下層region_2_f2の(6,1)、(10,9)です。すべて内壁の短絡路で、既存のクエスト対象や鍵扉の座標を変更しません。マーカーは未破壊が砕、開通済みが◇です。

6. 編集元と再生成

地下水道はauthoring/dungeons/region_1.jsonのsystems.water、廃坑はauthoring/dungeons/region_2.jsonのsystems.saltとsystems.wallsが編集元です。周期、水域、装置、初期開閉状態、腐食量、破壊壁、許可するアイテム・探索スキルをJSONで変更できます。useを指定する部品はwaterworks、corrosion、breakable_wallsです。同じ部品を別ダンジョンで使う場合も、所属マップに合わせた定義を置きます。

水路の床化、発破薬、販売価格はauthoring/terrain-content.jsonに置きます。岩砕きのコスト、習得職、習得レベルはauthoring/jobs.jsonに置きます。

ダンジョン定義・配置・道具の変更後は次を実行します。

```sh
npm run build:dungeons
```

職業・探索スキルも変更した場合は次を実行します。

```sh
npm run build:jobs
```

形式を拡張した場合はtools/build-schemas.mjsも更新し、次でSchemaを再生成します。

```sh
node tools/build-schemas.mjs
npm run check
```

build:scenariosの最終段階にもダンジョン生成を含みます。dataだけを手修正すると、次の再生成で原稿の値へ戻るため、作者の変更はauthoringへ反映してください。build:jobsが1.2.0の移行定義を再作成するとき、既存のクエスト一覧と旧経路フラグを保持するよう修正しました。

7. コードと保存

src/core/dungeons.jsのレジストリとライフサイクルを拡張し、部品ごとの地形、通行禁止理由、装備補正、戦闘開始、探索スキルの接続を追加しました。固有処理はsrc/core/systems/waterworks.js、corrosion.js、breakable-walls.jsに分離します。共通の距離・座標・表示可否の補助はcommon.jsです。

探索中の時刻はstate.dungeons.active.systems.water.elapsed、腐食はactive.systems.salt.wearです。水門の開閉はpersistent.region_1.systems.water.controls、破壊壁はpersistent.region_2.systems.walls.brokenへ保存します。runとpersistentの用途は[DUNGEON_SYSTEM_DESIGN.md](DUNGEON_SYSTEM_DESIGN.md)に従います。

内容版1.5.0からは、当時の部品構成として保存を検証し、新しく追加された部品の状態だけを補います。篝火の燃料・種火・台座、探索番号、地図、装備、所持品、クエスト、会話・選択・戦闘、乱数の位置は保持します。1.4.0以前の移行も維持します。1.6.0の保存で新しい部品が欠落した場合は、旧版として補完せず拒否します。

8. 検証と実装上の判断

現行の全体検証は[PROGRESS.md](PROGRESS.md)を参照してください。水位・操作・腐食・破壊・保存・投影と実行の一致を継続して検証しています。

build:jobsとSchema再生成の前後で全data JSONのハッシュが一致しました。データ参照、静的ファイル、モジュール参照、ビュー分離の検査も成功しました。

時間単位、周期の長さ、増水時の退避、同種装備の腐食共有、岩砕きの習得職・コスト、発破薬の価格、壁の配置と破壊状態の永続化は、原文に詳細がないため今回具体化した内容です。既存クエストの物語状態と今回の探索装置は別の状態として扱い、シナリオ本文や結末条件を変更していません。

クラウドブラウザはローカルHTTP接続をERR_BLOCKED_BY_CLIENTで拒否したため、ブラウザでの視覚・クリック確認は未完了です。操作可否と動的地形の表示用データはテストで確認しています。

現在は水門・塩壁の現地調査からq010・q011の手帳へ観察を記録できます。[素材と現地調査](DUNGEON_ART_AND_SCENARIOS.md)を参照してください。

## 1.8.0の貯水立坑

従来二階層の周期水位は上記仕様を維持します。地下水道の入口から入れるwaterworks_shaftは、六面の通水と立方体の容量で水を計算する別区画です。この区画では周期水位のパネルを表示せず、給水ポンプ・水門・排水蓋と実際の水深を表示します。水門を閉じたときの残水は保持されます。

立坑には高さ-1・0・1の排水縦坑・貯水室・橋を配置しました。完全水没した下の空間と、乾いた橋上を区別します。梯子、縄の設置、登攀誘導、密の立方体の掘削を利用できます。[仕様と操作手順](VOXEL_TERRAIN_AND_WATER.md)を参照してください。
