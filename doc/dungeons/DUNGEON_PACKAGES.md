# 配置物の標準パッケージ

2026-10-12。見た目・設置主体を、取得処理・サービス機能から分離する。新しいイベント実行系を増やさず、既存の配置物、調べる操作、通常スクリプト、location/service、ショップ、持ち物を使う。

## トレジャー

配置物の `treasure` に指定する。`kind` は `chest`（宝箱）、`remains`（冒険者の遺体）、`bookshelf`（本棚）、`pot`（つぼ）、`harvest`（採取）。これらは同じ取得処理を使い、配置物の名前・説明・画像と機能を分ける。

```json
{
  "kind": "harvest",
  "rewards": {"items":{"rope":1},"gold":3},
  "random": [{"weight":1,"rewards":{"items":{"torch":1}}}],
  "uses": 2,
  "reset": "reentry",
  "requiredItem": "torch",
  "afterText": "ここにはもう採れるものがない。"
}
```

`rewards` は毎回の固定報酬、`random` は重み付きで一つ選んで加算する報酬。空の報酬も指定できる。取得条件 `condition`、消費しない必要道具 `requiredItem`、取得回数 `uses`、取得後説明 `afterText` を共通化する。未成立・容量不足では抽選も回数消費もしない。抽選のどの候補が出ても入る容量を先に確認し、満杯での抽選し直しを防ぐ。

`reset` は `never`／`reentry`／`manual`。`manual` のものだけ `treasure.reset` 命令で再装填できる。時間による自動再生は導入していない。採取技能・道具消費・時間再生等を追加する際は、資源点として独立させる必要を再評価する。

取得は `state.events["treasure/<map>/<object>"]` で記録し、所持金と品物の付与と同じ処理内で確定する。受取品は共通袋へ入る。`trap` に標準トラップを併設でき、取得結果を読んだ後にトラップが作動する。結果表示や戦闘途中の保存から再開しても二重取得しない。

取得後は便利調べるの候補から消える。任意調べるでは `afterText` を読める。複数回取得できる場合は残っている間、繰り返し調べられる。原稿の配置物には既存のscript欄を保持できるが、`treasure` を指定した配置物の配布scriptは `treasure.package.<map>.<object>` に生成され、`once:false` となる。取得回数はtreasure側だけが担当する。

篝火の油蔵の「搬送用の工具箱」をこの処理へ移した。縄1本・松明2本、取得済みフラグ、説明は維持する。既存フラグとの接続用 `collectedFlag` は永久1回の取得だけに指定できる。工具箱を取得済みの同版セーブで再取得しない。

## サービス

[config/locations.json](../../config/locations.json) の場所に `package` を指定する。名前・背景・人物・入口は従来のlocationで指定し、サービス機能は下記の組み合わせにする。迷宮内の行商人・キャンプも、セルに立って明示的に施設へ入る既存の操作を使う。

kind：merchant / 生成される機能：通常ショップを有効化。商品・価格・割引・持ち主選択は既存ショップを使用

kind：rest / 生成される機能：指定したサービス。rest設定を置けば休息を生成

kind：camp / 生成される機能：指定したサービスと任意の休息。旅支度は既存の持ち物・装備画面

kind：services / 生成される機能：サービスの自由な組み合わせ

```json
{"kind":"camp","services":[],"rest":{"cost":8,"ratio":1}}
```

`services` は既存のservice IDの配列。施療・補給等を同じ枠で組み合わせる。`shop` を明示すれば種別にかかわらずショップの有無を設定できる。`rest` は費用と最大HP/MPに対する回復到達率を指定し、状態異常も解除する。所持金不足では回復・支払いを行わず、再試行できる。生成休息は迷宮内施設でも利用できる。既存サービスの室内利用許可は引き続きCoreで検査する。

町の店、帰り火亭、篝火の詰所をパッケージ表記へ移した。サービス内容・費用・解放条件を維持する。修理・鑑定・倉庫それぞれの新しいゲーム機能まで実装したものではなく、追加する際に共通サービスへ登録する構造とした。

## 生成と残る候補

配置物原稿は迷宮ごとの既存マップ正本へ記入する。`npm run build:dungeons` がセルパッケージ、配置物、場所、サービスの通常スクリプトを生成し、編集画面と文書も更新する。

調べる対象、レバー・水門等の仕掛け、階段・梯子等の移動設備は既存の調査／状態変更／接続を維持する。今回の優先対象はトレジャーとサービス。専用の追加パッケージが必要になったときに同じ方式で拡張する。
