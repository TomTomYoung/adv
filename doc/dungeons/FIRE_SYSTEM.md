# 火の仕様：火・火台・油・種火

効果をもつのは火。火台は火を生成するためのベース、油は消耗品であり、通常の火は火台と油から生成する。

通常の新規生成では、火の効果 ＝ 火台固有の効果 ＋ 最後に給油した油の効果。 基本的には両者を単純に足し、生成時にその火の効果を確定する。

移火と給油は火の生成ではないため、すでにある火の効果を維持する。 給油時に上書きするのは、次回の生成に使う油の効果である。

油は主に照明範囲・燃費・敵避けを担い、固定火台は主にステータスバフを担う。携行火台は消耗しない、かなり希少なアイテムとする。灯番は油による攻撃・油の回復や生成に加え、油を使わずMPで種火を作る別の生成手段を持つ。

### 火・火台・油の役割

要素：火 / 役割と性質：実際に効果を発揮する主体 / 効果の扱い：生成時に確定した効果を、その火が続く間保持する

要素：固定火台 / 役割と性質：ダンジョンに設置された、火を生成するためのベース / 効果の扱い：主にステータスバフを担う。火台ごとの固有効果は固定され、通常の新規生成時にだけ火へ渡す

要素：携行火台 / 役割と性質：松明・行燈・ランプなど、持ち運べるベース。アイテム自体は消耗せず、かなり希少 / 効果の扱い：固定火台と同様、火台ごとの固有効果を通常の新規生成時にだけ火へ渡す。プレイヤーの初期松明はくらがり避けを持つ

要素：油 / 役割と性質：複数種類を用意する消耗品。特殊な追加効果のないプレーン油もある / 効果の扱い：主に照明範囲・燃費・敵避けを担い、通常の新規生成時に火へ渡す。給油では次回生成用の油の効果を追加した油の効果で上書きする

火台と油の「効果」は、火を生成するときの材料を指す。火台や油が、それだけで周囲や戦闘へ効果を発揮するわけではない。固定火台と携行火台には、同じ生成・移火・給油の規則を適用する。

「主に」は効果の基本的な担当を示す。油がステータスへ関係する効果を絶対に持てない、固定火台が敵避けを持てない、という排他的な制限ではない。篝火の迷宮の固定火台は、基本効果としてくらがり避けも持つ。

### 油が担う効果とプレーン油

効果の軸：灯りの範囲 / 油によって変える内容：火が照らす範囲の広さ / 生成した火での扱い：生成時に確定し、移火・給油後もその火が保持する

効果の軸：燃費 / 油によって変える内容：火を維持するための油の消費の良しあし / 生成した火での扱い：生成時に確定し、給油した油を参照して燃焼中に切り替えない

効果の軸：敵避け / 油によって変える内容：敵との遭遇を避ける効果 / 生成した火での扱い：対象となる敵や避け方は効果ごとに定め、その火が保持する

効果の軸：プレーン油 / 油によって変える内容：特殊な追加効果がない基準の油 / 生成した火での扱い：火台の固有効果へ特殊な上乗せをしない

プレーン油に「効果がない」とは、特殊な追加効果がないという意味である。火が照明として機能しない、燃料として使えないという意味ではない。標準の照明範囲・消費量と、各油の具体的な補正値は別途定める。

照明範囲・燃費・敵避けはいずれも、生成後は火の効果として保持する。たとえば省燃費の油で作った火へプレーン油を給油しても、現在の火は省燃費のまま続く。次に新規生成するときには、最後に給油したプレーン油を使う。特殊油で作った火をプレーン油で維持することは、この生成・給油の規則から生じる使い方である。

燃費という性能と、残っている油の量は別に扱う。効果を引き継ぐ移火によって、油の残量や燃料容量まで増えるとは定めない。照明範囲を広げる効果が、敵避けやステータスバフの範囲も同時に広げるかは別途定める。

### 初期松明と篝火の迷宮の基本の守り

篝火の迷宮の固定火台は、基本的にくらがり避けを固有効果として持つ。プレイヤーの初期松明も、ベースである松明自体がくらがり避けの生成用効果を持つ。

通常の新規生成：初期松明＋プレーン油 / 生成される火：初期松明に由来するくらがり避けを持つ火

通常の新規生成：くらがり避けを持つ篝火の固定火台＋プレーン油 / 生成される火：火台に由来するくらがり避けを持つ火。火台固有のバフがあれば、それも持つ

これにより、序盤の火の管理ではまず燃料切れを気にすればよく、くらがり避けを得るために特殊油や効果の組み合わせを選ぶ必要がない。ここでいう「松明切れ」は燃料が尽きて火が消えることであり、携行火台アイテム自体の消耗ではない。くらがり避けは、通常の魔物まで一律に出現しなくなるという意味ではない。

この守りも生成時の効果である。くらがり避けのない火を初期松明や篝火の固定火台へ移した場合、移し先のくらがり避けを後から加えない。序盤の基本となる通常生成と、自分で別の火へ移し替える操作を区別する。

携行火台は、通常の補給で使い捨てる道具ではなく、入手機会の少ないベースとして扱う。初期松明があることと、追加の携行火台がかなり希少であることは両立する。初期松明の入手場面・貸与か所有か・追加の携行火台の入手先は別途定める。

### 生成・移火・給油の違い

操作：火台と油から火を生成する / 火を新しく生成するか：する / 火の効果：その火台の固有効果＋最後に給油した油の効果で確定する / 次回生成に使う油の効果：その時点の油の効果を生成に使う

操作：すでにある火を別の火台へ移す / 火を新しく生成するか：しない / 火の効果：移した火の効果をそのまま保持する。移し先の火台・油の効果は加えない / 次回生成に使う油の効果：移し先が保持している油の効果を維持する

操作：火がついている火台へ給油する / 火を新しく生成するか：しない / 火の効果：現在の火の効果をそのまま保持する / 次回生成に使う油の効果：追加した油の効果で上書きする

操作：灯番がMPで種火を作る / 火を新しく生成するか：技能が定める種火を生成する / 火の効果：技能が定める効果を持つ。油を消費しない / 次回生成に使う油の効果：給油を行う操作ではない

操作：技能で作った種火を火台へ移す / 火を新しく生成するか：移火先では生成しない / 火の効果：種火の効果をそのまま保持し、移し先の火台・油の効果は加えない / 次回生成に使う油の効果：移し先が保持している油の効果を維持する

火台・油の効果を適用するのは、それらを用いて火を新規生成する瞬間だけであり、燃焼中の火の効果を現在の火台・油から再計算しない。火を何度移しても、移し先の火台の効果が積み上がることはない。

給油では、残っている油の効果と追加した油の効果を混合・加算しない。最後に追加した油の効果を採用する。「油の効果を上書きする」とは、火台側が保持する次回生成用の効果を更新することを指し、現在の火の効果や燃料残量を上書きするという意味ではない。

### 生成・移火・別種の油による給油の例

火台X・火台Yと、効果の異なる油A・油B・油Cを使う例。表の「火台X＋油A」などは、生成時に組み合わせた効果を表す。

順序・操作：1. 油Aを用いて火台Xで火を生成する / 火の置き場所：火台X / その火台が保持する次回生成用の油の効果：油A / 現在の火の効果：火台X＋油A

順序・操作：2. 油Bが入った火台Yへ、その火を移す / 火の置き場所：火台Y / その火台が保持する次回生成用の油の効果：油B / 現在の火の効果：火台X＋油Aのまま

順序・操作：3. 燃焼中の火台Yへ油Cを給油する / 火の置き場所：火台Y / その火台が保持する次回生成用の油の効果：油Cへ上書き / 現在の火の効果：火台X＋油Aのまま

順序・操作：4. その後、火台Yで新しく火を生成するとき / 火の置き場所：火台Y / その火台が保持する次回生成用の油の効果：油C / 現在の火の効果：火台Y＋油C

移火後も、給油後も、元の火は生成元の組み合わせを保持する。火台Yと油Cの効果が使われるのは、火台Yで新しい火を生成したときだけである。

### 油の種類を具体化する案

プレーン油の存在と、照明範囲・燃費・敵避けを油が主に担うことは決定事項。以下は種類を詰めるための候補であり、プレーン油以外の名称・組み合わせ・数値・商品IDは未確定とする。

種類：プレーン油 / 生成する火への追加効果の案：特殊な上乗せなし / 使い分けの案：火台固有の効果で火を作る。すでにある特殊な火の燃料補充にも使える

種類：広照油（仮称） / 生成する火への追加効果の案：灯りの範囲を広げる。燃費を悪くする組み合わせも候補 / 使い分けの案：未踏の場所で、広く見渡したいときに使う

種類：長燃油（仮称） / 生成する火への追加効果の案：燃費をよくする / 使い分けの案：長い探索に向く火を作る

種類：忌避油（仮称） / 生成する火への追加効果の案：通常の魔物との遭遇を減らす / 使い分けの案：戦闘を避けて移動したいときに使う。くらがり避けとは別の効果として設計する

種類：防闇油（仮称） / 生成する火への追加効果の案：くらがり避けを付ける / 使い分けの案：くらがり避けを持たないベースでも、その効果を持つ火を作る

種類：対種族の油（分類案） / 生成する火への追加効果の案：特定の種類の敵を避ける / 使い分けの案：相手や探索先が分かっているときに油を選ぶ

広さ・燃費・対象となる敵で使い分けられる組み合わせを検討する。入手量や価格、良い効果と不利な効果を同時に付けるかは、上の候補だけで確定しない。敵から得られる油の種類は、灯番の技能側で敵の種類との対応も定める。

### 灯番の油と種火

灯番は、油を用いる攻撃、油の回復・生成、種火技能を扱うクラスとする。油の回復・生成にはMPを使うもの、HPを使うもの、水辺でのみ使えるものなどを設ける。敵を攻撃して油を得る技能では、攻撃した敵の種類によって得られる油を変える。各技能の費用・条件は技能ごとに定める。

種火技能は油を使わず、MPを消費して技能固有の効果を持つ種火を作る。通常の「火台＋油」とは別の生成経路である。

場面：戦闘中 / 種火技能の効果：技能発動時にその場で効果を発揮する。くらがり避けがない状態でくらがり戦へ入っても、くらがり避けの種火技能を使えばくらがりが逃走する

場面：戦闘外 / 種火技能の効果：生成した種火を火台へ移す。固定火台・携行火台のどちらでも種火の効果をそのまま適用し、移し先の火台・油の効果を足さない

種火を作る際に油を消費しないことと、移火先で火を維持するための燃料条件は別である。種火技能だけで油の残量まで満タンになることは、この仕様では定めない。

クラスの技能系統、未確定の費用・取得量、既存の灯番との対応は[灯番のクラス仕様](../battle/LANTERN_KEEPER.md)を参照する。

固定火台は合計16基。各火台の座標・範囲・初期点灯は [迷宮の専用ページ](details/kagaribi.md) に載せる。容量の単位は油のmLや実時間ではなく、同じ迷宮内で移動に成功した歩数。

同じ予備灯油で点火しても、青銅の火台は「鎮めの火」、赤鉄の火台は「呼び寄せの火」になる。操作名の「普通の火を灯す」は、固定火台では本来の効果による点火を指す。携帯松明を普通に点火した場合は `portable.baseEffect` の「普通の火」になる。

種火を移すと、その火が消えるまで台座本来の効果に優先する。たとえば青銅の火台へ深火を移すと、深火の効果が、その火台の容量80歩・範囲3で働く。種火に採取元の容量や範囲は保存しない。補充は移植した効果を保持し、消火・燃料切れは効果を消す。次に普通に点火すると台座本来の効果へ戻る。

現行の種火が保持するのは効果IDだけであり、油由来の照明範囲や燃費を保存する構造はない。先頭で定めた、生成時の照明範囲・燃費も火とともに引き継ぐ仕様への対応は別途必要となる。

### 点灯状態と燃料の保存

通常の火は次の三つを一緒に保存する。`effect` は火台本来の設定ではなく、現在灯っている火の効果。

```json
{ "lit": true, "effect": "ward", "fuel": 25 }
```

有限容量の点灯中の火は燃料1以上、無期限の点灯中の火は `fuel: null`。消灯中は必ず次の形になる。

```json
{ "lit": false, "effect": null, "fuel": 0 }
```

手動消火も燃料切れもこの消灯状態にする。消灯中に正の燃料を残した保存は `validateState()` が受け付けない。このため、現在は「油が残った器で火だけを消す」「消灯中の器に油だけを注ぐ」という状態・通常操作を扱えない。

定義上の火台本来の `effect` と、保存中の火の `effect` は別。保存中の効果を消しても、火台の定義そのものは変わらない。根拠は [fire-network.js](../../src/core/systems/fire-network.js) の `freshFlame()`、`act()`、`burn()`、`validateState()`。

### 操作と消費

固定火台は配置セルに立って操作する。壁面松明は、その壁が属するセルに立ち、指定された壁を向く。携帯松明は携帯松明の所持を確認する。通常操作は会話・選択待ち・戦闘中には行えない。

操作：普通の火を灯す / 条件：消灯中、利用できる油を所持 / 消費：携行油管理開始前は予備灯油1瓶。管理開始後は必要量までの予備油を優先し、予備油が0なら1瓶 / 結果：本来の効果で点灯する。管理開始前は満タン、開始後の有限火台・携行灯は実際に移した量まで補充する

操作：燃料を補充 / 条件：点灯中、有限容量、未満タン、利用できる油を所持 / 消費：携行油管理開始前は予備灯油1瓶。管理開始後は不足量までの予備油を優先し、予備油が0なら1瓶 / 結果：管理開始前は満タン、開始後は実際に移した量だけ増やす。現在の火の効果は維持する

操作：種火を採る / 条件：点灯中。同じ効果の種火を既に保持していない / 消費：なし / 結果：現在の効果を種火として保持。火元は消えず、燃料も減らない

操作：火を消す / 条件：点灯中 / 消費：アイテム消費なし / 結果：消灯し、現在の効果と残り燃料を消す

操作：種火を移す / 条件：移植先が消灯中、種火を保持。携行油管理開始後は利用できる油も必要 / 消費：種火1個。管理開始前は油不要、開始後は通常点火と同じ油の支払い / 結果：種火の効果で点灯する。管理開始前は満タン、開始後の有限火台・携行灯は実際に移した量で点灯する

操作：灯番の技能で点火 / 条件：習得・使用条件を満たす。固定火台は消灯中 / 消費：技能のMP。予備灯油は不要 / 結果：技能の効果で点灯し、燃料も容量いっぱいにする

携行油管理開始前は、残り1歩を満タンにする場合も、あと1歩で満タンになる状態を補う場合も予備灯油1瓶を使う。管理開始後は予備油を不足量だけ支払うが、予備油がなく瓶を使う場合は1瓶単位で消費し、余りを予備油へ戻す処理はない。無期限の火には燃料補充を行えない。消灯した無期限火台の通常点火・移火は、管理開始後は予備油1単位、予備油が0なら瓶1本を使う。

種火は携帯松明自身からも採れる。保持は1種類で、違う火から採ると持ち替える。同じ効果の再採取は無効。種火の採取や移植で、その火の効果を発現するための油の種類を検査する処理はない。

旅支度から予備灯油を使うと、携帯松明が点灯中なら補充、消灯中なら通常点火になる。固定火台へ補充するときは、その火台を選んで操作する。燃料を購入・入手しただけでは自動補充しない。

灯番は現在職の習得段階、出撃、生存、MP、携帯松明の所持を確認する。固定火台への技能点火でも携帯松明を所持している必要がある。携帯松明は点灯中でも技能で更新でき、固定火台は先に消火する。

灯番の技能：くらがり除けの火 / 習得Lv：1 / 消費MP：3 / 火の効果：`ward`

灯番の技能：鎮めの火 / 習得Lv：5 / 消費MP：4 / 火の効果：`calm`

灯番の技能：呼び寄せの火 / 習得Lv：10 / 消費MP：4 / 火の効果：`lure`

技能によるくらがり撃退は専用の戦闘処理で扱い、通常の魔物には使えない。詳細は [篝火の迷宮と灯番](KAGARIBI_DUNGEON.md)。操作可否と状態変更は [fire-network.js](../../src/core/systems/fire-network.js) の `plan()`・`act()`・`itemIntent`、習得と費用は [jobs.js](../../src/core/jobs.js) と [config/jobs.json](../../config/jobs.json) が根拠。

### 火の効果と重なり

火：普通の火 / くらがり除け：有効 / 通常遭遇率の倍率：1 / 通常敵の能力倍率：1 / 優先順位：0

火：くらがり除けの火 / くらがり除け：有効 / 通常遭遇率の倍率：1 / 通常敵の能力倍率：1 / 優先順位：10

火：鎮めの火 / くらがり除け：有効 / 通常遭遇率の倍率：0.5 / 通常敵の能力倍率：0.6 / 優先順位：20

火：呼び寄せの火 / くらがり除け：有効 / 通常遭遇率の倍率：2 / 通常敵の能力倍率：1.6 / 優先順位：30

火：深火の種火 / くらがり除け：有効 / 通常遭遇率の倍率：0 / 通常敵の能力倍率：1 / 優先順位：40

普通の火もくらがりを遠ざける。普通の火とくらがり除けの火は、通常の魔物の出現を止めない。深火は通常遭遇を抑えるが、物語の固定戦闘を一括で無効化する効果ではない。深火による蘇生は未実装で、伝承の真偽も確定していない。

これは現行の効果定義の説明である。新仕様でのくらがり避けの有無は、生成元のベース・油、または種火技能が持つ効果によって決まり、あらゆる火へ無条件に付けるものではない。

複数の火が届く場合、くらがり除けは一つでも `repels: true` なら有効。通常遭遇率と能力倍率は、届く火のうち優先順位が最大の一つを採用する。同順位では火元IDの英語昇順を使う。携帯松明、固定火台、点灯中の配置イベントの壁灯は同じ候補に入る。倍率を重ねて加算・乗算しない。

通常敵の能力倍率はHP・攻撃・防御・知力に適用し、経験値・所持金や、くらがりの能力には適用しない。深火と呼び寄せの火が重なる場合は深火が優先する。定義は [kagaribi.json](../../config/dungeons/kagaribi.json)、選択は [fireEnvironment()](../../src/core/systems/fire-network.js)、遭遇・戦闘への反映は [dungeons.js](../../src/core/dungeons.js) と [engine.js](../../src/core/engine.js) を参照する。

### 燃料が減るタイミング

同じ迷宮内で移動に成功するたび、点灯中の携帯松明と全ての有限固定火台の燃料を1ずつ減らす。別区画に置いてきた固定火台も対象で、見える範囲だけの消費ではない。区画間の接続を使う移動も成功歩に含まれる。

回転、壁への衝突、会話、選択、メニュー、セーブ・ロード、火の操作、戦闘ターンでは減らない。火台の守りの中にいても点灯中の携帯松明は減る。旧灯油ゲージの節約用パッシブによって、この火網の毎歩1消費を省く処理はない。

携帯松明は残り25歩と8歩を上から跨いだ際に警告する。0になると消灯し、効果もなくなる。移動の燃料消費を済ませてから歩行遭遇を判定するため、その歩で消えれば消灯後の守護状態を使う。

守りがないときは、ゲーム全体の成功歩数 `state.steps` の7歩ごとに基本22％で戦闘発生を抽選し、当選した場合に消灯時の敵候補を選ぶ。点火・消火・新規入場では判定周期をリセットしない。現在の候補はくらがりだけ。消火した瞬間に確定戦闘を起こす処理ではない。隊の遭遇率補正、安全な配置物の地点、物語イベントの優先については [火と遭遇](KAGARIBI_DUNGEON.md) を参照する。

根拠は [GameEngine.finishMove()](../../src/core/engine.js)、[stepDungeon()](../../src/core/dungeons.js)、[fireNetwork.step・burn()](../../src/core/systems/fire-network.js)、[区画間接続](../../src/core/systems/map-connections.js)。

### 光の見た目と火の守り

光の見た目と、くらがり除け・遭遇倍率が届く範囲は別の計算。セルの局所照度だけを高くしても、火の守りにはならない。

視覚上の照度は [lighting.js](../../src/core/lighting.js) の直線距離による減衰と遮光で計算する。携帯火の照射半径は4。セル、共有エッジ、閉じた接続境界などの遮光を調べる。詳細は [FIELD_LIGHTING.md](FIELD_LIGHTING.md)。

固定火の守護範囲は [fire-network.js](../../src/core/systems/fire-network.js) の `reaches()` が同一マップの上下左右の通路を辿って求める。2026-10-12から、実効セルの通行・遮光・障害物と共有エッジの遮光を参照する。落盤・爆発による変更も守護範囲へ反映する。守護は同一マップ内の到達距離、照明は直線距離であるため、曲がり角での範囲は同じではない。区画間へ守護範囲を渡す処理はない。

### 入場・帰還・保存

新しく篝火の迷宮へ入ると携帯松明を1個受け取る。携行油管理開始前は、くらがり除けの火・90歩分で支給する。管理開始後は保存した携行灯の残量と効果を復元し、入場・中継出発によって無料で満タンにしない。入口の篝火は本来の効果・容量で整備する。入口以外の15基の状態は保持し、入場による一括点火・満タン化は行わない。q001の場面に入ると、後述する残量指定が優先する。

現行の `kagaribi_torch` は迷宮への入場時に支給する道具で、ゲーム開始時の所持品ではない。この支給・返却方式は現行実装の記録であり、新仕様における初期松明や希少な携行火台全般の所有・入手方法まで定めるものではない。

通常帰還・緊急帰還・敗北で探索を終えると携帯松明を返却し、採取した種火を持ち帰る。次の篝火探索でも種火を保持できるが、所持だけでは火は灯らない。区画移動では携帯松明の残量は戻らない。

詰所などのダンジョン室内への入退室は、探索の終了・新規入場ではない。同じ探索番号・成功歩数・携帯松明・種火を保持し、入室による燃料回復はない。室内が町形式の表示になっても返却・再支給とは扱わない。

固定火台は `state.dungeons.persistent.<迷宮ID>.systems.<火システムID>.fixtures`、探索中の携帯松明・種火は `state.dungeons.active.systems.<火システムID>` に保存する。持ち帰った種火は永続側の `ember` に保持する。同版セーブではこれらの状態を検証して再開する。携行油管理の残量・容量・設備状態は `state.expedition` に保存する。1.26.0は正常な1.25.0のセーブを限定移行し、既存の火・探索・物語状態を保持する。その他の内容版は移行対象外。詳しくは[保存仕様](../SPEC.md)を参照する。

根拠は [fireNetwork.enter・leave・validateState](../../src/core/systems/fire-network.js)、[迷宮の入退場](../../src/core/dungeons.js)、[場所と室内への移動](../../src/core/engine.js)。

操作：携帯松明自身から種火を採る / 携帯火の残量：1 / 携帯火の効果：くらがり除け / 予備灯油：0 / 種火：くらがり除け

操作：携帯松明を消す / 携帯火の残量：0 / 携帯火の効果：なし / 予備灯油：0 / 種火：くらがり除け

操作：同じ携帯松明へ種火を移す / 携帯火の残量：90 / 携帯火の効果：くらがり除け / 予備灯油：0 / 種火：なし

操作は `dungeon.action`、`system: fires`、`target: portable` で、`action` を `collect`・`extinguish`・`transplant` の順に実行する。成功歩数は増えず、予備灯油も消費しない。保存・再読込後も満タンの状態を保持した。

当時の原因は、種火採取が火元の燃料を減らさず、種火移植が燃料アイテムを要求せずに `freshFlame(effect, capacity)` で火を作ること。この組み合わせで通常の油の消費を回避できた。2026-10-11の仕様記録時点では未修正。1.26.0の携行油管理開始後は `oilFuelPlan()` を通すため、油がなければ移植を拒否し、予備油12単位なら燃料12単位だけを移す。[遠征試験](../../tests/expedition.test.mjs)がこの挙動を検査する。

#### 初回確認時に残っていた箇所と現在の対応

1. 手動消火で残燃料も0になるため、油を残した消灯を扱えない。
2. 初回確認時は種火移植と技能点火が燃料アイテムなしで容量いっぱいにした。現在も携行油管理開始前の種火移植とMP技能点火はこの動作を維持する。管理開始後の種火移植は油を消費する。
3. q001の油切れ壁灯には燃料の補充操作がない。物語の「油が尽きた壁灯は火を移すだけでは灯らない」という制約と、通常火台の種火移植の動作が一致しない。
4. 燃料の表示名と一部の説明文に「予備灯油」「松明」が混在する。「普通の火を灯す」という操作名でも、固定火台では本来の特殊効果が出る。
5. 初回確認時は火の守護範囲に共有エッジの遮光判定が未接続だった。2026-10-12以降は実効セル・障害物・共有エッジの遮光を参照する。守護を区画間へ伝播させる処理はなく、照明の直線距離と守護の通路距離も異なる。

これらは初回確認基点で挙げた課題と、その後の対応状況である。修正の基準は先頭の[根幹仕様](#根幹仕様)とする。MP種火の生成が油を使わないことは決定済みだが、燃料残量の具体的な管理、移火後の燃料要件、q001の壁灯の統合、表示名の整理や区画間へ守護を伝えるかについては、具体的な変更内容を別途定める。

## 編集元と保守

通常火台は [マップ編集](../../config/map.html?dungeon=kagaribi) の仕掛けから扱う。q001の壁灯はイベント側の編集対象で、通常火台の一覧とは別。

変更対象：燃料アイテムの参照、携帯火の容量、火の効果、固定火台の位置・容量・初期点灯 / 正本・実装：[config/dungeons/kagaribi.json](../../config/dungeons/kagaribi.json)

変更対象：携帯松明・種火などの道具、詰所の補給・説明 / 正本・実装：[config/kagaribi-content.json](../../config/kagaribi-content.json)

変更対象：灯番の習得段階・技能の費用と効果 / 正本・実装：[config/jobs.json](../../config/jobs.json)

変更対象：点火・補充・採火・消火・種火移植・燃料消費・火の守護判定 / 正本・実装：[src/core/systems/fire-network.js](../../src/core/systems/fire-network.js)

変更対象：q001壁灯の配置・状態・調査説明 / 正本・実装：[config/quests/q001.events.json](../../config/quests/q001.events.json)

設定値だけで変えられる範囲と、操作規則そのものの変更を区別する。生成済みの `data/` を直接編集しない。原稿を変更した場合の生成・確認手順は [編集仕様](../authoring/CONFIG_EDITORS.md) と [開発・文書保守](../development/README.md) を参照する。

本書は手書きで管理し、先頭の採用する根幹仕様と後半の現行実装を区別する。文書のみの変更は `npm run check:docs` でリンクと既存の生成文書との整合を確認する。ゲーム動作を変更する際は本書・篝火仕様・関連試験も合わせて更新し、仕様への記載を動作修正済みの根拠にしない。

## トラップ・環境危険との接続（2026-10-12）

[トラップ・環境危険](TRAPS_AND_HAZARDS.md)を実装した。落滴は指定火台・携行火を現行の燃料規則で消す。漏水は着火を費用支払前に禁止する。ガス漏れは着火費用を支払い、火を点けずに共通の爆発を発生させる。持ち込み火・給油・守護範囲の到達では引火しない。原因のconditionが解消するまで有効。新しい油・器の根幹仕様全体を実装したものではない。
