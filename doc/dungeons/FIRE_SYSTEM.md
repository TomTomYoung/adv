# 火の仕様：火・火台・油・種火

**効果をもつのは火。火台は火を生成するためのベース、油は消耗品であり、火台と油から火を生成する。**

**新しく生成する火の効果 ＝ 火台固有の効果 ＋ 最後に給油した油の効果。** 基本的には両者を単純に足し、生成時にその火の効果を確定する。

**移火と給油は火の生成ではないため、すでにある火の効果を維持する。** 給油時に上書きするのは、次回の生成に使う油の効果である。

## 根幹仕様

決定日: 2026-10-11。この節は今後の実装で採用する仕様を定める。現在のゲーム動作と実装との差は、後半の[現行実装](#現行実装)に記録する。

### 火・火台・油の役割

| 要素 | 役割と性質 | 効果の扱い |
| --- | --- | --- |
| 火 | 実際に効果を発揮する主体 | 生成時に確定した効果を、その火が続く間保持する |
| 固定火台 | ダンジョンに設置された、火を生成するためのベース | 火台ごとに固有の効果が固定され、新規生成時にだけ火へ渡す |
| 携行火台 | 松明・行燈・ランプなど、持ち運べるベース。アイテム自体は消耗しない | 固定火台と同様、火台ごとの固有効果を新規生成時にだけ火へ渡す |
| 油 | 複数種類を用意する消耗品 | 種類ごとの効果を新規生成時に火へ渡す。給油すると、次回生成用の油の効果を追加した油の効果で上書きする |

火台と油の「効果」は、火を生成するときの材料を指す。火台や油が、それだけで周囲や戦闘へ効果を発揮するわけではない。固定火台と携行火台には、同じ生成・移火・給油の規則を適用する。

### 生成・移火・給油の違い

| 操作 | 火を新しく生成するか | 火の効果 | 次回生成に使う油の効果 |
| --- | --- | --- | --- |
| 火を生成する | する | その火台の固有効果＋最後に給油した油の効果で確定する | その時点の油の効果を生成に使う |
| すでにある火を別の火台へ移す | しない | 移した火の効果をそのまま保持する。移し先の火台・油の効果は加えない | 移し先が保持している油の効果を維持する |
| 火がついている火台へ給油する | しない | 現在の火の効果をそのまま保持する | 追加した油の効果で上書きする |

火台・油の効果を適用するのは新規生成の瞬間だけであり、燃焼中の火の効果を現在の火台・油から再計算しない。火を何度移しても、移し先の火台の効果が積み上がることはない。

給油では、残っている油の効果と追加した油の効果を混合・加算しない。最後に追加した油の効果を採用する。「油の効果を上書きする」とは、火台側が保持する次回生成用の効果を更新することを指し、現在の火の効果や燃料残量を上書きするという意味ではない。

### 生成・移火・別種の油による給油の例

火台X・火台Yと、効果の異なる油A・油B・油Cを使う例。表の「火台X＋油A」などは、生成時に組み合わせた効果を表す。

| 順序・操作 | 火の置き場所 | その火台が保持する次回生成用の油の効果 | 現在の火の効果 |
| --- | --- | --- | --- |
| 1. 油Aを用いて火台Xで火を生成する | 火台X | 油A | 火台X＋油A |
| 2. 油Bが入った火台Yへ、その火を移す | 火台Y | 油B | 火台X＋油Aのまま |
| 3. 燃焼中の火台Yへ油Cを給油する | 火台Y | 油Cへ上書き | 火台X＋油Aのまま |
| 4. その後、火台Yで新しく火を生成するとき | 火台Y | 油C | 火台Y＋油C |

移火後も、給油後も、元の火は生成元の組み合わせを保持する。火台Yと油Cの効果が使われるのは、火台Yで新しい火を生成したときだけである。

## 現行実装

確認日: 2026-10-11。対象は作品版1.25.0、確認基点は master [`1076397`](https://github.com/TomTomYoung/adv/commit/10763979fb3c11fbd5ce6a155b2dfe4d1d20880a)。

以下は篝火の迷宮の通常の火と、q001「帰らない灯番」の壁灯・物語の油について、確認基点の定義と実行処理を記録したもの。現行では予備灯油は1種類であり、複数種類の油、最後の給油による生成用効果の上書き、火台＋油による効果の合成は未実装である。

点火・消火・種火移植による燃料の扱いは現行動作として記録し、燃料を使わない補充などの未整理の点も明示する。先頭の根幹仕様への対応状況と区別し、実装を変更した際にこの節を更新する。

### 対象と構成要素

現在 `fire_network` を使う迷宮は篝火の迷宮。本書では現行2Dマップの携帯松明と16基の固定火台を扱う。q001の壁松明3本は別の配置イベントであり、通常の火台の操作対象には含めない。火網のない迷宮では従来の灯油ゲージを使う。

| 要素 | 定義・保存する内容 | 他の要素との関係 |
| --- | --- | --- |
| 油・燃料 | 所持品の「予備灯油」。参照IDは `torch` | 通常点火・燃料補充で1個使う。油の種類・品質・注いだ体積に応じた火の変化はない |
| 燭台・火台・壁面松明 | 設置位置、壁面方向、本来の火の効果、効果範囲、燃料容量、初期点灯 | 普通に点火したときの効果と、満タン時の継続歩数を決める |
| 点灯中の火 | 点灯状態、現在有効な効果、残り燃料 | 通常点火は器の本来の効果、種火移植・技能点火は指定された効果を使う |
| 種火 | 採取した火の効果を1種類保持 | 火台や携帯松明へ移すとその効果で点灯する。所持だけでは照明やくらがり除けにならない |

「予備灯油」の内部IDと一部の説明文には旧称の `torch`・「松明」が残っている。別の燃料が二種類あるという意味ではない。現行の表示名は [data/items.json](../../data/items.json)、携帯松明などの説明原稿は [config/kagaribi-content.json](../../config/kagaribi-content.json) を参照する。

### 火台の容量と本来の効果

火台の正本は [config/dungeons/kagaribi.json](../../config/dungeons/kagaribi.json) の `systems.fires`、配布定義は [data/dungeons.json](../../data/dungeons.json)。

| 対象 | 数 | 満タン時の燃料 |
| --- | ---: | --- |
| 携帯松明 | 入場ごとに1個 | 90成功歩 |
| 有限容量の壁面松明 | 2基 | 各60成功歩 |
| 青銅・赤鉄などの有限容量の火台 | 5基 | 各80成功歩 |
| 入口・中継篝火・深火の祭壇など | 9基 | 無期限。定義の `capacity` は `null` |

固定火台は合計16基。各火台の座標・範囲・初期点灯は [迷宮の専用ページ](details/kagaribi.md) に載せる。容量の単位は油のmLや実時間ではなく、同じ迷宮内で移動に成功した歩数。

同じ予備灯油で点火しても、青銅の火台は「鎮めの火」、赤鉄の火台は「呼び寄せの火」になる。操作名の「普通の火を灯す」は、固定火台では本来の効果による点火を指す。携帯松明を普通に点火した場合は `portable.baseEffect` の「普通の火」になる。

種火を移すと、その火が消えるまで台座本来の効果に優先する。たとえば青銅の火台へ深火を移すと、深火の効果が、その火台の容量80歩・範囲3で働く。種火に採取元の容量や範囲は保存しない。補充は移植した効果を保持し、消火・燃料切れは効果を消す。次に普通に点火すると台座本来の効果へ戻る。

### 点灯状態と燃料の保存

通常の火は次の三つを一緒に保存する。`effect` は火台本来の設定ではなく、現在灯っている火の効果。

```json
{ "lit": true, "effect": "ward", "fuel": 25 }
```

有限容量の点灯中の火は燃料1以上、無期限の点灯中の火は `fuel: null`。消灯中は必ず次の形になる。

```json
{ "lit": false, "effect": null, "fuel": 0 }
```

手動消火も燃料切れもこの消灯状態にする。消灯中に正の燃料を残した保存は `validateState()` が受け付けない。このため、現在は「油が残った器で火だけを消す」「消灯中の器に油だけを注ぐ」という状態・通常操作を扱えない。

定義上の火台本来の `effect` と、保存中の火の `effect` は別。保存中の効果を消しても、火台の定義そのものは変わらない。根拠は [fire-network.js](../../src/core/systems/fire-network.js) の `freshFlame()`、`act()`、`burn()`、`validateState()`。

### 操作と消費

固定火台は配置セルに立って操作する。壁面松明は、その壁が属するセルに立ち、指定された壁を向く。携帯松明は携帯松明の所持を確認する。通常操作は会話・選択待ち・戦闘中には行えない。

| 操作 | 条件 | 消費 | 結果 |
| --- | --- | --- | --- |
| 普通の火を灯す | 消灯中、予備灯油を所持 | 予備灯油1個 | 本来の効果で点灯し、燃料を容量いっぱいにする |
| 燃料を補充 | 点灯中、有限容量、未満タン、予備灯油を所持 | 予備灯油1個 | 残量にかかわらず満タンにする。現在の効果は維持 |
| 種火を採る | 点灯中。同じ効果の種火を既に保持していない | なし | 現在の効果を種火として保持。火元は消えず、燃料も減らない |
| 火を消す | 点灯中 | アイテム消費なし | 消灯し、現在の効果と残り燃料を消す |
| 種火を移す | 移植先が消灯中、種火を保持 | 種火1個。予備灯油は不要 | 種火の効果で点灯し、燃料も容量いっぱいにする |
| 灯番の技能で点火 | 習得・使用条件を満たす。固定火台は消灯中 | 技能のMP。予備灯油は不要 | 技能の効果で点灯し、燃料も容量いっぱいにする |

予備灯油は、残り1歩を満タンにする場合も、あと1歩で満タンになる状態を補う場合も1個使う。無期限の火には燃料補充を行えないが、消えていれば予備灯油による通常点火はできる。

種火は携帯松明自身からも採れる。保持は1種類で、違う火から採ると持ち替える。同じ効果の再採取は無効。種火の採取や移植で、その火の効果を発現するための油の種類を検査する処理はない。

旅支度から予備灯油を使うと、携帯松明が点灯中なら補充、消灯中なら通常点火になる。固定火台へ補充するときは、その火台を選んで操作する。燃料を購入・入手しただけでは自動補充しない。

灯番は現在職の習得段階、出撃、生存、MP、携帯松明の所持を確認する。固定火台への技能点火でも携帯松明を所持している必要がある。携帯松明は点灯中でも技能で更新でき、固定火台は先に消火する。

| 灯番の技能 | 習得Lv | 消費MP | 火の効果 |
| --- | ---: | ---: | --- |
| くらがり除けの火 | 1 | 3 | `ward` |
| 鎮めの火 | 5 | 4 | `calm` |
| 呼び寄せの火 | 10 | 4 | `lure` |

技能によるくらがり撃退は専用の戦闘処理で扱い、通常の魔物には使えない。詳細は [篝火の迷宮と灯番](KAGARIBI_DUNGEON.md)。操作可否と状態変更は [fire-network.js](../../src/core/systems/fire-network.js) の `plan()`・`act()`・`itemIntent`、習得と費用は [jobs.js](../../src/core/jobs.js) と [config/jobs.json](../../config/jobs.json) が根拠。

### 火の効果と重なり

| 火 | くらがり除け | 通常遭遇率の倍率 | 通常敵の能力倍率 | 優先順位 |
| --- | --- | ---: | ---: | ---: |
| 普通の火 | 有効 | 1 | 1 | 0 |
| くらがり除けの火 | 有効 | 1 | 1 | 10 |
| 鎮めの火 | 有効 | 0.5 | 0.6 | 20 |
| 呼び寄せの火 | 有効 | 2 | 1.6 | 30 |
| 深火の種火 | 有効 | 0 | 1 | 40 |

普通の火もくらがりを遠ざける。普通の火とくらがり除けの火は、通常の魔物の出現を止めない。深火は通常遭遇を抑えるが、物語の固定戦闘を一括で無効化する効果ではない。深火による蘇生は未実装で、伝承の真偽も確定していない。

複数の火が届く場合、くらがり除けは一つでも `repels: true` なら有効。通常遭遇率と能力倍率は、届く火のうち優先順位が最大の一つを採用する。同順位では火元IDの英語昇順を使う。携帯松明、固定火台、点灯中の配置イベントの壁灯は同じ候補に入る。倍率を重ねて加算・乗算しない。

通常敵の能力倍率はHP・攻撃・防御・知力に適用し、経験値・所持金や、くらがりの能力には適用しない。深火と呼び寄せの火が重なる場合は深火が優先する。定義は [kagaribi.json](../../config/dungeons/kagaribi.json)、選択は [fireEnvironment()](../../src/core/systems/fire-network.js)、遭遇・戦闘への反映は [dungeons.js](../../src/core/dungeons.js) と [engine.js](../../src/core/engine.js) を参照する。

### 燃料が減るタイミング

同じ迷宮内で移動に成功するたび、点灯中の携帯松明と全ての有限固定火台の燃料を1ずつ減らす。別区画に置いてきた固定火台も対象で、見える範囲だけの消費ではない。区画間の接続を使う移動も成功歩に含まれる。

回転、壁への衝突、会話、選択、メニュー、セーブ・ロード、火の操作、戦闘ターンでは減らない。火台の守りの中にいても点灯中の携帯松明は減る。旧灯油ゲージの節約用パッシブによって、この火網の毎歩1消費を省く処理はない。

携帯松明は残り25歩と8歩を上から跨いだ際に警告する。0になると消灯し、効果もなくなる。移動の燃料消費を済ませてから歩行遭遇を判定するため、その歩で消えれば消灯後の守護状態を使う。

守りがないときは、ゲーム全体の成功歩数 `state.steps` の7歩ごとに基本22％で戦闘発生を抽選し、当選した場合に消灯時の敵候補を選ぶ。点火・消火・新規入場では判定周期をリセットしない。現在の候補はくらがりだけ。消火した瞬間に確定戦闘を起こす処理ではない。隊の遭遇率補正、安全な配置物の地点、物語イベントの優先については [火と遭遇](KAGARIBI_DUNGEON.md) を参照する。

根拠は [GameEngine.finishMove()](../../src/core/engine.js)、[stepDungeon()](../../src/core/dungeons.js)、[fireNetwork.step・burn()](../../src/core/systems/fire-network.js)、[区画間接続](../../src/core/systems/map-connections.js)。

### 光の見た目と火の守り

光の見た目と、くらがり除け・遭遇倍率が届く範囲は別の計算。セルの局所照度だけを高くしても、火の守りにはならない。

視覚上の照度は [lighting.js](../../src/core/lighting.js) の直線距離による減衰と遮光で計算する。携帯火の照射半径は4。セル、共有エッジ、閉じた接続境界などの遮光を調べる。詳細は [FIELD_LIGHTING.md](FIELD_LIGHTING.md)。

固定火の守護範囲は [fire-network.js](../../src/core/systems/fire-network.js) の `reaches()` が同一マップの上下左右の通路を辿って求める。現在は `map.tiles` が通路であることと `objectBlocks()` を使い、共有エッジや区画間接続の境界判定は参照していない。このため、視覚上の遮光と全ての境界条件が一致する仕様とはいえない。共有エッジを含む守護範囲の統一は未整理の点として残る。

### 入場・帰還・保存

新しく篝火の迷宮へ入ると、くらがり除けの携帯松明を90歩分で1個受け取る。入口の篝火も本来の効果・容量で整備する。入口以外の15基の状態は保持し、入場による一括点火・満タン化は行わない。q001の場面に入ると、後述する残量指定が優先する。

通常帰還・緊急帰還・敗北で探索を終えると携帯松明を返却し、採取した種火を持ち帰る。次の篝火探索でも種火を保持できるが、所持だけでは火は灯らない。区画移動では携帯松明の残量は戻らない。

詰所などのダンジョン室内への入退室は、探索の終了・新規入場ではない。同じ探索番号・成功歩数・携帯松明・種火を保持し、入室による燃料回復はない。室内が町形式の表示になっても返却・再支給とは扱わない。

固定火台は `state.dungeons.persistent.<迷宮ID>.systems.<火システムID>.fixtures`、探索中の携帯松明・種火は `state.dungeons.active.systems.<火システムID>` に保存する。持ち帰った種火は永続側の `ember` に保持する。同版セーブではこれらの状態を検証して再開する。今回の文書整理では内容版・保存形式・旧版を移行しない方針を変更していない。

根拠は [fireNetwork.enter・leave・validateState](../../src/core/systems/fire-network.js)、[迷宮の入退場](../../src/core/dungeons.js)、[場所と室内への移動](../../src/core/engine.js)。

### q001の壁灯と物語の油

#### 通常火台に含まれない三つの壁灯

| 壁灯 | 配置 | 初期状態 | 現在の操作 |
| --- | --- | --- | --- |
| 西の壁松明 | 巡回路 (8, 1)、北壁 | `empty`：油切れ | 状態に応じた調査説明 |
| 東の壁松明 | 巡回路 (11, 1)、北壁 | `empty`：油切れ | 状態に応じた調査説明 |
| 老人を守る最後の壁松明 | 巡回路 (13, 3)、東壁 | `low`：残り少ない油で点灯 | 状態に応じた調査説明。帰路イベントで消灯 |

これらは [config/quests/q001.events.json](../../config/quests/q001.events.json) の `clue` 配置イベント。状態は `state.objects` に保存し、各壁灯の油量・燃料容量を数値では持たない。予備灯油を注ぐ、通常点火する、種火を移す、灯番の技能で点火する操作も登録されていない。

q001の表示条件（受注中または完了）を満たし、現在状態が `lit` または `low` の間は、範囲1のくらがり除けの火として照明・守護判定に参加する。未受注の自由探索では、初期状態が `low` でも表示条件を満たさず光源・守護源にならない。老人の壁灯の `low` は歩数で減る燃料値ではなく、物語の消灯場面が `extinguished` へ変更する。

#### 老人・新人が持つ油

物語の油は [authoring/story-q001.mjs](../../authoring/story-q001.mjs) の独立した数値で、プレイヤーの予備灯油の所持数とは接続していない。

| 物語の値 | 初期値 | 意味 |
| --- | ---: | --- |
| `oldOil` | 0 | 老人の瓶に残る油 |
| `newOil` | 1 | 新人の瓶に残る、老人から渡された油 |
| `oilUsed` | 1 | 既に使った油 |

三つの合計は常に2という整合性条件を持つ。救援で `newOil` を1から0へ、`oilUsed` を1から2へ変える。物語内の量であり、mL・プレイヤーの燃料アイテム個数・携帯火の歩数への換算は定義していない。

#### 物語による携帯松明の残量指定

| 場面 | 実際の携帯松明への指定 |
| --- | --- |
| 入口の新人の場面 | くらがり除けの火、25歩分 |
| 老人との遭遇 | くらがり除けの火、8歩分へ上書き |
| 帰路の消灯場面 | 0へ上書き。同時に老人の最後の壁灯も消灯 |
| 新人による救援 | くらがり除けの火、25歩分へ上書き |

途中で予備灯油を補充していても、帰路の指定地点で消灯場面が始まれば残量を0へ上書きする。通常の燃料切れを待つ処理ではない。老人介助中は北 (9, 1)・南 (13, 5) の帰路、または通常抽選でくらがりに当選した実遭遇地点から、同じ消灯・戦闘・救援へ進む。

救援は一度だけで、救援前の全滅は共通チェックポイントにより老人遭遇後の区間を巻き戻す。物語の `partyTorch`・`rookieTorch` も実際の携帯火の残り歩数とは別の物語状態として扱う。本文の「新人の火を頼る」という表現と、プレイ上の携帯火の再点灯を、同じ一つの燃料値と見なさない。

詳細は [q001原稿](../../authoring/story-q001.mjs)、[老人同行中のイベント戦闘](KAGARIBI_DUNGEON.md#老人同行中の消灯はイベント戦闘)、[チェックポイント](../scenarios/EVENT_CHECKPOINTS.md)。

### 確認済みの未整理の点

#### 種火だけで携帯松明を満タンにできる

2026-10-11、確認基点のクリーンなcheckoutで、既存の [tests/helpers.mjs](../../tests/helpers.mjs) の `newGame()` と実際の `GameEngine.dispatch()` を使って確認した。初期条件は、篝火探索中、携帯火がくらがり除け・残り1歩、予備灯油0個、種火なし。q001の場面を進める操作ではなく、通常の火の操作を実行した。

| 操作 | 携帯火の残量 | 携帯火の効果 | 予備灯油 | 種火 |
| --- | ---: | --- | ---: | --- |
| 確認用の初期状態 | 1 | くらがり除け | 0 | なし |
| 携帯松明自身から種火を採る | 1 | くらがり除け | 0 | くらがり除け |
| 携帯松明を消す | 0 | なし | 0 | くらがり除け |
| 同じ携帯松明へ種火を移す | 90 | くらがり除け | 0 | なし |

操作は `dungeon.action`、`system: fires`、`target: portable` で、`action` を `collect`・`extinguish`・`transplant` の順に実行する。成功歩数は増えず、予備灯油も消費しない。保存・再読込後も満タンの状態を保持した。

原因は、種火採取が火元の燃料を減らさず、種火移植が燃料アイテムを要求せずに `freshFlame(effect, capacity)` で火を作ること。この組み合わせで通常の油の消費を回避できる。仕様記録時点では未修正。

#### 燃料・器・火の関係が統一されていない箇所

1. 手動消火で残燃料も0になるため、油を残した消灯を扱えない。
2. 種火移植と技能点火は燃料アイテムなしで容量いっぱいにする。点火方法と燃料補給が一体化している。
3. q001の油切れ壁灯には燃料の補充操作がない。物語の「油が尽きた壁灯は火を移すだけでは灯らない」という制約と、通常火台の種火移植の動作が一致しない。
4. 燃料の表示名と一部の説明文に「予備灯油」「松明」が混在する。「普通の火を灯す」という操作名でも、固定火台では本来の特殊効果が出る。
5. 火の守護範囲は共有エッジ・接続境界の共通判定へ未接続で、視覚上の照度と全ての遮蔽条件が一致するわけではない。

これらは確認基点における現行実装の課題。修正の基準は先頭の[根幹仕様](#根幹仕様)とする。燃料残量の具体的な管理、種火移植や技能点火の燃料要件、q001の壁灯の統合、表示名・守護範囲の統一については、具体的な変更内容を別途定める。

## 編集元と保守

通常火台は [マップ編集](../../config/map.html?dungeon=kagaribi) の仕掛けから扱う。q001の壁灯はイベント側の編集対象で、通常火台の一覧とは別。

| 変更対象 | 正本・実装 |
| --- | --- |
| 燃料アイテムの参照、携帯火の容量、火の効果、固定火台の位置・容量・初期点灯 | [config/dungeons/kagaribi.json](../../config/dungeons/kagaribi.json) |
| 携帯松明・種火などの道具、詰所の補給・説明 | [config/kagaribi-content.json](../../config/kagaribi-content.json) |
| 灯番の習得段階・技能の費用と効果 | [config/jobs.json](../../config/jobs.json) |
| 点火・補充・採火・消火・種火移植・燃料消費・火の守護判定 | [src/core/systems/fire-network.js](../../src/core/systems/fire-network.js) |
| 視覚上の光と遮光 | [src/core/lighting.js](../../src/core/lighting.js) |
| q001壁灯の配置・状態・調査説明 | [config/quests/q001.events.json](../../config/quests/q001.events.json) |
| q001の油・携帯火の指定・消灯と救援 | [authoring/story-q001.mjs](../../authoring/story-q001.mjs) |

設定値だけで変えられる範囲と、操作規則そのものの変更を区別する。生成済みの `data/` を直接編集しない。原稿を変更した場合の生成・確認手順は [編集仕様](../authoring/CONFIG_EDITORS.md) と [開発・文書保守](../development/README.md) を参照する。

本書は手書きで管理し、先頭の採用する根幹仕様と後半の現行実装を区別する。文書のみの変更は `npm run check:docs` でリンクと既存の生成文書との整合を確認する。ゲーム動作を変更する際は本書・篝火仕様・関連試験も合わせて更新し、仕様への記載を動作修正済みの根拠にしない。
