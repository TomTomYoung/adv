# 灯帰りの迷宮 現行仕様 1.3.1

更新日: 2026-09-10。JSONを正式形式とし、ブラウザのES Modulesで実行する静的アプリです。Phaser試作から共通エンジンを再構成し、CDN依存を取り除きました。

## 必須要件

1. シナリオ・クエスト・探索イベント・戦闘データ・計算式をJSONへ分離しました。文章や個別依頼のIDをエンジンへ埋め込みません。
2. 実際に戦闘を実行します。勝利・敗北・逃走の経路を分け、勝利した場合にだけ依頼の戦闘分岐を完了します。
3. ビューはプレーンなViewModelを受け取り、操作意図を返します。ゲーム状態の変更・報酬計算・保存を持ちません。独立した表示例とテーマ編集ページがあります。

## 世界と探索

拠点は灯帰りの町。10地域、各2階層、19×15マスのマップをJSONで定義します。壁は `#`、床は `.`。入口、階段、鍵入りの補給箱、施錠された小部屋、罠、一度だけ使える回復の泉を各階へ置きます。生成済みマップは固定で、再訪時に地形を作り直しません。

北・東・南・西の方角を持ち、前後移動と左右回転を行います。移動成功時だけ歩数と灯油を消費します。壁・施錠扉へは移動できません。足元と正面を調べる際、正面の閉じた扉を優先し、それ以外は足元を先に解決します。

灯油は90歩分。0でも行動できますが遭遇率が上がります。7歩ごとに18%で通常敵と遭遇し、暗闇は15ポイントを加えます。イベント地点のsafe指定ではランダム戦闘を起こしません。各階のencounterPoolから重み付きで選びます。第一層は既存20%／新種各40%、第二層は既存20%／新種各35%／新種ペア10%。依頼の固定戦と既存ボスは維持します。敵定義は53件です（依頼の固定戦用13件を含む）。罠と泉は消化状態を保存します。鍵は地域単位、使用しても消費しません。

入口からの帰還は無料。帰還印は所持金の8%を消費します。全滅時は15%を失い、町で最低35%まで回復します。所持品・手掛かり・依頼進行は維持します。無料施療所があるため、所持金が尽きても再出発できます。

疑似3Dビューは方眼地形をレイキャストし、AIPaint背景から得た石壁のテクスチャを使います。移動や衝突はエンジンが判定し、レイキャストは描画だけを担います。

## 依頼

200件・618結末です。既存100件には3結末、新規100件には2〜5結末を定義します。各件に依頼文、依頼人、世界の真相、現場の痕跡、記録・証言、決着地点、各選択固有の結末・報酬を定義します。世界・人物・提示・読者仮説・開示のメタデータも同じJSONへ保存します。

状態はavailable → active → completed。複数受注でき、追跡する一件を切り替えます。既存篇は原則2つの手掛かりを照合し、判断前に事情を開示します。q011・q013・q017・q018は決定的な一方の根拠で早期に判断できます。一部は戦闘を伴い、勝利して作業を確定した時だけ縄を1本消費します。逃走・敗北では消費しません。依頼優先の分岐は戦闘、別案の分岐は戦闘なしで決着します。決めずに離れる選択も常に残します。

各地域の10件目は同地域3件完了で解放。100件目だけは元のq001〜q099全件の完了が必要です。追加篇の完了数では代替できません。100件目の選択が3つの終幕へ分岐し、終幕後も探索・閲覧を続けられます。完了した依頼は同じ記録では再選択できず、報酬も再取得できません。比較する場合は選択前の別記録を使用します。

新規篇は239場面からなり、各依頼の一つの開始地点から会話内の相談・移動・作業を選びます。中断後は同じ地点から現在場面を再開します。調査数・告知・返信・同意・準備・材料・仲間の在否などを実際の条件で分岐します。

観察結果と結末は冒険手帳へ記録します。事情を踏まえた／依頼優先／別案の選択数はvarsへ、各件の結末はquestsへ保存します。人物の観測・信念等のmodel部分は作者向け設計データであり、自律NPC思考の実装ではありません。

## 隊と戦闘

剣士アダ、斥候ニオ、祈祷師セラ、魔術師イルの4人で開始。町の酒場「帰り火亭」で全10人の候補から1〜5人を編成できます。加入・待機・満員時の交代は無料で、町の非会話・非戦闘時だけ受け付けます。最低1人の生存者を残します。交代だけでは回復せず、待機中のHP・MP・毒・装備も保持します。隊でレベル・経験値を共有し、HP、MP、毒、装備は個人別です。

レベルLの次の閾値は40×L×(L+1)。上限30。成長量は現在の職業と記録済みの成長履歴から算出します（JOB_SYSTEM参照）。レベル上昇時に隊を全回復します。装備は武器・防具・護符で能力値を加算します。付け替えた装備は在庫へ戻り、同じ一個を複数人へ装備できません。

各ラウンドは素早い生存味方から順に一人一行動、その後に敵が素早さ順で行動します。攻撃、強打、貫通、火・氷・雷術、治療、全体回復、解毒、単体・隊全体の防御、MP回復、毒刃、傷薬・解毒薬、逃走に対応。敵には全体攻撃・MP減少もあります。行動不能者は飛ばします。回復術・戦闘中の道具は生存者を対象とし、探索中の傷薬・糧食・泉・町の施療は倒れた仲間にも効果があります。

防御は敵の行動終了まで被ダメージを半減。毒は移動成功時に1（探索中はHP1を残す）、ターンごとに3を与えます。敵の毒は敵行動の直前、味方の毒は敵行動の後に適用します。全敵が毒で倒れた場合も勝利処理を通ります。

敵AIはJSONの優先度と条件式で選択し、MP不足の技能は飛ばして通常攻撃へフォールバックします。自己回復は敵自身を対象にします。通常戦闘の逃走成功率78%。失敗時は敵ターンになります。地域最終戦では逃走不可です。先に「別の道」を選べば戦闘を避けられます。

ダメージ・治療式は `formulas.json` の式ツリーを評価します。乱数はseed付きxorshift32で、乱数状態も保存します。命中・会心・列配置・行動予約は未実装です。

## JSONと実行モデル

作品の入口はgame.json。manifest内のdatabases、maps、quests、scriptsを読込み、ID重複・参照切れ・未知命令・不正マップを検証してから開始します。詳細はSCRIPT_REFERENCEを参照してください。

スクリプトはcommand配列と呼出スタックで進みます。say/narrate、choice、battle.startで入力を待ちます。スタックはscript ID、配列内パス、命令位置、ローカル値、呼出scopeで表します。分岐内のlocal変更は同じ呼出へ戻り、returnはその呼出全体を終了します。jumpはlocalを保持して現在の呼出を置き換えます。1回の自動実行は1000命令・深さ32まで。

JSON内のJavaScript、eval、Functionコンストラクタは使用しません。状態参照のprototype系パスを拒否します。直接set/addできる領域はvars/flags/localで、所持品・移動・戦闘等は専用命令で変更します。

## 保存と表示設定

saveVersion 1、gameId lantern-archive、contentVersion 1.3.1を照合します。1.0.0〜1.3.0を各移行定義で検証し、既存の進行・隊員・職業・成長・装備・継続位置・乱数を保持して追加100件を未受注にします。旧版の戦績は推測せず、移行後の履歴だけを記録します。本文・選択・戦闘待ちも保存可能です。ロードは検証成功後に状態を置き換えます。詳しくはSCENARIO_IMPLEMENTATIONの保存互換性を参照してください。

localStorageの接頭辞は `lantern-archive:v1:`。auto、slot1〜slot3、settingsを分離します。最大読込サイズは2MB。旧Phaserセーブを上書きも変換もしません。外部ファイルへ輸出できますが、サーバー同期はありません。

音声は初期オフです。音ボタンで有効化でき、設定を保存します。標準音量は50%（既存設定があればそれを維持）。音量0は消音です。読み込み中・再生中・自動再生の制限・読込失敗を表示し、ボタンで再試行できます。BGMは探索22.857秒・戦闘13.333秒のループ。音量調整版のOGGを使用します。本文は全文表示で、文字送り速度の設定はありません。画面テーマは許可された色・書体・寸法・配置だけを読込みます。任意CSSやJavaScriptの実行は許可しません。

## SEと表示演出

28種のSEをOGGで収録し、足音・接触・施設・技能・勝敗へ接続しています。音の有効化は従来の音ボタン、SEの強さは全体音量×SE音量×音源別gainで決めます。SE音量の初期値は80%、最大8同時発音です。

表示演出24種はeffects.json、音源定義はsounds.json、同時再生と技能等への割当てはpresentation.jsonです。3命令effect.play / screen.set / screen.clearを追加し、1.2.0時点では実装DSLは42命令でした。職業命令2つとjumpを加え、現行は45命令です。振動・回転・スキュ・伸縮・分割・消散・色・周辺シェードと8種の連番画像に対応します。

一時的なSE・演出はGameEngine.feedbackからViewModelへ渡し、保存しません。遅延イベントは入力ごとの相対ミリ秒であり、ゲームの乱数を使用しません。新しい描画・入力・ロードで前の予約を破棄し、完了待ちで進行を止めません。screen.setのレイヤーだけはpresentation.layersへ保存します。探索時の灯油25以下の暗さと周辺シェードも表示へ投影します。

設定の「動きを控える」とOSの動きを減らす指定では大きな運動を薄い一回の色変化へ置き換えます。「切」では表示効果を省略します。数値判定、敵AI、クエストの結末には影響しません。

人物と職業を分離し、主職1つを町で無料変更します。全30職の技能、バフ、装備種別、成長率をJSONに定義します。Lv1・5・10で技能を解放し、隊のレベル上昇は控えを含む全人物の現在職履歴に記録します。詳細はJOB_SYSTEM.md、実装位置と検証はJOB_IMPLEMENTATION.mdを参照してください。
