# q021「種を盗む鳥」現場接続前監査

2026-11-19。配布原本は [data/quests/q021.json](../../data/quests/q021.json)。次の第2版の実装範囲を整理した設計文書であり、q021の現場接続済みを意味しない。原本、旧保存、既存地理を編集しない。

## 原本の確定事項

場所は根喰みの地下庭園（`region_3`）。依頼人は庭師のユイ。地下庭園の種が毎晩なくなる理由は、鳥が食べているからではなく、光の届く亀裂へ運んで発芽させているからである。亀裂の新芽、まだ植えられていない種、畑へ戻す種を区別する。鳥を撃退しただけでは発芽条件が改善しない。

原本の場面は `entry`・`crack`・`nursery` の3場面。`entry → nest` は戦闘勝利後contract（101G・61EXP）。`follow → half` はcompromise（52G・63EXP）。`follow → mark → beds` はinformed（81G・84EXP）、`follow → mark → half` はcompromise。`crack → wait → crack` は一度だけ許される任意観察で、`watched=true` が保存され、そこからhalf/markへ合流する。待った後も同じ選択を繰り返せない。

旧版の `flow.visit` と、さらに古い `decision`・`review` は混合しない。旧 `decision`・`review` のinformedには `clue_a`・`clue_b` の2手掛かりが必要。旧contractでは `guard_3` 戦がある。現行原本 `entry → nest` の戦闘も `guard_3`（守護兵二体、逃走可能）であり、勝利前に種の回収を確定しない。古い原稿の条件・報酬・旧命令列はそのまま保持する。

## 既存地理の計測

既存の入口・決着点は `region_3_f1` の (10,10)。旧調査点は (7,1) と (11,4)。これらは全て既存の通行可能な床であり、元のマップと元のイベントを保存する。同じ地図にq022以降の事件があるため、それらの配置や既存オブジェクトを変更しない。

新規の操作地点の候補は、種棚・ユイの作業場所 (10,10)、羽根を追う道 (7,1)、光の差す亀裂 (11,4)、鳥の巣へ続く監視点 (15,13)、育苗床を置く作業地 (11,11)、戻した種の記帳地 (9,11)。後3点は現行の床セル・既存イベントとの重複がないことを静的確認した候補であり、実移動の到達試験を通して採否を決定する。最短格子歩数は (10,10)→(7,1) が26、(10,10)→(11,4) が7、(10,10)→(15,13) が8、(10,10)→(11,11) が2（既存迷路の床を四方向で探索した距離）。

## 必要な確定点

芽の発見、もう一度運搬を見る観察、植えられていない種の回収、戻した種の現物引渡し、発芽位置の標示、ユイの意思確認、鳥が使う分の保全、育苗床の施工、種の配分と記録を個々に保存する。標示しただけで育苗床ができたことにしない。戦闘の勝利と種の回収を分ける。鳥が亀裂で発芽させた苗は、回収・在庫補充の処理で勝手に消さない。

同じ `compromise` でも、亀裂を見た直後に半分を戻す経路と、標示してユイに確認してから設備を作らず半分を戻す経路の差を保持する。`wait` を経由したときは追加観察を保持して本文に反映するが、結末報酬は変えない。

## 検証工程

原本の繰返しを含む全到達状態と結末を3編成で確定、各途中状態を保存再読込する。旧 `flow.visit`・`decision`・`review` を別々のエンジン読込で再開し、戦闘・手掛かり・報酬の差を保持する。各実移動について、途中帰還、全滅救助、別地点での再開拒否、到着後の作業一回性を検査する。登場人物は実際の所在だけに表示する。Scene/Classic×1440/390、通常攻略、全体CI、統合・公開配信照合を分ける。

次工程：原本実試遊と保存状態を先に固定し、地理と物品の保持者を定義して第2版の原稿・生成器・専用試験へ落とし込む。
