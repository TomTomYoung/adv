# q014 帰りの貨車：現場接続前の監査

2026-11-18。原稿はauthoring/catalog-q011-q020.mjsのq014、配布原本はdata/quests/q014.json。原本Git blobはca8ce68aa81345f565f29476d3e7b3bb4823e817。3場面・6行動・3結末、経路はhaul、unload→split、unload→medical→register、unload→medical→quietの4通り。現場接続はまだ実装していない。

## 守る事実

切羽で脚を負傷した坑夫を、同じ組の坑夫たちが貨車の床下へ隠した。正規の搬送記録なしに早退すると当日の給金を差し引かれるため、仲間は帰宅と給金を守ろうとした。貨車番ホドは依頼時点では床下の人を知らず、増えた荷重に気づいて運転綱を外している。

貨車は人員搬送用ではなく、床下には手すりも固定具もない。貨物便と人員便は別であり、床下の人を見つけて別の人員籠へ移すことが、過荷重と危険な搬送を解消する。これだけで補償審査や鉱山の制度改善が済むわけではない。

治療所の受診・処置の記録と、作業中の負傷として鉱山へ届ける記録を分ける。本人の同意を得て発生場所・時刻・負傷内容を登録すれば補償審査が始まるが、補償の支払いや坑主の処罰が確定した結果へ拡大しない。本人と仲間が不利益を受けるおそれも保持する。

ホドが出す手すり・固定帯の申請は、設備の取付け完了とは別である。登録経路で治療所へ来る家族は、受付直後や床下の発見前には表示しない。

## 分ける作業

現行の調査点はregion_2_f1 (7,1)と(6,9)、決定点は(17,3)。貨車の固定、床板の開放、負傷者の発見、担架への移乗、人員籠への移乗、地上到着、治療所への搬送、処置、本人への説明、同意、記録の提出、帰宅を別に扱う。新しい接続先と座標、旅程数は次工程で決める。

人の保持者と移動中の所在を分け、ホド・仲間の坑夫・負傷者が誰とどこへ移動するかを明示する。移動開始だけで地上・治療所・自宅への到着を確定しない。処置前の到着でtreatedを、同意だけでregisteredを立てない。

床下を開けず巻き上げる経路はopened=false・injuryKnown=false・safeTransport=falseを保持する。仲間が人目のない場所で降ろして帰すことは後続の行為として扱い、隊やホドが床下で発見した事実へ置き換えない。

治療を経ず人員籠で帰す経路はtreated=false・consent=false・registered=falseを保持する。治療後に届出を見送る経路はtreated=trueを残し、治療記録を消さず、consent=false・registered=falseのまま帰宅する。登録経路のworkerAt=clinicとhome=falseも維持する。
