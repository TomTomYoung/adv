## 種の現物、育苗床、記録

新芽・未植付けの種・巣の未運搬の種を別々の物品とした。観察では鳥が種を食べていないことを知り、二度目の運搬を一度だけ見られる。芽の標示だけでは育苗床は完成しない。未植付け分を半分回収する経路は亀裂で隊が現物を取り、種棚でユイへ引き渡して初めて記帳する。標示後にユイが了解して半分回収する経路では、承諾と回収を分ける。

育苗床を作る経路はユイの同意、資材の種棚からの運搬、亀裂隣の施工、鳥の持分と新芽の保全、種棚での記帳を独立して保存する。苗は亀裂に残り、鳥の運んだ分を無断で全部在庫へ計上しない。巣から徹底回収する経路は `guard_3` の戦闘勝利、その後の巣の種回収、亀裂の種・苗の回収、種棚への現物返還を個別に操作する。戦闘勝利だけでは回収も依頼完了も成立しない。

## 原本と報酬の対応

- `nest`：守護兵を倒し、巣と亀裂の種・芽を全回収してcontract、101G・61EXP。
- `follow → half`、`follow → wait → half`：芽を残して未植付け分を半分回収しcompromise、52G・63EXP。追加観察の有無を別に保持。
- `follow → mark → half`、`follow → wait → mark → half`：発芽位置の標示とユイへの確認後、育苗床を作らず半分回収してcompromise、52G・63EXP。
- `follow → mark → beds`、`follow → wait → mark → beds`：育苗床を作り、鳥の分を残してinformed、81G・84EXP。

旧 `flow.visit` の7経路と、旧 `decision`・`review` の各3結末の命令列を別に維持する。旧 `decision` と `review` のinformedには二つの手掛かりが必要。元の `guard_3` は守護兵二体で逃走可能。新しい現場接続の巣の戦闘でも既存 `guard_3` をそのまま用いる。戦闘報酬と依頼報酬は分けて扱い、再挑戦後の重複受給を防ぐ。
