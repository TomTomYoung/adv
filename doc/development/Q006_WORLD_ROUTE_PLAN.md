# q006 沈んだ給金箱：現場接続前の監査

## 現在の構造

現場イベントは `region_1_canal_c (7,1)` の `q006_decision`。物語上の回収場landing、浅瀬water、荷役人の岸shore、ガロの事務所officeにはworldPlacesがない。ガロは回収場、荷役人集団と疑われた荷役人は岸、箱は浅瀬、二つの台帳は事務所、石は箱の中にある。

私的回収は縄1本と `guard_1` 戦闘を伴う。現在は勝利後のstory.actionで縄消費・引揚げ・回収場への往復を同時に確定し、逃走・敗北では一切を確定しない。共同回収は所持縄を使わず、荷役人の道具で回収し、岸で公開する。

未開封でガロへ返し、そのまま報告すればcontract。報告前なら箱を返してもらい公開へ変更できる。直接の公開、返却撤回後の公開、共同回収の3経路から、それぞれ一部払いinformedと証拠引渡しcompromiseへ分かれる。非循環の選択列は計7経路である。

## 接続する順序

回収場から浅瀬へ歩き、現地で戦闘と引揚げを行い、施錠された箱を運んで回収場へ戻る。縄の使用と箱の受渡しは勝利後の現地作業で一度だけ確定し、移動のjourneyへcostや戦闘を混在させない。勝利直前・勝利直後・運搬中の保存と敗北再開を別々に検証する。

共同回収では、まず岸で荷役人と合流し、同行者を明示して浅瀬へ歩く。引揚げと岸への帰路を分ける。箱が沈んだまま共同回収や石の発見を成立させない。無料で続行できる既存経路を保持する。

箱を開けるのは岸へ到着した後の現地作業とする。ガロへの未開封返却では石や未払いの情報を知識へ加えない。返却撤回の受渡しはガロのいる回収場で行い、箱を持って岸まで運ぶ。未開封の施錠箱を公開で開く方法については、ガロが鍵を持つ冒頭と矛盾しない本文・行為を実装前に確定する。

台帳の調査は、岸から回収場へ戻ってガロへ同行を求め、岸で荷役人と合流し、全員で事務所へ行く手順に分ける。二つの台帳を読んで保持者を隊へ移し、岸へ戻って公開照合する。石だけで未払いの偽装を確定させない。給金台帳、入金台帳、石の観察を別々に保持し、三つを照合して初めてdebtを知る。

一部払いでは実際の売却・支払を確認してpartialPaidを成立させ、証拠委任では箱・台帳・目撃報告の引渡しまでとする。委任しただけでガロの説明撤回や支払を実行済みにしない。事務所と岸の座標・戸口は、水位・歩行可能セル・既存イベントを照合してから決める。

## 地形と既存設備の確認

[給金箱水路の地形](../../data/maps/region_1_canal_c.json)では、上段の(4,1)〜(6,1)と(2,2)〜(8,2)が浅い窪み、(2,3)〜(8,4)が深い窪みである。地理定義のlower_gateで水位が変わり、初期状態は冠水している。底を調べる場面の移動可否は、文字タイルだけで判断せず、冠水中と排水後の両方で確認する。

(1,1)西側は6F操作室への水密扉、(9,1)東側は8F待避場への水密扉、(1,5)には一回限り縄1本を得る備品箱がある。旧現場(7,1)の回収場を保持し、岸・事務所・浅瀬の新しい現場はこれらの扉・備品・水位条件と重ねずに決定する。縄不足から無料の共同回収へ移れる現行経路と、備品箱を使った補給を別々に試験する。
