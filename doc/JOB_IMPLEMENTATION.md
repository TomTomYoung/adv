# 職業システム 1.3.0：実装と検証

更新日：2026-09-10。30職の定義表は [JOB_SYSTEM.md](JOB_SYSTEM.md) です。設計だけではなく、ゲームの操作・成長・戦闘・保存へ接続しています。

## 遊び方

町で「酒場・仲間」を開き、人物カードの「職業・成長」を展開してください。30職から転職先を選ぶと、役割、常時効果、成長率、Lv1・5・10の技能、装備可能な種類、転職後の能力、袋へ戻る装備を確認できます。「この職業へ転職」で確定します。待機中の仲間も同じ操作ができます。

主職は一つです。転職は無料ですが回復はせず、人物の肖像・負傷・毒と過去の成長を保持します。袋が満杯で装備を返せない場合は変更全体を拒否します。装備は旅支度で変更します。職業に合わない武器・防具は選んだ人物に装備できません。

測量と調合は、該当職の人物カードにある探索特技から使用します。戦闘技能は習得済みのものだけを表示し、対象・MP・HP・材料・媒体の不足は無効化理由として表示します。「魔物解析」で調べた敵だけに能力・耐性を表示し、「弱点注記」はその対象を解析した後に使えます。

## 実装内容

30職、38個の追加戦闘技能、18個の戦闘バフ定義、2個の探索特技、10個の追加装備をJSONで定義しています。攻撃・防御と既存技能も再利用しています。新しい効果画像・SEは追加せず、既存の演出へ割り当てています。

人物のactor.jobとactor.growthHistoryを、職業のJobSpecから分離しました。隊のレベル上昇ごとに控えを含む全人物の現在職へ成長回数を記録します。各能力は職歴全体の小数成長を合算してから一度だけ切り捨てます。職業固有の加算能力statsも扱えますが、現行30職の初期加算値は空で、差は成長率・技能・常時効果で付けています。

技能許可は職業・段階・API・対象・対象数・装備中という寿命を一つの許可として検査します。職業変更、戦闘技能、探索特技は事前検査に成功した後だけ資源を消費します。未知の効果や不正な材料数は拒否します。職業EXP、副職、技能持ち越し、盗品生成、鍵無視の解錠、召喚は含めません。

バフは発動者・職業・技能・残り敵巡数を持ち、同種同対象では期限を更新します。異種の強化と弱体は各能力の最強値一つずつ、属性防護も最良値一つを使います。かばうは生存者への単体攻撃を一度だけ転送し、隊員順で保護者を選びます。全体攻撃と連鎖は対象外です。戦闘終了で一時効果を破棄します。

薬師の散布は薬箱・傷薬1・MP4を条件に、低HP率の生存者3人へ28回復します。同率は隊員順です。道具定義を変更せず、戦闘中の本人の傷薬だけを増幅します。調合は傷薬2・解毒薬1・MP2を糧食1へ一括変換します。

巡礼者の「帰路の祈り」は戦闘中の全体回復と防御です。瞬間移動ではありません。探索時の帰還印には別の常時効果で費用半減を適用し、確認画面にも実際の費用を表示します。商人の購入割引、盗賊の罠軽減、斥候の遭遇・逃走補助、灯守の灯油節約は、生存して出撃中の仲間だけから算出します。

## 実装位置

原稿はauthoring/jobs.jsonです。tools/build-jobs.mjsがdata/jobs.json、job-profile.json、buffs.json、field-abilities.jsonを出力し、人物・装備・技能・式・店・演出・マニフェストへ適用します。build-content、build-entities、build-presentationからも最後に実行するため、通常の再生成で職業追加を失いません。

src/core/jobs.jsは成長、権限、装備、転職、探索特技、隊効果を担当します。buffs.jsは一時効果の集約、job-validation.jsは定義とセーブ内の職業状態を検証します。battle.jsは技能決済、かばう、解析を接続し、save.jsは移行を担当します。

src/application/job-projection.jsとprojection.jsが表示データを生成します。src/view/jobs.jsとview.jsはそのコピーだけを表示し、ゲーム状態を直接変更しません。操作はjob.change、job.action、既存のbattle/equip意図へ戻します。DSLもjob.changeとjob.actionを追加し、44命令になりました。

## セーブ互換性

1.0.0、1.1.0、1.2.0の保存データを旧能力計算で検証してから移行します。従来の成長はlegacy履歴へ保存します。初期職業を付け、不適合装備を袋へ返却し、上限を超えたHP・MPだけを切り詰めます。返却先が満杯なら元の保存データと現在のゲームを変更せず拒否します。

新しい保存では職業・履歴回数・装備適合・バフの付与元と期限・かばう対象・解析対象・敵耐性を検証します。セーブ形式の外側のsaveVersionは1を維持し、contentVersionは1.3.0です。会話位置、継続スタック、乱数位置、依頼結果を保持します。ローカルJSONは署名付き認証データではなく、完全な改竄防止を保証する設計ではありません。

## 検証結果

2026-09-10のローカル検証で81テストが成功しました。既存32件に49件を追加しています。全30職についてLv1・5・10・30で能力・習得・装備適合を確認し、解放された全職業技能を実行して保存・再開しました。転職連打、在庫満杯、未習得、必要媒体、材料不足、HP・MP不足、対象不正、バフの集約と期限、かばう競合と非連鎖、散布の対象順、補正の漏出、旧版の負傷・装備移行を含みます。

既存の100クエスト・300結末と、通常の初期隊・獲得資源による100クエスト通しの検証も成功しています。tools/simulate-balance.mjsの既存代表隊1200戦はすべて勝利し、最大3巡・最大HP損失17%でした。結果はBALANCE_RESULTS.jsonにあります。

tools/simulate-jobs.mjsでは初期隊のアダだけを30職へ差し替え、Lv1・5・10・30、各3シードで計360戦を完走しました。職に合う武器1つと技能材料を検証用に支給しています。固定の代表行動方針による結果であり、全職の最適運用・単独攻略・完全な強さの均等を保証するものではありません。詳細はJOB_BALANCE_RESULTS.jsonです。

ChromiumとPlaywrightへローカルのモジュール・画像を直接渡した表示用試験では、30件の選択肢、転職の確定、解析前後の表示、対象変更時の技能無効化、幅390pxの戦闘画面を確認しました。横方向のはみ出しとJavaScript例外はありませんでした。一方、HTTPページへの遷移は実行環境のブラウザ管理ポリシーで拒否され、通常HTTP起動・自動保存のブラウザ再読込・実音声の一連の操作確認は未完了です。表示用試験をHTTP通し試験の成功とは扱っていません。
