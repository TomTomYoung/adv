# 町とシナリオのワールド接続

照合日: 2026-10-27。作品版1.34.0。初版の共通ロケーションと実移動に、第2版の複数拠点・旧100件の現場・仲間80件・国境10件を接続しています。[探索による到達の方針](../scenarios/EXPLORATION_AND_PROSE.md)も参照してください。

## 正本と参照

初版の町の正本は [config/locations.json](../../config/locations.json)、配布先は [data/locations.json](../../data/locations.json) です。`game.world.townRoot` を起点とし、各施設は安定ID、名称、親、追加の移動先、背景、人物配置、施設機能を持ちます。共通施設を増やすときはここへ追加し、依頼内に同名の独立した町を作りません。

[ロケーション一覧](LOCATION_CATALOG.md) は町12か所・ダンジョン室内3か所の親子・機能・背景・参照場面を配布JSONから生成します。篝火広場の下に旅道具店、スキル屋、帰り火亭、灯番組合、医学校、保険審査所があり、医学校の下に標本室、組合の下に灯番詰所、広場の下に上層の待避場、帰り火亭の下に汚水槽があります。`location.move` は親・子・明示した接続先へ移動します。会話・戦闘中は移動できません。

宿泊・編成は帰り火亭、品物の取引と補給・工房は旅道具店、技能購入は独立したスキル屋（hikarigaeri_skill_shop）、依頼掲示板は灯番組合、無料の手当は医学校に表示します。`service` と購入操作は対応施設が現在地の場合のみ成功します。遠隔操作で施設へ自動移動しません。通常の迷宮一覧は入口を持つ町ロケーションから出発します。受注中のクエストの入口ボタンは町のどの施設からでも使え、現在の次イベントに対応する迷宮入口へ進みます。現在地を変えない編成・職業等の既存の町内APIは維持しています。

マップの所属は `dungeons[id].maps` を正本にし、生成時に `maps[id].dungeon` とクエストの `events[].points[].dungeon` を付けます。全配置が同じダンジョンに属するときは `events[].dungeon` も付けます。q193・q194など複数ダンジョンに同一イベントを置く場合は、配置点ごとの所属を使います。既存のダンジョン名とIDを地域番号から推測し直しません。

## 第2版の拠点と正本

第2版は6独立拠点・151ロケーション。灯帰り、国境宿場、石橋の交易市、巡礼台地、旧王領の村、サロメを `worldTravel.settlements` で区別する。町のrootと帰還・受付圏は、画面上でtownとして表示する個々の施設とは別概念である。

初版15施設へ、[仲間連作](../../data/scenario-editions/e2/companions.json)の20、[オッドランド地理](../../data/scenario-editions/e2/geography.json)の66、[国境第一群](../../data/scenario-editions/e2/oddland-first-ten.json)の7、[サロメ地理](../../data/scenario-editions/e2/salome-geography.json)の43を加え、差分内のpatchを適用する。版別の読込先は[版カタログ](../../data/scenario-editions.json)を正とする。

国境の登録・到達と各町の訪問、受付、迷宮の出発・通常帰還・帰還印・敗北救助を拠点ごとに扱う。第2版の依頼入口は、上記の初版共通APIだけで判断せず、依頼の受付・出発拠点の制限も満たす必要がある。[オッドランド実装](ODDLAND_ACCESS_IMPLEMENTATION.md)、[サロメ実装](SALOME_ACCESS_IMPLEMENTATION.md)。

行政都市・地下街・開拓地は施設IDを持つが、現時点の独立settlementには含まれない。独立化と既存施設の描き分けを[町・シーン切替候補](SCENE_SWITCH_PLAN.md)に分けて記載した。

## ダンジョン内の室内

`dungeonEntrance` を持つ親なしのロケーションがダンジョン室内の入口です。定義は迷宮ID、マップID、x/yと退出時の向きを持ちます。正確な戸口セルで `location.enter` を明示選択し、町と共通の背景表示へ切り替えます。内部の `location.move` は同じルート内だけ許可し、`location.exit` は入口のセルへ戻します。表示上のmodeはtownですが、探索番号と部品状態は保持し、町の編成・転職・出発操作には使えません。

室内で保存・再開でき、取消は留置室前→受付→地下の戸口の順です。完全水没区画に室内入口は置けません。[水路拡張](../dungeons/WATERWAY_EXPANSION.md)と[q004の実移動](../scenarios/Q004_WORLD_ROUTE.md)。

篝火の迷宮の詰所は `kagaribi_crossroads` の (8, 1) から入る独立した室内です。当直との会話、整備記録、復旧後の燃料購入を提供します。室内サービスは現在地の `services` に登録され、かつ `game.services` で `interior: true` と明示されたものだけ実行できます。入退室・購入で探索番号、歩数、携帯火の燃料をリセットしません。[詰所と補給](../dungeons/KAGARIBI_EXPANSION.md)。

## q001の帰路と実到着地点

この節は初版q001の経路を記載する。第2版の改稿は[版別仕様](../scenarios/SCENARIO_EDITIONS.md)を参照。

老人を介助する `old_support` の帰路は、`kagaribi_f1` の北 (9, 1) / `q001_return` と南 (13, 5) / `q001_return_south` のどちらでも、共通入口 `q001.v11.visit` から消灯・くらがり戦・新人救援へ進みます。この2地点で老人のいる支道から他区画へ抜ける徒歩経路を覆います。帰路の通常歩行抽選で `kuragari_hunt` が当選した場合も、その実遭遇セルで同じイベントを開始します。燃料切れや旋回だけでは開始しません。

往路の `dark`・`empty` 場面は、既存の `worldPlaces.dark` が指す北 (9, 1) だけです。帰路の到着先だけを `old_support.journey.arrival` で広げ、消灯場面 `outage` と救援場面 `rescue` は実到着セルを共有します。戦闘や新人の救援に合わせて探索隊を北へ移動させる処理はありません。救援後は別の帰路配置を通っても再発せず、その場から入口へ歩いて戻ります。救援前の全滅は既存のチェックポイントで老人遭遇へ巻き戻します。

## q002の実際の場所

依頼の正本は [authoring/story-q002.mjs](../../authoring/story-q002.mjs)、イベントの正本は [config/quests/q002.events.json](../../config/quests/q002.events.json) です。8場面・3結末、物語状態の改訂2です。全文・座標図・3マップの経路・イベントIDは[q002専用ページ](../scenarios/quests/QUEST_Q002.md)へまとめています。

引き揚げ場は灯守の地下水道 `region_1` / `region_1_landing` の (5, 1)、イベント `q002_decision` です。岸と浅瀬の作業は同じ現地イベントの範囲で扱います。標本室は `hikarigaeri_medical_specimens`、審査所は `hikarigaeri_insurance` を参照します。対応は `story.worldPlaces` に置き、各場面の `place` から引きます。

1. 地下水道の現場で、荷札のみの回収、骨箱ごとの引き揚げ、管理番号の照会を選びます。
2. 医学校へ照会する選択では出発準備だけを確定します。帰還し、広場から医学校、標本室へ入ると自動で会話が始まり、貸出台帳との照合が成立します。
3. 箱を持参していればその場で返却できます。浅瀬に残っていれば運搬人と出発し、地下水道の実座標へ戻ってから引き揚げます。持ち帰った箱は標本室への到着後に返却します。
4. 運搬人の同意を得ると、台帳と荷札を受け取り審査所へ出発します。到着後に実書類と証言を照合して、不正請求を立証します。標本の箱は医学校に残ります。

旧版で医学校に置いた荷札を会話内だけで取り戻す処理は廃止しました。現在の審査には持参した荷札が必要です。旧q002の場面・二つの廃止手掛かりイベントも通常データから除去しました。この旧q002進行を含む未対応の内容版は移行対象外です。1.26.0導入時の移行経緯は保持し、現行の読込対象は下記の保存方針と[SPEC](../SPEC.md)に従います。

## 出発・到着・中断

移動行為は `journey: {to, companions}`、出発時の効果 `depart`、到着時の効果 `effects` を持ちます。DSLの `story.journey` が出発処理を一括確定し、会話を閉じます。現在の定義では移動行為へ費用や結末を直接付けません。現場作業や到着後の選択へ分けます。

`state.journey` は依頼・行為・出発場面を保存します。出発した探索隊と同行者の論理上の所在は `transit`、会話場面はnullになります。正確な実位置は `mode` と `townLocation` または `location` が持ちます。町の目的地は場所ID一致、ダンジョンの目的地はmap/x/y/zが足元のセルと一致することを要求します。

移動行為には任意の `journey.arrival` を指定できます。`points` は通常の目的地に加えて到着を認めるマップ・座標・イベントの配列、`encounters` は目的地と同じ迷宮内で、その移動中の通常歩行抽選に当選したときに到着を成立させる遭遇IDの配列です。遭遇確率・周期を省略する指定ではありません。共通Coreは到着したセルと行為、遭遇による到着ならその遭遇IDを、任意の `stories.<quest>.arrivals.<place>` に記録します。同じ物語上の場所で続く場面はこの実位置を使い、到着後に定義上の基準座標へ移しません。q001では帰路の記録が `stories.q001.arrivals.dark` です。

Coreのフィールドイベントは、目的地への実到着で到着効果を自動確定します。移動中に元の受付へ戻って再開しても、その移動を巻き戻しません。途中保存・再読込や寄り道では、台帳照合・返却・証拠取得を先に成立させません。到着は一度だけです。上部の目的地・継続ボタンのUIは削除しました。目的地案内は手帳・メインクエスト欄を使います。

資材不足や物語上の退出による中断では現在の場面を保持します。その後に実際の場所を離れた探索隊の `partyAt` は現在地に同期し、依頼の定義外なら `transit` になります。同行指定のないNPCは元の場所で待ちます。戻ると施設の「続きを話す」または現地イベントから再開します。完了済み依頼の物語状態は結末の記録として保持します。

ダンジョンの新規会話・再開・物語行為も、場面の配置セルに立ってから行います。正面の一マス先を現在地とは扱いません。手帳の到着表示と探索画面の印も実際の配置セルに合わせます。

不正な場所ID、移動行為、同行者の所在、現在地と会話の不一致はセーブ検証で拒否します。Applicationの共通復元処理は読込失敗時に最初から開始します。現行内容版は1.34.0で、正常な1.25.0〜1.33.0の初版保存を検証して移行します。既存の現在地・進行・所持品・同行者を保持し、1.25.0には遠征状態を追加します。第2版は保存改訂2・地理版2。旧改訂2の受注済み経路・会話・旅程を保持し、改訂2より前のe2は非対応として原文を保護します。[版別保存](../scenarios/SCENARIO_EDITIONS.md)。

2026-10-10の複数地点・遭遇による到着追加時は、内容版1.25.0・q001の物語改訂4・既存チェックポイントの復元対象を維持しました。この任意の到着記録は1.26.0でも維持し、`arrivals` のない正常な1.25.0セーブも移行して継続でき、既存の北側会話は従来の場所で再開します。追加地点または通常遭遇から到着した新しい保存では、記録された実位置で戦闘と救援会話を再開します。

配置セルへの統一前に作られた同版保存では、探索中の `partyAt` だけが旧来の正面セルを指す場合、検証後に現在地へ同期します。座標・進行・所持品・NPCの所在は変えません。すでに正面から開いて保存した会話は、その保存に残る命令列だけを継続できます。本文・選択・戦闘の途中で再保存しても続けられますが、新しい会話開始・再開や旅程の到着を手前から成立させる許可には使いません。

継続許可は実行時だけ保持し、保存項目を増やしません。会話終了、出発、位置や向きの変更、新しいスクリプトの開始、別の保存の読込で失効します。旧来の正面判定でも一致しない会話・同行者・命令列は引き続き拒否します。`tests/world-cell-access.test.mjs` は、この互換性と配置セルでの開始・再開を検証します。

## 表示と素材

Coreが現在地・会話・人物・物品・移動記録を所有し、Applicationの `world-projection.js` が表示用の町・移動案内を返します。Viewは背景、透過立ち絵、場所名、本文、選択肢を描画します。取引と隊編成は施設から開く追加パネルです。背景へ表示した人物の肖像を会話欄へ重複表示しません。

現行登録の施設・町背景は関所と新しい到着口5枚を含む13枚、NPC48人に会話用画像を接続済みです。第2版151ロケーションの共用と未制作30NPC、人物表示の未接続を[不足素材台帳](ASSET_BACKLOG.md)へ集約します。[到着背景5枚の原本・英日プロンプト・配布情報](../../assets/source/world-locations/settlements-2026-10-27.json)は別に保持します。以下は初期制作分の記録です。背景7枚は `assets/images/locations/`、標本係・運搬人・審査官の立ち絵3枚は `assets/images/characters/sprites/` です。既存の生成肖像を参照して透過立ち絵を生成しました。背景1536×1024、立ち絵1173×1341。元の生成PNGは保持し、配布画像はサイズ変更・描き直しをせずWebPへ符号化しました。

英語・日本語プロンプト、参照画像、生成元・配布画像のSHA-256は [素材manifest](../../assets/source/world-locations/manifest.json)、概要は [PROVENANCE](../../assets/PROVENANCE.md) にあります。背景と立ち絵の単体を目視確認し、透過・寸法・ファイル参照を検査しました。

`node tools/build-fixtures.mjs` は現在の処理から独立した表示例を作ります。過去のローカル描画確認と今回の確認範囲は[検証記録](../development/PROGRESS.md)へ集約します。公開版で全施設・全人物・音声を通した確認は未完了です。

## 生成と検証

`npm run build:scenarios` のダンジョン生成末尾で `tools/build-world.mjs` を実行します。手書きのダンジョン所属が間違っていれば生成を止めます。配布JSONの不正なダンジョンID・町ID、所属マップ、通行不能・範囲外座標、現地イベントの不一致、ロケーションの親子循環を `validateContent` が検出します。

`npm run build:catalog` でシナリオと町の索引を更新します。全210件のイベント配置にダンジョンID・名称・マップ・階層・座標・イベントIDを掲載し、q001〜q004・q201〜q210では各場面の現在地と施設ID、出発先も掲載します。実装指紋はクエスト・人物に加え、ロケーション・ダンジョン・マップを含みます。`npm run check:docs` は指紋と配置行、町カタログの実データ一致を照合します。
